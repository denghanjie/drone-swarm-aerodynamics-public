## Generation interface

`results/generation.json` uses schema `m31-native-fresh-generation-v1`, identity `sourceCommit` / `sourceManifestSha256`, `complete`, `inputsAndSourcesPreserved`, `errors`, a `journal` pin, exactly two `slots`, and four `controls` on completion. Failed generation retains both target slots; a started/persistence-failed slot is not relabeled unattempted.

Each slot has `id`, `seed`, `t: 5`, `n: 64`, `methods`, `status`, `generation` pin, `input` pin or null, `semanticInputSha256` or null, and `motion` / `novelAgainstRetained`. Motion is `{stateChanged, relativeGeometryChanged, witness: {id, axis} | null, passed}`. It compares exact raw dyadic relative positions against drone ID 0, without an initial aerodynamic evaluation. Slot `status: captured` requires normal terminal t5 completion, full-state/pose equality, passing motion and content novelty. Novelty is `{comparedCount: 6, matches: [], passed: true, rawContentSha256, retained: science.retainedInputs}`. The content digest hashes the raw `{drones}` object with recursively sorted keys, compact ASCII JSON and no trailing newline; it excludes the semantic domain/case-ID envelope. Each target must differ from all six pinned retained input contents. A match remains unavailable with its failed capture preserved, without replacement. Both slots must pass for `complete: true`.

Each fixed moving control has `id`, `n` (3,2,2,2), `methods: [F,L]`, `input` pin, `semanticInputSha256`, `expectedReference: {status, branch}`, and `expectedNative: {status, reason}`. Native expectations are success/null for positive and distant-zero, input-refused/nominal-nonpositive for raw-force, and domain-refused/native-graph-order for order-incompatible. Expected exact statuses preserve the old admitted-loads, rejected-raw-force, rejected-ordering meanings.

Raw input files `results/inputs/ID.json` contain exactly `{drones: [{id, state: [17 binary64 hex words]}]}`. Semantic hashing retains the canonical envelope `{domain: m31-moving-admission/input/v1, id, input}`. Generation records are `results/generation/ID.json`, schema `m31-native-fresh-generation-record-v1`, preserving initial callback, returned initial, terminal final and scheduled snapshot, all actual pose frames/callbacks, returned summary/configuration, error, motion and the exact novelty metadata. Durable `results/generation-journal.jsonl` binds generation intent, every streamed frame, t0/t5 or stopped full captures, and completion. Partial evidence survives generator failure.

## Reference interface

`results/reference.json` uses schema `m31-native-fresh-reference-index-v1`, source identity, exact `generationIndex` pin, `complete`, `qualified`, `inputsAndSourcesPreserved`, `constants`, `errors`, four `controls` and two `targets`. Every result descriptor copies its generation row and adds `reference` pin, `referenceStatus`, `branch`, `graphStatus`, `positiveRotorPairs`, and `qualified`. The initial placeholder rows remain explicit if a case cannot be evaluated.

`complete` means all six predeclared exact reference evaluations returned and were saved. `qualified` additionally requires four expected control status/branch results and both targets admitted, descending compatible, complete over 16,128 pairs, positively coupled and moving. A complete scientific negative can exit 0 with `qualified: false`; parent must block browser unless `complete` and `qualified` are both true. Errors/preservation failures exit nonzero.

Each `results/reference/ID.json` uses schema `m31-native-fresh-reference-v1`: source identity, `id`, `n`, exact `input` file pin, semantic `inputSha256`, `referenceStatus`, `branch`, `witness`, `prepared`, `plannedPairs`, `evaluatedPairs`, `pairs`, `graph`, `loads`, and fixed `recipe`. `graph.status` is the string `acyclic-compatible` for qualified targets. Every pair includes `i,r,j,status,branch` and positive coefficient bounds where applicable. Every admitted load row has `id`, four independent root boxes, and signed physical-unit `loads` boxes keyed `rotor,collective,force,moment`. Root/load serialization reads the independent helper target directly; it never runs a rational candidate or reconstructs loads from native x.

The entry calls the unchanged scene helper once per declared control/state, with unchanged pair helper, 192-bit coefficient/source bounds and 128 cubic bisections. It explicitly enforces cap180 and the actual declared 2/3/64 counts before calling the helper, whose internal historical maximum is216. No additional precision or replacement slot is available.

## Final audit interface

The final checker binds completed generation/reference/browser attempts to their outputs and source identity, independently validates the saved generation journal/capture/motion and recomputes content novelty against all six pinned retained inputs, checks exact decimal-to-word control literals, and hashes every consumed reference/input/journal. It calls neither producer nor reference modules. Its numerical core is copied from the retained checker; changes are declared row counts, fresh provenance/schedule and fixed corruption witness IDs.

Browser output retains schema `m31-native-browser-qualification-v1`. It must expose `calls` (four target records) and `movingControlCalls` (eight control records), exact `generationIndex` / `referenceIndex` pins, and adopted Chrome-root exit/close evidence. Each moving call uses the target call shape, its own sequence0..7, and journal kind `moving-control`. Ownership result IDs are `control:ID` for native microcontrols, then `moving:ID:METHOD`, then `target:ID:METHOD`; only successful calls replace the remembered prior successful result. Refused moving controls therefore preserve the predecessor.

`results/check.json` uses schema `m31-native-fresh-load-check-v1`, `passed` for audit integrity and `decision: qualified|unqualified` for the finite scientific result. It reports exactly four target calls and eight moving-control calls, all14 arithmetic fixtures, four fixed corruption outcomes, F/L parity and per-category native error/identity/support/consumption findings. Positive/distant-zero controls receive the same strict load audit using their2/3 rows. Raw-force and order-incompatible controls receive their fixed status/precedence assertions and do not count as load-accuracy successes. A qualified result requires both targets, all fixed controls, parity and corruption assertions; missing predetermined corruption witnesses fail.

The original failed supervisor is not repaired. No performance, every-helper-exit, hard-containment, hard-memory, physical-validation, closed-loop or5000-drone claim is made. The parent supervisor owns the adopted finite resource and guardian lifecycle policy.
