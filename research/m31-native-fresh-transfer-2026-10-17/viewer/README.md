# Actual saved-frame fresh-transfer viewer

This viewer displays the two actual 5-second Boids recordings from the fresh-transfer experiment. Both flights had airflow off. Playback advances through 26 saved pose frames per run without interpolation. Initial/final controls select actual recorded endpoints. The 5-second native force arrows are separate posthoc aerodynamic queries, enabled only when the source-bound saved stages and selected scientific check qualify.

The app reads actual saved generation, browser and check records directly. It does not import or execute scientific modules, rebuild loads, or project a second copy of the numerical evidence. `bind-records.py` is an administrative byte verifier: it accepts explicit identities, verifies every declared file and associated generation/input record, creates a pinned binding, and writes that binding hash into an otherwise unbound application. The final binding contains 18 saved/source/dependency files. Three.js, its core module and OrbitControls remain unchanged.

The source-only draft was statically checked and then administratively bound after the parent supplied the completed immutable result identities. Preparation has not launched a browser or executed QA. QA source and the one-attempt allocation are in `qa/PROTOCOL.md`; separate parent approval is required before launch. No automatic retry.

The original retained-stage supervision remains failed and is linked separately. The new fresh result does not rewrite it. F is the screened method, L the lean baseline, and both retain full contribution. The current cases skipped no center-norm calls, so no speed result is claimed.

Files are intended for `research/m31-native-fresh-transfer-2026-10-17/viewer/` in the repository. Use the existing root HTTP server; opening `index.html` through `file://` cannot provide the required same-origin evidence fetching and Web Crypto context.
