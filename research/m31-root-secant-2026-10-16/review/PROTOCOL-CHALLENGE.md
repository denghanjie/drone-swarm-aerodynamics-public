## Clarification needed before freeze

The protocol says candidate/root-only controls are “not separately executed,” while boundary controls are checked in the reviewer, which must not import candidate code. This leaves two different coverage claims possible:

- Fixed candidate-produced fixture outputs, generated inside the sole candidate invocation, can be independently checked during the sole reviewer invocation. This tests the candidate's constant/linear/startup and invalid/nonfinite serialization paths without another run.
- Fixtures evaluated only by independent reviewer code test that reviewer's own logic. They cannot establish candidate edge-case behavior that did not occur in the target data; candidate coverage would then remain static.

The first is preferable if candidate boundary behavior is to be claimed as exercised. Freeze which outputs are produced, include them in the aggregate cap, and avoid describing reviewer-only examples as candidate tests. No controls should execute before source publication. This issue was sent to the coordinator while implementation was being prepared.

## Causal interpretation and population

The predictor's restricted interface—past fresh roots/times plus target time, without current states, commands or oracle roots—is appropriate. Current state enters only the subsequent load assembly. A flushed prediction/predecessor trace before oracle scoring, together with exact source review, makes the intended data dependency auditable. Loading the immutable record or checking all of its input identities first is compatible with this rule; that does not make the exposed oracle data blind or physically hidden. “Causal” means past-only computation here, not identification of a causal physical mechanism.

The mandatory k=1 hold, fixed k=2...200 secant formula and post-scoring admission of each actual fresh root resolve startup and history ownership. Feeding the scheduled fresh root into the next history after an invalid prediction is a fixed reference-data schedule, not an outcome-dependent reset. The implementation must preserve this distinction and must not substitute a fresh root for the failed current prediction.

All 200 positive targets, including cold start and terminal audit, remain primary. The 199 extrapolated targets are secondary. These states were generated by the old held-root path, so results will be conditional on that exposed path. Neither a pass nor an improvement establishes what a predictor-driven controller would do. The 200 events are correlated observations, not independent trials or a basis for population confidence claims.

## Invalidity and gates

Finite 0 < x <= 1 is an explicit root contract. Invalid finite values remain visible as invalid-domain arithmetic; nonfinite/uncomputable entries have null/tagged representations and coverage counts. Zero invalid roots and zero unscored targets are separate requirements. Null complete-set maxima on any unscored event avoid silently qualifying a finite subset. The final implementation must not let null/NaN become a passing zero, and should distinguish complete finite arithmetic from valid-domain qualification.

The three absolute maxima, paired hold comparison and all-event coverage are prospectively fixed. The protocol correctly notes that “no worse than hold” is comparator context rather than independent added evidence once the known failed hold maxima and stricter absolute screens are considered. Event-level worsening is permitted by this maximum-based rule and must remain in the paired table; a later result must not rename a passing global maximum test as improvement at every event. A cold-start miss cannot be removed by the secant-only secondary report.

Integrity/completion and scientific qualification are separate. A valid scientific miss consumes and closes the allocation; neither candidate nor reviewer failure authorizes repair or rerun.

## Claims and next boundary

The joint-source root variable and associated load assembly distinguish this diagnostic from the old fixed-hover scalar-inflow predictor. Linear extrapolation, two-sample history, feedback cadence and full moments are not newly invented here. The two admitted originals provide antecedents, not an implementation guarantee, a derivative-error certificate or physical validation.

The stated outcome boundary is appropriate: success permits considering another separately designed diagnostic only. It cannot qualify intermediate times, feedback flight, adaptive-trigger accuracy, fewer actual solves, speed, novelty or fresh generalization. The new visualization must remain an error overlay on the original saved trajectory, not imply a newly integrated secant trajectory. Publication and visual QA remain future obligations of this new allocation, not evidence already obtained.
