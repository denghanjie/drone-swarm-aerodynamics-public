# Prospective execution admission — no drone calculation

Motivation: the closed coupled-cost allocation's supervisor recorded PermissionError with no valid scientific artifacts and no failing-stage marker. Its null returncode/empty logs do not prove that the child never began. A subsequently approved host saved-record reviewer launched and monitored Python successfully. A direct default-sandbox ps command was denied; this makes monitoring a plausible denial site but cannot retrospectively identify it.

This is a separate infrastructure experiment, not a scientific retry or permission to reopen the closed allocation. It imports no swarm code, reads no target state and produces no model/timing result. Two fixed invocations: default sandbox, then explicitly approved host execution. Same Python script and Node executable, one invocation in each context. No replacement context, flags, policy changes or additional retries. Source is published and exact remote manifest verified first.

Each invocation records and flushes a stage journal before Node Popen(start_new_session=True), before a bounded echo handshake read, before ps RSS sampling and before completion/cleanup. Node emits a fixed READY line, waits for ACK from its parent, emits DONE, then exits0. An internal6second watchdog exits3 if ACK never arrives. No science module is imported. Store exact echo match, return status, numeric RSS if available, exception class/errno/operation, and executable/source hashes. Do not store PIDs/private executable paths or raw system metadata. The8second child completion wait and2second handshake/ps/cleanup waits are operation-specific bounds. Filesystem flushes, hashing and Popen do not have an overall external wall cap; no hard total-time claim is made. Executable hashing occurs before the lock. This is not a runtime benchmark. Cleanup records its own errors and retains evidence if a process operation is denied.

An admitted context requires valid handshake, successful numeric RSS sample, expected child exit0 and no exception. Failure is retained and closes that context's allowance. Compare only the actual operations demonstrated, not performance. If host fails, no scientific allocation is launched until a separate diagnosis resolves it. If host passes, a new prospective replacement cost allocation may reuse the exact numerical sources and fixed cases with this execution path, still requiring its own source/manifest checkpoint. The previous failure remains published and no missing result is filled in.

Nonoptimized Python and empty NODE_OPTIONS are preconditions before consuming a lock. The coordinator verifies the commit and exact remote manifest plus local/committed pins before dispatch; sourceCommit in this script is explicitly supplied verification metadata, not an internal Git query. The script rechecks all local source pins and supplied manifest hash. Journal write/flush/fsync stages are distinguished from process stages; cleanup exceptions revoke admission.
