# Independent saved-phase audit design

Prepared 2026-10-23 before the source publication gate and before any new numerical allocation. This document describes prospective checks, not observed phase totals or a result. Preparation is restricted to source/schema review, small publication and closure metadata, file identities and syntax compilation without execution. The query log is not reaggregated during preparation. No producer, auditor or aerodynamic module is imported or run, and no previous allocation is reopened.

## Independence and shared infrastructure

`source/audit.py` independently implements decimal-token parsing, rational arithmetic, canonical timing text, canonical expected JSON, row partitioning, aggregation, ranking, group reconciliation and viewer reconstruction. It imports neither `analyze.py` nor a prior auditor or scientific module. The producer uses `decimal.Decimal` at precision 80 with the `Inexact` trap; this auditor uses `fractions.Fraction` and does not import Decimal. Numeric JSON decimal spellings become integer numerator/power-of-ten denominator pairs directly, without conversion through a binary floating-point value.

The explicitly shared `common.py` is used only for the public-source gate, immutable-origin/local identity reads, paths/configuration, output writing and allocation supervision. Its numeric helper functions are not called. Independently generated expected bytes are compared with producer bytes before shared output helpers are used. The written audit viewer is also reread and compared with those independent expected bytes. This is arithmetic and reconstruction independence, not complete infrastructure independence.

An ordinary JSON parser is used for administrative records and the unchanged inherited summary, because `oldResult` must match the producer's unchanged parsed-JSON copy. It also reads stage metadata, but uses only identity/status/order fields from those records. Finite ordinary floats from inherited metadata never enter timing partitions, sums, tolerances or ranking. Both parsers reject duplicate keys and nonfinite JSON constants. Timing access rejects booleans and every type except integers and Fractions.

## Identity and closure gates

The auditor first requires the current public source receipt to bind the reviewed source manifest, checks every source identity and every frozen origin-Git input identity through the shared gate, and compares configuration against its independent literal contract. Mandatory source files include both implementations, the protocol/schema/design, launcher/supervisor, finalizer/UI, viewer files, input pins, runtime disclosure and all three renderer dependency files. Source files must be labeled as source pins.

Two fixed prior metadata byte identities anchor the radial integration result manifest and final parent publication receipt. The composite independent public-review receipt is bound through that fixed parent receipt. Its commit, manifest identity, verified-pin count, successful public/composite verification and closed-allocation statement must agree. The prior transport history is preserved verbatim through `verificationScope`; failed/incomplete acquisitions and explicitly reused input proofs are not rewritten as a clean fresh download.

The consumed queries, groups, summary, prior audit, stages, stage summary, prior allocation closure, all four prior supervisors and producer/audit internal exit records must match the prior public manifest. The prior independent audit must have passed evidence integrity, common scientific equivalence and stricter baseline equivalence, and must bind the exact saved summary and query/group/summary identities. Its complete 1,920 input bindings anchor each stage and the retained native-input/shared-reference/strict-baseline hashes. This audit consumes that existing scientific proof; it does not reread scientific CAS bodies or perform new scientific comparisons.

All four prior supervisors must match the prior closure and report successful bounded completion. The internal producer/audit exits must be closed; the original producer read history must match the retained summary. Prior cost, coverage and keep gates must all remain false. Operational success is never substituted for qualification.

The current producer must already have closed successfully. Its output directory must contain exactly launch, exit, rows, summary, viewer and input-binding files, all regular files without symlinks. Its exact byte total must match its supervisor and fit the 128 MiB evidence-output cap. Launch evidence, elapsed-budget assertions, source/input binding, summary/exit read history and all consumed result identities are checked. Before a passed report, producer files and all frozen local source files are checked again for mutation.

## Full population and exact row reconstruction

The fixed population is 34,560 saved calls: twelve windows, 160 stages per window, F and C, warmup repetition -1 and measured repetitions 0 through 7. All 108 group records must follow repetition/window order, with F then C when `(rep + window + 10) % 2 == 0` and C then F otherwise. Each call number, repetition, window, method and stage index must follow that exact original stream. The input and transformed streams must end together with no extra record.

Every saved query must have the original exact field set, true reference/input-preservation/method flags, unchanged before/after input hashes, no mutated-input payload, and the full shared semantic descriptor bound to the prior audit. F additionally requires both stricter baseline hashes and the true equality flag; those F-only fields must be null for C. Stage status, reason and identity must match the complete original stage/input-binding order.

Success requires the exact eight wrapper and four nested kernel phase names. The only refused pattern is the inherited near-field native-admission failure at window 2/index 159, native stage `build`, with time word `400cf5c28f5c28f6`. It has exactly input/finalization wrapper timings and an absent kernel-timing field; null and fabricated zeros are rejected. The derived expected population is 34,542 successes and 18 refusals. The original clock and boundary string must match, and all recorded timings are finite and nonnegative.

For success the auditor replaces buildAndAdmission by kernelInput, kernelIndex, geometry, kernelAdmission and buildUnassigned, retaining the other seven wrapper phases. It independently computes buildUnassigned as wrapper build minus all four kernel phases, outerBoundary as outer minus inner total, and timerResidual as inner total minus all wrapper phases. For refusal it renames finalization to unfinishedPhaseAndFinalization and retains input, outerBoundary and timerResidual. Both leaf sets are fixed and must sum to outerMs exactly as rational values.

The fixed tolerance is exactly 1/1,000,000 ms: absolute timerResidual must be at most this value, and outerBoundary/buildUnassigned must be at least its negative. Signed derived values remain signed. encodePersistMs and comparisonMs are nonnegative; comparisonMs may not exceed encodePersistMs by more than the same fixed tolerance. These nested external evidence intervals are retained separately and never added to the query partition.

Exact times are rendered by factoring the reduced denominator into powers of two and five, padding the resulting integer decimal expansion and removing only redundant trailing fractional zeros. A remaining denominator factor fails rather than rounding. Zero renders as `"0"`. Expected row JSON uses sorted keys, compact separators, ASCII escaping and one newline; every one of the 34,560 transformed lines must byte-match its independently reconstructed line.

## Aggregates, decision and viewer

Separate rational accumulators reconstruct pooled bucket/method/status, repetition/method/status and repetition/window/method/status records, retaining count, outer/inner/evidence/comparison totals and every disjoint leaf. Arrays use the exact lexicographic order required by the schema; no empty aggregate is emitted. Leaf conservation is asserted again for every aggregate.

For all 108 original groups and each method in F/C output order, the auditor reconciles successful/refused outer sums and counts, total query time and total including the separate recorded reset interval. The resulting 216 records retain signed sumQueryMs/admittedMs/refusedMs/totalMs deltas, each within the fixed tolerance. Reset is never assigned to an outcome category.

The primary denominator is pooled measured successful F outerMs. It and all eight corresponding per-repetition outer totals must be strictly positive. Leaves are ranked by decreasing exact sum with alphabetical ties; only timerResidual is excluded. The majority branch uses the exact rational comparison `2 * leading_sum >= primary_outer`. The stability branch counts whether that same component leads at least six of eight measured F repetitions. Both must hold for stable-majority-component; otherwise the classification is distributed-or-unstable. Exact numerator/denominator timing strings, all eight winners and both branch conditions must match the producer. There are no medians, average-share substitutions, rounded decisions, speedup predictions or revised old gates.

The entire expected summary, including every ordered aggregate, group reconciliation, decision, unchanged inherited result, source commit, fixed scope text and retained producer read history, must byte-match the producer summary. Administrative read histories are preserved and cross-bound to the producer exit; the auditor does not claim to independently reproduce the producer's transport events.

For each of the 1,920 stages, the auditor independently retains paired F/C records from measured repetition zero and sorts them by window/index. Each arm contains outerMs, innerMs and disjoint leaves. Both arms must be present and share status; refused stages must have no geometry leaf. These viewer rows must byte-match the producer viewer and are separately written as `audit/viewer-rows.json`. The headline population remains all measured successful F calls, not the illustrative viewer repetition.

## Reporting, bounds and interpretation

The audit allocation is single use, at most 450 seconds with a 128 MiB evidence-output cap, supervised by the frozen launcher/supervisor. Output construction reserves failure evidence. Any missing field, inconsistent identity, unexpected population, noncanonical byte, invalid partition, tolerance failure or differing decision fails closed. A passed report is written only after every reconstruction and final identity check; a failure retains its completed-check list, type/message and read events, followed by an exit record. No retry, source repair or second analysis is authorized by this design after freeze.

Successful output includes explicit result file pins, the independent viewer pin, current source commit, consumed prior-input pins, prior publication scope, arithmetic disclosure, preserved read histories and limitations. The finalizer can bind the exact audited summary and independent viewer without recomputation.

Timer names denote the instrumented boundaries, not isolated causal costs. Wrapper input includes capture/validation/copy/sort/normalizers and setup. KernelIndex is screen/certificate work; kernelAdmission also includes coefficient scaling and ordinaryLmax. Geometry includes candidate cache/list work, center/rotor interactions and assembly/conversion. BuildUnassigned includes wrapper evidence/validation and kernel work after t4; outerBoundary includes external owned copy, call/return, timing-object construction and timer boundaries. Refused finalization spans an unclosed wrapper interval even if the kernel returned. F reset is a matched branch/timer interval; C also resets the cache. comparisonMs is nested in partial encodePersistMs, which excludes its own query append and other later producer work. F's old-nine comparison and C's witness copying are asymmetric outside the primary timer and may affect subsequent runtime state.

Exact arithmetic preserves the serialized decimal evidence; it cannot improve the underlying clock measurement. The exposed, dependent N64 stage population supports descriptive inspection priority only. It provides no causal acceleration estimate, new holdout, scaling result, uninstrumented throughput, physical validation or flight-safety claim. Earlier historical N1000 browser observations do not transfer their timings to this Node/N64 population. Prior cost/coverage/keep failures and incomplete overall research status remain explicit.
