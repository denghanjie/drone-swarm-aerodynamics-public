# AUDIT-C1 terminal-record viewer

This small postrun adaptation of the frozen `../demo/` scaffold presents the actual one-shot launch rejection and embeds the unchanged historical Three.js viewer. It generates no paths and copies no trajectory payloads or renderer dependencies.

Serve the workspace root over HTTP and open `/research-audit-optimization/postrun-demo/`. In the public repository layout, serve its root and open `/research/campaign-audit-overhead/postrun-demo/`. The sibling prior campaign must remain at `research-next/` locally or `research/campaign-joint-stage-reference/` publicly, including its `implementation/demo/records.json` and vendor modules. The app selects only between these two relative layouts. This is a display layout, not authorization or instructions to rerun the frozen experiment.

The page fetches the three original terminal receipts, checks their byte lengths and SHA-256 hashes against `evidence.json`, and displays copied resource counters with their original before-write qualification. Receipt verification needs Web Crypto, normally available on HTTPS or localhost. If unavailable or mismatched, the page reports that verification failed and leaves the original evidence links accessible. The default HTML already states the terminal outcome when JavaScript is unavailable.

Historical P1 poses stop at 0.990 s and then hold; its prior accepted stop was 0.9915625 s. Animation does not establish current AUDIT-C1 correctness, speed or physical accuracy. The old campaign remains unqualified.

Only static syntax, paths and identities were checked. No HTTP server, browser, simulation, benchmark or supervisor retry was run to create this artifact. See `../postrun-report/STATIC-CHECKS.json` for the exact scope. The frozen original demo and original receipts were not edited. Nothing was published remotely by this preparation.
