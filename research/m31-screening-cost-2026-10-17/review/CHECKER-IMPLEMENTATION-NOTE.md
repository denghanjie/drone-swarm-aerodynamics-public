## Allocation and retained evidence

The checker parses the bounded index and journal, verifies all six scene pins without parsing their scientific content, then loads one paired scene. It constructs that scene's full oracle, exact tree/plans, roots and loads, validates both methods independently, compares common science only afterward, reconstructs all ten trial hashes/counters, and runs any first qualifying fresh controls for that scene. Scientific controls clone only the current hierarchy method and immediately release the clone. Metadata controls clone only the small index/ledger.

Per-scene root/load evidence is written exclusively and fsynced before scene graphs are released. The new reference directory's parent is fsynced. The report retains small counters, hashes, methods' compact findings and file pins. All six bounded helper caches are explicitly cleared after each scene. No closure or list of pending mutations is retained across scenes. This schedule reduces retained pair oracle population to at most 185,760; it does not prove the 1 GiB sampled RSS or 1,800-second feasibility limits.

The final report's `referenceEvidenceBytes` counts only reference files; complete checker-corpus accounting remains the supervisor's separate responsibility. Both source and all scientific input pins are rechecked afterward, including after a validation failure when possible.

The checker validates warmup `AB`, then measured `AB, BA, BA, AB`, exact chronology, all four offsets, stage partition, separately scoped harness intervals, first-measured representative identity, context-bound full-method/common hashes and every trial work counter. It recomputes all four paired ratios, each duration median, the median paired ratio and the ratio of medians as reduced exact rationals. The common positive projection is explicitly `{i,r,j,coefficient}` with stable IDs in canonical input order; method hashes still bind the full status/branch/proof/work record.

The 15 fresh controls and deterministic witnesses are fixed in the final contract. Controls invoke the same semantic/index/ledger/binding validators as the baseline and require their named intended failure families. Hash-only, equality-only and generic-exception rejection cannot qualify. Missing witnesses, a passing mutation, or an unintended failure family fails the cycle; attempted control outcomes remain visible in the failed report. No old fixtures or controls are rerun.

Successful cost qualification explicitly requires every method/scene to achieve all four normalized load tolerances. Truthful `tolerance-failed` output can be semantically understood but cannot produce a successful cost qualification.
