# Independent source review: retained-panel native-load qualification

Review date: 2026-10-17. Scope: browser harness/controller/bundler, independent delivered-load checker and its contract, parent supervisor/guardian and protocol. This review used source/schema text and byte hashing only. It imported or executed no scientific module, browser, numerical fixture, checker, control or target. Source authors made corrections; this reviewer did not edit their code.

## Result

The reviewed design is suitable for the narrow, separately authorized retained-panel qualification after exact final source publication and runtime/input gates. This is source-review acceptance, not a numerical qualification or a run allocation. The final byte pins below identify the reviewed revision. Any later source change needs a targeted review and new pins.

The source now cleanly separates native success, engineering refusal/resource failure, saved-evidence integrity, and exact-model accuracy. Twelve fixed F/L target calls retain their declared associations; native scientific refusals cannot pass accuracy and are not replaced. Infrastructure/control/resource failures stop the schedule with durable partial records. No browser or timing substitute, fresh input selection, extra target iteration, automatic retry, online exact certificate or performance claim is introduced.

## Concrete pre-run findings and dispositions

1. **Input digest identity was ambiguous.** The initial checker used a bare raw-object digest and an `inputSha256` name for more than one identity. Corrected source uses explicit `inputFileSha256` and `semanticInputSha256`; the semantic digest hashes the canonical envelope `{domain:'m31-moving-admission/input/v1',id:caseId,input:raw}`. Browser, call evidence, contract and checker now agree with the saved reference identity. The actual input file remains separately pinned by byte hash.
2. **Consumption verifier lagged the native wrapper.** The initial checker recognized only the load-word checksum. It now independently reproduces the success-status character mixing, each safe-integer ID word and the eleven associated load words, and verifies separate load/identity/status counts. This small checksum is used for output consumption/consistency, not cryptographic certification.
3. **Two corruptions depended on row 0 having a useful witness.** A row-0 root equal to one or untilted axis could make an otherwise useful checker test unavailable. The squared-force-law and body-frame-force corruptions now deterministically transform all rows of the same predeclared cases, without choosing a favorable row or changing cases. They record actual changed words and require an appropriate total arithmetic-category failure count, rather than relying on a truncated witness list. Missing witnesses remain explicit failure and are never replaced.
4. **Checker control gates were too aggregate.** It now checks each inherited control's pass/input/screen/parity/omission/solution fields and saved L/F arrays, each wrapper control's actual expected status and individual assertions, and all ownership build records. It separately binds the browser source receipt to the pinned bundle and seven standalone source slices, exact allowlist, named Chrome/runtime metadata and all fifty-six adapter assertions.
5. **A native-success record could omit success diagnostics.** The checker now requires native admission with no reasons, descending graph eligibility, finite/valid geometry/nominal flags, finite residuals within the declared engineering cutoffs and a positive-term work count matching CSR length. These checks supplement, and do not replace, the four exact normalized accuracy checks.
6. **Generated browser evidence lacked a post-check preservation gate.** The parent supervisor now records additional hashes for the source manifest/publication on every stage and browser-attempt, browser JSON and browser journal before the checker. It rechecks all those bytes after the child completes, before recording a completed stage.
7. **Actual wrapper output ownership needed a check.** The browser now recursively collects array/view/buffer storage from caller input and native answers, checks disjointness, retains the previous successful answer and verifies that the next fixed call neither changes nor aliases its storage. This adds no query. The independent checker enforces the emitted predicates and declared successful-result predecessor chain.

All items above are source changes made before numerical observations. No control expectation was changed in response to a run.

## Arithmetic review

The checker decodes finite binary64 words as exact Fractions and implements round-to-nearest/ties-to-even by integer quotient/remainder arithmetic, including subnormal rounding and transition to the minimum normal. Native load consistency uses rounded f*x, rounded rotor-order sums, separately rounded cross-product products/subtractions, and rounded moment products/sums. This matches the declared native grouping without importing the producer. Both signs of arithmetic zero compare numerically; raw/prepared word identity and F/L parity remain byte-level checks.

Actual returned load words are the accuracy target. The checker does not replace them with exact load reconstructions from x. Independent consistency reconstruction is a separate failure gate. For each reference interval, it computes exact point-to-interval lower error and endpoint maximum upper error. Squared vector errors sum component squares, so force/moment decisions use Euclidean bounds without a native square root. Rotor normalization is mg/4, collective/world-force normalization mg and world-moment normalization mg*R, with supplied mg/R words interpreted exactly. Acceptance uses upper squared error <=(1e-8)^2; lower bound above it is definite failure, overlap is unresolved. Reference uncertainty is retained. The outward square-root conversion is reporting only.

Prepared geometry/constants/raw words are compared to their pinned saved reference. CSR validates row coverage/offsets, ascending unique nonself source indices, strictly positive native K/a and the actual term cap. Native support is compared to all exact-reference positive keys and reports both missing and extra entries. Coefficient error is explicitly diagnostic; it is not an unexplained accuracy gate. Final qualification requires all twelve calls, control/identity/status/support/load-arithmetic/consumption conditions, F/L parity, all four error categories and the fixed checker fixtures/corruptions.

## Browser and resource review

The browser loader verifies bundle length/hash and each embedded source slice before factory execution, uses a fixed seven-module dependency allowlist and resolves the copied relative CommonJS dependencies correctly. Buffer compatibility is confined to a local Uint8Array/DataView subset. The bundle executes exactly the bytes verified, through a Blob script. All scientific native targets see raw state/ID inputs, not exact reference coefficients, roots or loads.

The controller verifies source publication/manifest bytes, Node and selected Chrome/Playwright component pins before one pinned Chrome spawn with one new profile. It records Browser.getVersion metadata, prevents unlisted page fetches and verifies source/input bytes again after the schedule. The selected-component identity is explicitly narrower than a complete transitive runtime attestation. The source contains no alternate-browser or retry path.

Inherited controls retain the historical builder comparison, full symbols, omission reconstruction and admitted/ordered solve policy. Wrapper controls use their fixed literal inputs and analytic assertions; target input storage gets a fresh decode for each method. The encoded target evidence preserves both file and semantic input identities. Native refused results remain attempted calls. Query duration is diagnostic only; encoding, transport and independent audit are not represented as native query work.

The supervisor uses exclusive attempt/output files, checks the publication/cutoff before launch and requires a completed registered browser output before the checker. A retained group guardian remains unreaped until group cleanup, protecting against group-leader PID reuse. Parent-pipe loss kills the group; the Chrome spawn is forced non-detached. The stated limits are a supervised child wall deadline, inherited per-process CPU/file limits and post-stage total evidence limit. They are not aggregate browser CPU/memory ceilings; the protocol does not claim them to be. Uncatchable termination, host suspension or an externally killed guardian remain the documented userspace-supervision limitations.

## Remaining scope limits

No source-only review can establish that the retained cases meet accuracy, that every fixture expectation is observed, that all source/runtime gates are satisfied on the run host, or that the fixed resource allowance is sufficient. A resulting finite-panel pass supports only that panel in the recorded Chrome. Fresh-state, closed-loop, physical, scaling, timing and novelty claims remain outside this stage.
