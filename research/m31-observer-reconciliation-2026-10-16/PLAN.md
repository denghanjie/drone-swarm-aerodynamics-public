# Deterministic observer reconciliation study

Status: source development and inert synthetic tests only. This package allocates no browser, live process probe, GPU, historical experiment or empirical physical-data evaluation. The last failed trial remains immutable. The prior goal turn is classified as progress: it produced actual failed-run evidence, an independent cleanup-scope finding, a verified public checkpoint and a deferred unsuitable data-score proposal.

Question: can a caller refresh its append-only ownership registry around a single supplied process snapshot, avoid rejecting an already-intended browser merely because the first registry read was stale, and conservatively preserve any unresolved ownership observation through closure reporting?

The prospective cases are: (1) browser already registered; (2) browser intent/spawn appended between the first registry read and process snapshot; (3) truly unregistered reachable detached descendant; (4) no detached descendant; (5) malformed/nonappend-only registry or invalid caller group proof; (6) closure with an unresolved observation even if known groups are later absent. The registry writes exact executable/profile intent before spawn. The same process snapshot must be used for reclassification; no supplied process may vanish from the evidence merely through selecting another snapshot.

We will AST-extract the frozen old sample function and closure expression into a deliberately mocked environment. No original module import or operational top-level statement is allowed. Test expectations are saved before those tests. Source hash and extracted AST provenance bind the control. Old-code behavior in constructed schedules demonstrates possibility, not the cause of the historical abort.

The candidate is a minimal pure helper plus an integration design: registry read → supplied snapshot → registry refresh → exact ownership classification. Caller validation of append-only records, nonce and exact executable/profile identity remains mandatory. Ancestry or numeric PID alone grants no signal authority. Any descendant still unadmitted after the refresh is retained privately and permanently prevents a whole-observed-process-closure claim for that invocation. Known-group absence can be recorded separately. This conservative first version adds no identity-discharge protocol or new claims about native process birth identity.

Finite development budget: at most three small source-review revisions and100pure synthetic cases; no heavy benchmark, real measurements or operating-system scheduling simulation. Retain failed tests as development failures; do not call the helper runtime-qualified. A future integration needs its own full source/admission/review and prospective allocation before any live use. Existing terminal attempts cannot be repaired or reclassified.

Success here means the source and deterministic cases enforce these declared state transitions and conservative closure semantics. It does not prove reliable OS monitoring, GPU readback, physical validity, speedup,5000drone coupling or novelty. The latest visible Three.js milestone remains the actual failed-trial evidence view; no new drone trajectory is invented for a source-development substep.
