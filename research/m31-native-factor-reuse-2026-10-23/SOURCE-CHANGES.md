The candidate wrapper is copied from the pinned native-fresh-transfer native-load.cjs with only its kernel require path changed. The candidate kernel is copied from its vendor/kernel.cjs: dependency paths point to those exact pinned original dependencies; a fresh lazy beta cache is inserted after screen fallback; the cap-check and scaling loop reuse beta; each scaling row lazily computes nu once. All ordinary assembly storage, guards, coefficient ordering, arithmetic grouping, validation, solver, load and output fields remain as before. Extra factor payload is9N bytes plus object overhead; inherited assemblyStats excludes it. Standard fixed intrinsics/cancellation-only guards/owned immutable data assumptions apply.

Producer, common gate, supervisor, launch, finalizer, UI checker and viewer are adapted from the earlier radial-integration/phase-attribution checkpoint scaffolding. New producer retains both archived nine-exclusion and strict current two-timer-exclusion comparisons, input preservation, full saved evidence, paired failure journal and a single fixed performance decision. New controls and independent saved-evidence audit were authored by the existing evidence reviewer. The protocol challenger reviews these independently. This is internal project code provenance, not a claim of a published external research innovation.

The viewer replays existing density-checkpoint positions with the new timing and source-derived expression counts. No new flight is simulated by browser rendering. Original trajectory provenance and failed alternatives remain visible. Source-derived expression reductions exclude unchanged computations and cannot establish a timing improvement.

Administrative recovery of local input identity uses tree OIDs and local blob hashes; it is not a model execution or a Git-blob extraction. The original failed reads are retained separately. Public inputs must still be independently fetched fresh before numerical launch.
