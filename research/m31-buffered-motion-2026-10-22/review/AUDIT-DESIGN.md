# Prospective saved-evidence audit design: buffered motion queries

22 October 2026. Source preparation only. No scientific module has been imported or executed, no source journal decompressed, no selected native input extracted and no old allocation restarted during this design work. The prior candidate audit and cache/native wrapper sources were inspected as text; published paired-resolution metadata supplies fixed paths/counts. The implementation below is bound to the producer/extractor schema described in this document. Only syntax/AST inspection has been performed; this document is not an execution receipt.

## Fixed workload and trust boundary

The comparator is the published paired-resolution result commit `7fae6ca51733a9bc9b6b2ada5156d05a7a64f747`, with result manifest 51,543 bytes, SHA-256 `e54ba424f77676f0f04e7037e01d646b4d2e4c7b76acfe085a479cd4887cac44`,237 pins. Its four new fine paths are ordered seed 2026102101 original, seed 2026102101 memory, seed 2026102102 original, seed 2026102102 memory. The source, receipt, original report/index, closure and all source parts must be pinned before extraction. Prior result acquisition anomalies remain history and do not license unbounded new retries.

Select three disjoint windows per path by **zero-based attempted native-stage ordinal**, including a recorded refused attempt when it falls in the selected range:0–159,4000–4159 and the final 160 attempted stages. The published index fixes total attempted stages at 5,792 for the first original path and 8,000 for the other three. Final windows are therefore 5632–5791 and 7840–7999 respectively. Selection is by recorded order across segments, not endpoint index, successful-only filtering, floating-time sorting or outcome-dependent replacement. There are exactly 12 windows,160 stages per window and 1,920 distinct selected stage records. The first-original final stage is the known recorded domain refusal; its presence must not be treated as a newly surprising producer failure or silently excluded from query-cost accounting.

Every window has one warmup repetition(-1) and eight measured repetitions(0–7), with both baseline F and candidate C receiving all 160 saved current projected inputs. That is 34,560 new native calls if the complete allocation succeeds:12×9×2×160. Both modules are called with model method F; F/C are external experiment labels. Each candidate stream starts with a fresh reset and processes its window in chronological recorded order. There is no cache carry between windows/repetitions and no integrated candidate trajectory: these are fixed recorded-query replays.

The source's 1,919 successful selected stages and one selected refusal imply 34,542 replay successes and 18 replay refusals if every F/C/reference comparison passes. These conditional counts do not permit acceptance of an unexpected refusal, unexplained success, mismatch or numerical retry. A matching inherited refusal remains comparison evidence. An unexpected status, output mismatch, malformed result, resource failure or persistence failure closes the new allocation.

The audit is a separate one-attempt, saved-evidence-only allocation with 1,800 successful wall seconds and 256 MiB output. Its external supervision and producer/extractor caps must be fixed in the protocol. No execution is authorized by this document. It does not rerun F/C, the controller, native solver, RK integration, initialization or trajectory safety logic. It may independently scan the pinned old journals to bind selected records and recompute the candidate-list certificate from saved selected coordinates; that is a new provenance/selection and cache-certificate check, not a repeat of the old full scientific audit.

## Source selection and independent binding

The extractor must preserve every selected complete original journal envelope, with window/index, case, global attempted-stage ordinal, segment/local stage ordinal and original uncompressed line sequence/offset/byte length/SHA-256. A selected gzip envelope containing the parsed complete original record plus its literal source-line identity is sufficient; duplicate base 64 copies are unnecessary when the auditor independently scans the source bytes. The extraction index pins selected gzip bytes, the exact fixed window table and all reached old source descriptors/parts. The current source manifest and audit gate separately bind the old source report/index/result manifest/final receipt and closure.

For each old compressed part, verify complete length/hash before bytes reach decompression. Check ordered contiguous part offsets and complete compressed/raw aggregate identities and record totals. A forward scan may parse envelopes to count stages and bind source order. The auditor must independently derive the 12 windows from the frozen old index, require exactly 1,920 selected matches with no duplicate/missing/reordered record, and compare the complete selected parsed record to the independently read source envelope. Re-serialized JSON bytes cannot stand in for the original line hash, because number formatting may differ by language. Original line hashes include the newline. Limits, canonical sequence order and all read anomalies remain explicit.

For selected stages, bind stage/local/global ordinal, step/stage IDs, segment origin, dt and actual saved time words, nativeInput and native evidence to the archived record. Validate 64 canonical IDs and 17 physical words per input, and require the archived native raw input to bind to that same projected input. Validate all three adapter annotation fields before normalization:caseId equals stageId; semanticInputSha256 and inlineInputCanonicalSha256 equal the canonical projected input identity. No old controller/derivative/RK arithmetic is independently regenerated in this allocation.

## Exact normalization contract

All three comparands must start from **m31-native-load-evidence-v1**: archived stage.native, baseline.encodeEvidence(result), candidate.encodeEvidence(result). Do not mix raw m31-native-load-result-v1 with encoded evidence or silently rename fields. All must have the unchanged ordinary-binary64-full-contribution model and native method F before normalization.

Recursively sort object keys, preserve array order, preserve strings and null, preserve booleans distinctly, and encode every remaining finite JSON numeric value as its exact 16-digit big-endian binary64 word. Existing scientific word strings are left unchanged. NonfiniteWord wrapper objects are preserved exactly; they are not converted to null, ignored or treated as ordinary finite numbers. Canonical semantic JSON uses fixed compact separators and one trailing newline, with its full byte length/hash pinned. Raw field presence/absence remains meaningful.

Only these exact rooted paths may be excluded from semantic equality:

- method, after separately requiring F;
- timing;
- diagnostics.buildPhasesMs;
- diagnostics.geometryWork.gatheredNonselfCandidates;
- diagnostics.screen.orderedPairVisits;
- diagnostics.screen.componentTests;
- caseId, semanticInputSha256, inlineInputCanonicalSha256, after their separate archived adapter binding checks.

The last three are top-level adapter annotations only. The same spelling nested elsewhere is not excluded. No whole diagnostics, geometryWork or screen object may be removed. In particular certifiedSkippedPairs, center-norm counts, current-screen eligibility, graph/admission, symbol counts, coefficient words/indices/order, solve/residual work, complete prepared geometry/force words, solution/load words and full consumption checksum remain semantic targets. Refusal status/reason/stage and every present partial evidence field remain comparison targets. Removed timing/work fields must remain in the per-query excluded evidence for review and cost interpretation.

Require new F = new C = archived normalized reference for each stage and repetition, by actual canonical bytes as well as length/hash identity. Source reference identity is checked independently, not trusted merely because the producer repeats its digest. Content-addressed deduplication may reduce files; it cannot reduce query rows or comparison coverage. Each actual query retains its input-before/input-after identity and inputPreserved flag, and all 64×17 input words are bound to the selected input. Per-query call/window/rep/method/index schedule is exact and independently reconstructed.

## Candidate certificate and lifecycle

The candidate implementation remains byte-identical to the already published buffered candidate modules; only the new harness/extractor/auditor are new. Retained state consists solely of canonical IDs, boxes, candidate rows and counters. Cache witnesses and statistics must be saved for every candidate query, including matching refused outputs. Baseline witnesses/statistics are null. Deduplicated witnesses still retain a per-query reference.

Every witness stores witness.boxes as explicit binary64 words and boxEncoding="binary64-be-hex". Native JSON numbers can erase the sign of negative zero, so the design must not assume that uninspected recorded coordinates exclude signed zero. The audit independently reconstructs reference boxes with nextDown(RN(center−.125)) and nextUp(RN(center+.125)), inclusive containment, exact canonical IDs, rebuild/reset/invalidation events, candidate rows in ascending ID order and every work counter. It checks box words exactly, not with a numerical tolerance. No hidden cache survives a reset or unexpected count/identity change.

For each receiver/source pair, independently reconstruct the actual stored interval screen:RN(sourceLo−receiverHi)≥4 or RN(sourceHi−receiverLo)≤−4 on any axis permits omission. Every other nonself source must appear exactly once in the canonical row. Every omitted pair at every current selected query must also fail the current unchanged component screen(abs(currentSource−currentReceiver)≥4 on some axis). Current centers must remain within the stored boxes on reuse. The audit checks fresh current inputs even where the candidate rows are reused.

A native build/admission refusal can occur after cache access and must advance cache statistics according to the unchanged implementation. An input refusal before candidate enumeration must not be credited with a cache step. For the fixed selected source, input identities/counts and the known refusal stage determine this behavior; the implementation must not blanket-skip all refused queries. Global-screen or cache eligibility fallback retains exact F work and must not silently truncate rows. Branches not reached by this recorded N64 workload remain explicit noncoverage; earlier synthetic failures are not erased or promoted to qualification.

## Timing and decisions

Each query outer timer must enclose owned input copying and the complete unchanged query including native load/ID/status consumption. Extraction, encodeEvidence, normalization/hash/CAS persistence, cacheStats/witness collection, equality checks and viewer preparation are separately recorded overhead outside the query timer. Reset duration is included in each stream's reported cost; the baseline uses the same wrapper/reset boundary even if it has no persistent candidate state. No warmup or refused observation may be dropped from its recorded stream; warmup is excluded only from the eight measured-ratio decision.

The audit derives group totals from the exact chronological query rows, matching the producer's frozen operation grouping. totalMs is sequential resetMs plus every outerMs; sumQueryMs is accumulated separately from positive zero, while totalMs starts at resetMs; the auditor preserves both operation sequences. admittedMs/refusedMs are separately accumulated from the appropriate statuses. They need not sum with bit-identical rounding to another differently grouped total. Native timing fields must be finite/nonnegative, internally coherent and nested within the measured outer query boundary; all excluded work fields remain auditable.

For each measured repetition, sum the 12 window totals for F and C in fixed window order before computing aggregate C/F. Report all eight aggregate ratios, their prescribed median grouping, strict wins and the prospectively fixed gate. Also retain all per-window ratios and coverage categories; do not pool individual query ratios or select a favorable window after observing costs. The fixed thresholds are median aggregate C/F ≤0.90 and at least 7 of 8 strict C<F wins. Coverage additionally requires at least one measured reuse and one measured box-exit rebuild across the workload. Cold builds alone do not satisfy that coverage gate. Separate admitted-query and refused-query durations prevent the single known refused reference from being described as successful solver work. Wall/output caps are resource bounds, not benchmark results.

## Export and failure meaning

The audit report must distinguish evidenceIntegrityPassed, exactReferenceEquivalence, candidateCertificatePassed, measured cost gate and coverage gate. A failed cost/coverage gate is a valid recorded result when evidence checks pass; an evidence mismatch cannot be converted into a performance outcome. Export fixed source-stage positions/times/provenance and per-window cache/timing summaries without fabricating integrated candidate motion or missing suffixes. Both original and memory source paths are inputs to this query experiment, not newly simulated candidate-controller outcomes.

Preserve extraction/producer/audit launch and exit receipts, all source/result pins, complete query/group schedules, refusal records, cache transitions, timings and read/persistence anomalies. Unexpected failure closes the whole allocation; no repair/rerun, tuning, changed bound, extra window or additional repetition is permitted under this protocol. Current-stage F/C equality and a conservative candidate certificate do not establish real aerodynamic accuracy, flight safety, general speedup, independent statistical trials, large-swarm performance or research completion.

The current config fixes cases, total stage counts,12 windows, nine repetitions,34,560 calls, all nine rooted exclusions, allocation caps and keepGate. The predecessor gate requires result manifest 51,543 bytes/SHA-256 e54ba424f77676f0f04e7037e01d646b4d2e4c7b76acfe085a479cd4887cac44 and the final receipt 2,002 bytes/SHA-256 04222b030249899253cfc47808c5643d43cc90f3e6d87c42c1332b59db9039fa. Existing native refusals do not invalidate that prior evidence. New extractor and producer must each have closed zero-exit internal and external receipts, passing wall/output bounds, no failure artifact and complete regular-file inventories before this audit can pass.

extract/selected.jsonl.gz has exactly 1,920 envelopes with keys window, index, caseId, globalOrdinal, segment, localStageOrdinal, rawOffset, sourceLineSha256,sourceLineBytes, record. Each record is the full original journal envelope. The auditor independently streams all eight source journals, checks every newline/sequence and compressed/raw aggregate, matches the next selected envelope only at the fixed ordinals, and uses deep comparison that distinguishes booleans and numerical sign bits. It binds the original literal line bytes/hash/offset separately, so a reconstructed JSON serialization is never represented as an original line identity.

results/input-binding.json binds the exact extraction index bytes/hash and selectedPin to the new source commit/manifest. references.json has 1,920 ordered {window, index, semantic} entries. The auditor independently normalizes each selected encoded native evidence, compares the actual content-addressed file bytes to those canonical reference bytes, and retains its input/hash/outcome/provenance. There is no native query or old trajectory reintegration in this process.

Failed comparisons, method errors or mutations are preserved by the producer before their assertion closes the allocation. This auditor does not approve partial failed native panels as complete comparisons.

The query schedule is rep -1 through 7, then window 0 through 11, then methods F, C if(rep+window+10)%2==0, otherwise C, F, then index 0 through 159. It reconstructs a fresh candidate cache at each C stream and applies one cache step per selected query, including the build-stage refusal. Every candidate row's counters and last-event metadata must equal independent reconstruction. Every witness reference is byte/hash verified; deduplicated bodies are reusable, but omission/containment checks still run against every actual repeated input. Baseline cache/witness are null. The auditor independently accumulates all fields from query rows in the source's operation order. It separately validates positive total durations, comparison timing within encoding overhead, inner native total within the query outer timer, finite nonnegative phases and the declared small clock-telescope tolerance. That timing tolerance does not relax semantic or input-word equality.

summary.json contains complete, calls, referenceEquality, reps, medianRatio, strictWins, coverage, coverageGate, costGate, keepGate, scope, readEvents, wallSeconds. All numerical summary fields and boolean gates are independently reconstructed. Producer readEvents and wallSeconds are retained as observed metadata, with closure binding and bounds; they are not invented by the auditor. Aggregate ratios use 12 window totals per repetition, median uses the mean of sorted positions 3 and 4, and ties never count as strict wins. No performance outcome is assumed before execution.

The auditor validates exact inventories, including every referenced semantic/witness file and no extra producer result. exit.bytesWritten must equal actual result bytes before exit.json. It rechecks all consumed/source identities before success, including 93 old part identities without a second decompression scan. Each expected-identity read allows at most three attempts before bytes are exposed, and each failed read is retained with path/operation/attempt. An uncaptured new small metadata file receives one capture read; arithmetic/parsing is never retried. These checks do not turn previous acquisition errors into numerical retries or diagnose their cause.

Outputs are audit/audit.json and audit/viewer-data.json plus launch/exit receipts. The report has passed/checks/summary, independent counts and source/closure/input pins, all retained anomaly lists, normalization/certificate boundaries and viewerPin with file="viewer-data.json". Each frame has index, globalOrdinal, time, status, reason,64 positions, measured-rep 0 C cache state and original line provenance; it is labeled recorded-attempted-RK-stage-input with completedEndpoint:false. Repeated or nonmonotonic RK times are retained. The report's passed flag attests evidence integrity and certificate/equality checks, while keepGate may legitimately be false because of cost or unexercised motion-rebuild coverage.
