# Lossless publication plan

GitHub rejects single blobs above100MiB. The complete extracted selected.jsonl.gz remains the scientific artifact and stays available locally for all allocations. It is explicitly ignored by Git so a large original never accidentally enters history. After the scientific/display allocations close, a separate single-use byte-transport operation copies this file into ordered32MiB pieces under transport/. This operation has a300second wall ceiling and768MiB output ceiling, with1MiB closure reserve; no parsing, source extraction, query, selection or timing is repeated. Smaller files remain unchanged. This is transport, not another scientific allocation.

transport/index.json binds the original file's exact bytes/SHA256, the extraction index's selectedPin and every ordered piece's offset/bytes/SHA256. The public result manifest pins all actual published files and includes the logical original descriptor. Do not claim the large ignored original is a separately committed Git blob. Independent result verification must check the piece hashes and reconstructed stream identity against the audited original. source/reassemble.py recreates the exact ignored local file on a fresh clone, refusing to overwrite an existing file and verifying each piece plus aggregate before renaming. Keep failed transport attempts and partial pieces; never recreate scientific evidence to fix a publication problem.
