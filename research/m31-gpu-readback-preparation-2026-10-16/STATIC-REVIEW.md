# Static review of the proposed tiny GPU-readback boundary

Review date: 2026-10-16, Asia/Shanghai. This preparation assignment began before the existing `2026-10-15T23:00:00Z` launch cutoff. The cutoff has not moved. This review used local source reads, cached primary-document reads and source/artifact hashing only. No browser, adapter, device, shader compiler, GPU queue, operational producer or saved-evidence reviewer was invoked. No new network retrieval occurred. Earlier campaigns and their evidence remain unchanged.

## Disposition

The inspected page implements the intended ownership boundary: it copies the actual 128 mapped bytes into a separately allocated ordinary heap buffer while mapped, then unmaps and destroys the GPU resources before converting the owned copy into the returned array. The byte-reference package properly separates byte equality from GPU provenance, producer phase claims and process closure. Neither package establishes an executed GPU result.

This is preparation, not launch admission. The strict pure envelope validator exists, but its integration with a new host, owned-process supervision and independent saved-file review must be completed and source-pinned; fresh execution/review windows must be allocated; and the WGSL arithmetic/layout/byte-order primary-source gap must be resolved. A later positive would concern this one fixture and admitted environment only.

Final page and validator source pins are recorded below. Review conclusions apply only to those exact bytes, not to later edits. The author confirmed the files stable after the final static read.

## Source-level findings

The fixture is well chosen for this narrow boundary. It has 32 u32 words, four prefix sentinels, 17 active words and 11 suffix sentinels. Three groups of eight launch 24 lanes; the guard excludes seven surplus lanes. Every active expected value differs from its initialization. Comparing all 128 bytes can detect untouched output and this fixture's prefix/suffix corruption; a passing result cannot prove general out-of-bounds safety.

The page initializes only the distinct sentinels on the CPU, using `Math.imul` and `DataView.setUint32(..., true)`. It does not construct the expected active output on the CPU. The embedded shader and separate `fixture.wgsl` have identical source bytes. Storage uses STORAGE | COPY_SRC | COPY_DST; staging uses MAP_READ | COPY_DST. One dispatch, one copy and one submission are encoded. Counters distinguish encoded dispatches from submission, and the single-use guard prevents a second page function invocation in that page instance. Host invocation accounting is still required.

After successful mapping, the page obtains the complete raw range and performs `owned = new Uint8Array(128); owned.set(new Uint8Array(mappedRange))`. `owned.buffer !== mappedRange` checks separate storage. It records map state and byte lengths, unmaps, observes detachment, destroys both buffers, pops the three scopes in reverse push order, and deliberately destroys the device. Only afterward does it call `Array.from(owned)`. No post-unmap payload access or host re-encoding from numeric u32 results is used. Failed runs can still retain actual bytes when ownership and release conditions allow; those bytes must remain failed-run evidence.

The device-loss observer and uncaptured-error handler are installed before substantive GPU work. A loss with reason unknown remains unexpected even if its handler runs after the deliberate-destruction flag is set. A previously recorded unexpected loss is never cleared. Awaiting the device-loss observer during cleanup prevents null scopes or a resolved pipeline alone from creating a clean candidate. The adapter's API-reported fallback status is observed before requesting a device; true or unavailable is rejected. API-reported false is an admission condition, not hardware attestation or proof of device performance.

Initial draft issues were communicated to the author: fixture IDs differed; settled rejections could leave pending flags true; pipeline rejection reasons were collapsed; and final event overflow needed to affect candidate status. The inspected revision resolves these. It also resolves two boundary bookkeeping points raised by this review: it observes an already-created promise before an early deadline throw, and applies the cleanup limit to the final elapsed sample before candidate classification. No remaining material page ownership/order or false-clean classification blocker was identified in the pinned draft.

The pure `validation.cjs` checks exact record keys and ordinary enumerable data properties, dense arrays, bounded lengths and enums, integer byte values without coercion or negative zero, fixture/layout identity, event chronology, event/count consistency, resource/loss observations and pending-state consistency. A candidate additionally requires the exact complete lifecycle, all counts equal to one, no failure or overflow, three clean popped scopes, expected deliberate loss with no previous/unexpected loss, API-reported nonfallback admission and final elapsed time below ten seconds. It returns a copy of actual byte values and explicitly leaves independent persistence unverified. It does not import expected bytes or promote the page's candidate label into a content match. This is a source inspection, not an executed host validation result.

The page author supplied a retained record of 70 passing pure validator/fixture cases, including partial creation, pending versus settled rejection, mapping timeout, unexpected loss with null scopes, scope-before-destroy ordering, deadline boundaries, malformed arrays/records and structurally valid wrong output. This reviewer read the record without rerunning it. The page's reference generator uses BigInt with manual byte extraction and produces the same expected/sentinel hashes as the independent Python package. Neither fixture generator is imported by the page's output path.

## Independent byte package

The independent source computes expected words with Python integer arithmetic and explicit reduction modulo 2^32, then packs `<32I`. It accepts only a 128-element list of exact integer bytes, with no coercion. Its persisted-byte comparison accepts at most 129 bytes so a bounded reader can detect trailing content. It compares actual return with actual supplied file bytes, both with the expected fixture, and active/padding regions separately. Receipt checking hashes actual supplied bytes. It neither reads files nor certifies closure, GPU execution or producer phase order.

The retained pure-test record reports 33 passing inert cases, including an independently written repeated-addition reference, explicit byte extraction, sentinel-only output, word-endian reversal, active/padding mutations, short/trailing content, expected-file substitution, malformed values and forged expected receipts. This reviewer read that record and the source; it did not rerun those tests. The package explicitly demonstrates that CPU-created expected bytes pass byte comparison without GPU evidence. Its ordinary Python ownership example is correctly labeled as not testing WebGPU unmap.

The evidence contract contains no material technical overclaim found by this review. No additional implementation-mirroring tests are requested. A future filesystem/host wrapper must receive focused review of its new trust and lifecycle boundaries.

## Minimum contract for a future separately allocated test

1. **Freeze before invocation.** Resolve the WGSL source gate and final static findings. Pin the exact page, shader, host, validator, independent reference/reviewer, runtime identities and fixture. Publish and independently retrieve the exact source/freeze as required by the proposed protocol. Define fresh execution and review windows; these source drafts allocate neither.
2. **One supervised lifecycle.** Admit one browser/page/device, one guarded dispatch, one copy, one map and one payload-bearing evaluate call. The page's eight-second work and ten-second cleanup limits are elapsed-from-entry limits, not cancellation. The external evaluate deadline must exceed the complete ten-second page interval with a defined return/validation allowance; a separate outer budget must cover actual persistence and owned-process closure. Reusing a ten-second host race would discard the page's cleanup result at its own boundary. No retry, alternate extraction, extra adapter/device or expected-output repair is permitted.
3. **Validate the actual envelope.** Bound the decoded structure, keys, arrays, strings, enums, numeric fields and chronology before byte conversion. Enforce fixture/layout identity and candidate consistency while labeling page phases as self-reports. Retain a validly shaped wrong array as actual evidence. Malformed values, page failure, byte mismatch and incomplete evidence need distinct dispositions. A missing/rejected evaluate return reveals no unreturned page phase.
4. **Persist actual bytes and close explicitly.** Write only the accepted actual returned byte array to an exclusive new artifact. Preserve actual partial files; distinguish written length, close success and digest. Retain the decoded returned array separately. Expected bytes and expected digest may be comparison inputs only. They may not fill, truncate, replace or repair actual data.
5. **Review closed files independently.** After external process closure, a separately allocated reader must reread actual retained files with bounded reads, verify source/manifest identities and actual sizes/hashes, and compare return-versus-file and each-versus-fixture independently. The supplied pure comparison functions do not implement this reader. Record integrity may pass for an honestly retained failed experiment; that cannot make readback pass.
6. **Preserve limited conclusions.** Keep API call returns, producer phase reports, external evaluate/persistence/process observations and independent byte facts distinct. Require consistent lifecycle evidence as well as bytes for any complete engineering account. Device/buffer destroy flags do not establish immediate physical reclamation. Matching bytes alone cannot authenticate GPU origin or copy timing. Unexpected loss, mapping rejection, pipeline/compilation/scope error, timeout, serialization failure, persistence failure and incomplete closure must not collapse into success.

A tiny integer success would not establish f32 accuracy, realistic output-size cost, long-lived resource reliability, GPU/driver portability, 5,000-agent performance, an explanation of historical missing outputs, aerodynamic validity or a scientific successor. Those remain separate questions requiring separate evidence.
