## Candidate and proof compatibility

The inspected `candidate.cjs` uses exactly the documented halfwidth 1/8, absolute coordinate bound 2^20 and threshold `3+2^-20`. Threshold addition is exactly representable; the squared threshold is rounded then moved upward. Endpoints are rounded then moved outward. Each squared axis gap and both grouped additions are rounded then moved downward and clamped to nonnegative zero. This matches the conditional lemma's geometric construction and the schema's specified grouping.

The endpoint differences are source-low minus receiver-high and source-high minus receiver-low. Monotonic rounded subtraction encloses current rounded differences for inclusive members; the cache does not substitute ideal unrounded coordinate differences. `max(0,lo,-hi)` correctly covers positive, negative and zero-crossing intervals. Nonnegative clamping after `nextDown(0)` prevents a spurious negative squared bound without violating its lower-bound property.

The input domain makes the candidate's endpoints, differences and squared bounds finite; the reviewer found no unguarded overflow path within that declared domain. Current global eligibility is recomputed for each `step`. Coordinate-domain or screen failure invalidates the cache and retains all pairs. Count and canonical ID-vector changes rebuild; containment is inclusive; a box exit rebuilds before the returned mask is used. The previous cache is cleared before construction and published only when complete. The producer copies the returned mask before record construction. The candidate retains no attitudes, rotor terms, force/admission outputs or solutions.

The cache is an internal diagnostic helper, not a public input-validation API. Its caller verifies finite three-coordinate points, matching ID/point lengths, safe increasing IDs and bounded counts, and requires 64 agents for every selected data stage. Fixed controls use two or three agents. Broader malformed-input behavior is not claimed to be qualified.

## Independent auditor

The independently authored auditor imports only standard-library modules. Its integer-ratio binary64 rounder handles ties-to-even, exponent/carry transitions and gradual underflow; the certificate reconstruction does not use floating multiplication, square root or `hypot`. It reconstructs every endpoint word, difference interval, downward square/sum, upper threshold and complete mask at every build, and separately checks the rational lower-bound inequality.

It independently replays cache lifecycle, witness numbering/context, exact fixed control inputs and expectations, inclusive current containment, every stage mask, all pair classes and counts, the exact summary, and actual call closure. Current component differences and global spans use explicitly disclosed ordinary Python basic arithmetic; this is not described as a norm oracle. The fixed bounded input values that parse as Python integers have exactly representable relevant integer differences, so that representation does not introduce a different component decision here.

The auditor additionally rejects a negative finite recorded norm as an evidence-consistency anomaly. This is intentionally stricter than merely reproducing F's class-3 branch for such a hypothetical anomalous return. It can fail the audit; it cannot certify an unsafe omission or erase/reclassify the recorded word. The audit author confirmed that intent.

The source gates require the exact fifteen committed input pins, prior publication/audit bindings, current public freeze receipt, required source files and all three Three.js dependency files. The auditor accepts exactly eleven successful producer result files and reconciles their total/pre-exit byte counts with both producer closures. It checks complete raw binary lengths and every pair slot, rejects extra/missing rows or witnesses, and rechecks consumed local identities before success. The resulting `filePins` descriptors match the finalizer/viewer interface.

The audit's declared result remains limited: it classifies actual recorded intrinsic outputs without independently recalculating them, preserves the inherited refusal, and does not prove any universal runtime path, ideal norm accuracy, full native equivalence or physical behavior.

## Failure handling and allocation closure

A material early-draft issue was corrected before freeze: witnesses were originally retained until the end and duplicated wholesale in the catch handler despite a 1-MiB failure reserve. The reviewed revision writes each witness to append-only `witnesses.jsonl` before the corresponding norm evaluation, and removes the unbounded duplicate failure write.

The final producer records active context, last pair, completed pair-prefix length and whether that active record was already persisted. On a caught failure it stores any unpersisted prefix in bounded scratch binaries. At most 4,032×10 bytes are needed for the three prefix buffers, within the reserved 1 MiB together with the bounded failure/exit metadata. It marks the process unsuccessful before attempting those writes. Partial ordinary-stage writes may coexist with the clearly identified interrupted prefix; they do not become successful complete records.

A hard kill can still leave an in-flight call or partial file without a complete receipt. The protocol says so expressly. The exclusive launch locks, output directories, supervisor process-group termination, wall/output caps, nonzero-closure rejection and no-retry policy prevent such an attempt from becoming a qualified run. Physical filesystem or process failure is not claimed to be lossless.

Budgets are fixed prospectively at producer 300 s/128 MiB, audit 900 s/16 MiB, finalizer 120 s/2 MiB and UI 150 s/16 MiB. The launcher checks the Node executable identity. Output budgets are evidence-byte caps, not RAM limits or performance results. The supervisor's wall measurements serve allocation closure only. Read-only identity retries are separately bounded and recorded; no scientific or UI invocation is retried.
