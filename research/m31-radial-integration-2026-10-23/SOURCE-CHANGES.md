# Implementation boundaries

The new source/candidate.cjs and candidate-kernel.cjs are byte-identical copies of the20October buffered candidate files. Their relative baseline imports resolve to the same pinned native-fresh-transfer modules. This preserves input validation/canonical order, current geometry preparation, global-screen eligibility, rotor guards/classification, coefficient ordering, admission/refusal, ordered solve/residuals and delivered-load construction. This is a static identity statement, not evidence that every resulting call will match.

Only candidate-cache.cjs changes the omission arithmetic from an axis4 interval condition to the previously tested radial squared-distance condition. It also reports the new limit/margin/threshold, witness schema and buildIntervalCoordinateTests name. Cache identity, inclusive containment, bounds/fallback, candidate-entry cap, canonical rows, invalidation and witness copying retain the old implementation structure. The threshold's nextUp calculation occurs only when the module loads after source admission; static syntax checks do not load it.

The run/common harness derives from buffered-motion, with immutable selected-part concatenation instead of new extraction, the expanded explicit work-counter contract, a separate stricter baseline comparison, and failure context. Scientific modules accept only current inputs and the cooperative guard, never archived reference evidence or prior radial masks. The prior masks are audit evidence, not an oracle supplied to the candidate. Every excluded field is persisted; exact counters are checked independently.

Display code derives from the radial evidence viewer and its successful separate recovery interaction check. It binds the new audited timing summary and representative saved actual-work rows to old recorded positions. The scrolled visible-canvas hit test and saved before/after/reset camera evidence are retained prospectively. No new flight/model calculation is available in the viewer.

The independent auditor is separately maintained by the existing evidence reviewer, with disclosed textual reuse of standard-library helpers and the earlier exact-ratio arithmetic routines. No new package or runtime is installed. Exact sources, imports, runtime identity and input provenance are frozen together before execution; post-freeze fixes require a distinct reviewed attempt.
