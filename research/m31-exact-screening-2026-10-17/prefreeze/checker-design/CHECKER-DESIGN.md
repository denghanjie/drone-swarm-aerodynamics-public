# Independent checker and output-contract design

This is a prospective source-only design review. It does not implement or execute a checker, candidate, hierarchy, fixture or scientific calculation. No external operation, new agent or closed-suite rerun is used. The inherited read inventory is recorded separately. Exact scene literals, the final schema, control count and execution allocation remain to be frozen before implementation or evaluation.

The proposed exact hierarchy can satisfy the common M-current load interface, provided omitted scalar zero records are interpreted as explicit zero claims over an independently reconstructed complete source universe. Neither a reported zero count nor agreement between the two methods is sufficient evidence. The saved checker must independently audit both methods against the same complete guarded oracle, then separately check their common outputs.

## Model and execution identities

Use one scene record containing the frozen raw input and two method records in fixed order: complete baseline, exact hierarchy. Both methods must independently perform complete preparation and global validation from that raw input, use the same prepared-pair implementation, and independently invoke the common proposal/certificate/load code. Sharing immutable constants and functions is appropriate; feeding baseline preparation, positive edges, a candidate, a certificate, admission answers or a tree into the hierarchy is outside the comparison.

Saved output cannot establish that computation was performed twice or that no cross-method answer was reused. Source review and a frozen execution schedule establish that obligation. Instrumented counts are checked against reconstructed work, but are algorithmic work evidence, not measured time or proof of runtime cost.

Every method's prepared array should remain explicit, with one input-order record per drone: stable ID, prepared object or null, and raw/preparation rejection or null. Independently regenerate all raw bits, constant expression-graph values and prepared bits. Bind every subsequent tree, query, coefficient, candidate and load to those IDs and those exact operands. Stable IDs are unique integers in a frozen range; source exclusion is ID equality. Preparation of every drone precedes self exclusion, including an isolated scene. Keep the established distinction between raw rejection with null and preparation rejection retaining the prepared object.

Use the published independent raw/prepared pair oracle as frozen source, without importing any candidate implementation. The new shared prepared-pair adaptation must be checked on every fresh scalar pair against this independent model, including pairs the hierarchy skips. The finite qualification may spend complete-oracle work in the separately accounted saved checker. It must not run the old generated suite, old checker main or old controls. If reference adaptation is needed for cost, it needs its own source review; matching two candidate implementations is not an independent adaptation test. Preserve the hashed-source-buffer loading fix from the coupled checker so cached bytecode cannot substitute for the pinned reference.

## Recommended common record shape

The exact JSON names may be adjusted before the contract is settled. The following semantics should be frozen rather than inferred by the checker:

- Document: `schema`, `specId`, `runtime`, `sourceSha256`, `constants`, `records`.
- Scene: `id`, `input`, `methods` in fixed complete/hierarchy order.
- Method: `method`, `prepared`, `execution`, `globalGuard`, `tree`, `queries`, `coverage`, `result`, `solve`, `certificate`.
- Execution: a declared mode such as `global-preparation-stop`, `complete`, `screened`, or `fallback-complete`; a separate fallback reason and stage; and deterministic work counters.
- Result: existing model/certificate status, branch, canonical stable-ID witness, and exact tolerance decision. Execution fallback is not a model rejection.
- Solve and load certificate: the established candidate bits, row contractions/defects/factors/root intervals, exact rational candidate loads, signed load boxes, per-rotor/per-drone error uppers and four scene maxima.

All objects should have exact allowed key sets, bounded arrays and strings, canonical integers/rationals, duplicate-key rejection and exact type checks. Scientific bounds are exact dyadics/rationals; no JSON float or native decimal parse should silently replace their mathematical meaning. Preserve fixed96 certificate endpoint and rational limits unless the final source explicitly changes and reviews them. Reference coefficient/source resolution remains fixed192 and cubic bisection count fixed128; candidate proposal remains fixed48 by54 and is untrusted.

Global invalidity has no queries, tree or solve/certificate. It still retains every prepared record, planned pair count, zero accounted/evaluated pairs and an explicit stop. This exception must not be reported as complete enumeration.

## Compact complete source evidence

The parent proposes omitting scalar zero records and retaining only nonzero outcomes. This is sound with the following interpretation.

For a complete-baseline query `(receiverID, rotor)`, the independently known source universe is every input source ID except the receiver. `entries` contains exactly the nonzero outcomes, in input-source order, with no duplicates; `zeroCount` equals universe size minus entry count. Every source absent from `entries` is an explicit claim that its guarded-model result is zero. The checker evaluates that claim individually. A positive coefficient, domain rejection, reference uncertainty, or allowed candidate refusal cannot be omitted as zero.

A fallback query uses exactly the same universe and evidence as the complete baseline. It cannot retain a partial tree traversal while claiming complete fallback unless that more complicated union is separately specified and checked; the recommended first implementation restarts complete scalar accounting for the scene.

For a screened hierarchy query, `terminals` is a left-before-right traversal frontier consisting of:

1. A zero-node terminal `{node, rule, count}`, whose effective member set is the reconstructed node members minus the receiver. The fixed rule is recomputed independently. `count` is the exact size of that set. Require a nonempty effective set so empty records cannot inflate coverage/work claims.
2. An evaluated-leaf terminal `{node, entries, zeroCount}`, where `entries` contains every nonzero result among that leaf's nonself members, in input-source order. Every omitted nonself member is an explicit scalar zero claim. `zeroCount` equals effective leaf size minus entry count. A leaf containing only self can be omitted by a frozen traversal rule and contributes no pair coverage.

Only leaves may carry evaluated-leaf terminals. A zero terminal may cover an internal node or a leaf. The checker independently expands every terminal into its effective member set, rejects overlaps and missing members, and requires the disjoint union to equal the whole nonself universe. It also replays deterministic traversal: at each visited node, try the fixed zero rules in declared order; use the first proven rule, otherwise descend or evaluate a leaf. A claimed zero may have a different reason from a member's scalar early-zero branch; only true guarded-model zero is required. Legacy per-zero reason arrays are not common outputs.

Independently checking the scalar oracle for every skipped member is useful finite qualification evidence, but does not replace verification of the node proof. Otherwise an invalid hierarchy proof could accidentally pass a small fixture. Both checks are required here.

A positive entry may retain only its fixed96 coefficient interval, with positive status/active branch. The five internal pair intervals need not become Q-current output if the independent oracle independently proves whole-domain admission/caps and coefficient containment, and source review preserves the shared internal five-interval arithmetic. Rejected and unresolved entries retain their status/branch and identity. Unknown statuses, malformed coefficients, negative intervals or unrecognized refusal codes fail. No prospective stress exception is inherited automatically: any new one must bind exact scene, receiver, rotor, source and code, preserve reference compatibility, and leave the scene unqualified.

## Tree and bound representation

Store source membership compactly as a single deterministic leaf-order permutation and contiguous node ranges. Each node records its preorder ID, half-open range, split axis or leaf marker, children or null, and exact center/axis boxes. Membership is implied by the permutation and range; do not repeat a full source-ID list at every node.

The checker rebuilds the entire tree from independently prepared centers: largest exact span; x/y/z tie order; exact selected coordinate followed by stable-ID tie order; floor(n/2) split; leaf capacity8; left-before-right preorder IDs. The contract must specify ordering within a final leaf (recommend ascending stable ID) so permutation and node ranges are unique. The query's nonzero entries still use input-source order, regardless of tree order.

Require exact agreement with the reconstructed membership, split, ranges, child partition and exact extrema, not only that reported boxes happen to enclose members. This tests the frozen deterministic tree and prevents stale/alternative trees from contaminating the work comparison. Canonical exact-rational boxes are simplest; if 16-hex extrema are used, freeze the tie rule for +0/-0 and compare their exact values while preserving raw/prepared identity separately. Node intervals for H, E and W can be recomputed from these boxes rather than emitted per query. A rule name and node reference are then sufficient compact proof witnesses.

## Global guard certificate and fallback

Independently compute exact extrema for all prepared centers C, axes A and rotor points P. Recompute, without native rounding:

- Center displacement C-C: component maxima at most257 and sum of squared component maxima at most512².
- Rotor displacement D=C-P: component maxima at most258.
- H=sum D_k*A_k: absolute maximum at most1024.
- E_k=D_k-H*A_k: sum of squared component maxima at most2048².

The saved global proof may report these boxes and exact scalar upper witnesses once per hierarchy method, or use a compact result plus the input-bound extrema; in either case the checker must recompute the quantities and the decision. Freeze the first failed inequality order. A success claim is valid only when every inequality holds. A failure does not itself reject the model. It disables every node-zero terminal and forces the complete scalar path, which can subsequently admit or reject the scene on its actual pair outcomes.

Freeze the build/guard order. A simple schedule is preparation, global proof, tree only after proof success. Then a failed proof legitimately has zero tree-build work. If a tree is built before the proof, retain its evidence and charge that work even when discarded for fallback. Do not claim a built tree or free proof based only on the final mode.

Tree arithmetic/range/resource failures need a precise policy separate from mathematically insufficient guard proof. A recoverable named failure may trigger complete fallback only if remaining resources permit and the contract predeclares it. An interrupted or exhausted fallback is an unqualified resource failure, never an implicit zero or an admitted scene. No retry of the allocated process is implied. Do not presume a global-proof-failure fixture will be model-admitted: its complete scalar outcome must be derived independently at execution.

## Exact node-zero obligations

Only a passed global guard certificate permits node zeros. Recompute each rule using the actual supplied axis intervals and prepared rotor point; never use ideal unit-axis projection identities.

1. `neighbor`: lower squared distance of node center box minus receiver center is at least neighbor².
2. `upstream`: H.upper is at most zero.
3. `down-cut`: H.lower is at least downCut.
4. `near-outside`: H.upper is strictly below minDown*Dconst, and the lower squared norm of E is at least nearRad².
5. `radial`: H.lower is at least minDown*Dconst, width lower is positive, and the lower squared norm of E is at least radCut² times width-upper squared.

Use natural exact interval products/sums and coordinate absolute minima/maxima. The global proof discharges all earlier magnitude guards, including for mixed neighbor support; earlier zero branches are harmless, but earlier rejection branches are not. Preserve strict versus non-strict boundaries exactly. Width positivity supplies positive height because the frozen spread and Dconst are positive; verify those frozen constant conditions. Do not use projection screening, cap assumptions, source ordering, or a numerical smallness threshold to skip terms in this first contract. A node containing self is allowed only when its rule proves zero for the whole node box; membership accounting then removes self exactly.

## Complete statuses and common coupled loads

Collect all nonzero outcomes before scene selection. Retain every rejection/refusal even when an earlier outcome already determines scene status. Reconstruct the same canonical complete order `(receiver input index, rotor, source input index)` for both methods. Select global preparation rejection first, then first proved pair rejection, first unresolved pair, first positive edge violating descending prepared-z/ascending-ID order, then actual positive-term resource excess, then candidate/certificate processing. Traversal order must not select the witness.

Active status supplies positive membership even when a returned coefficient lower endpoint is zero. The active count is exact; an upper estimate above a resource cap cannot prove actual excess. The finite64-drone qualification cannot exercise the2,000,000-term boundary, and must say so.

Each method independently validates complete positive coefficient membership and enclosures, exact weights, recorded candidate domain, full row contraction and defect boxes, local/global factors, root-corollary and independent-root containment, exact candidate-load identities, signed root-box/load propagation and full-returned-box normalized error bounds. World moment remains sum(offset cross actual axis)*f*x in all3 coordinates. Normalize by exact mg/4, mg and mg*R. Exact tolerance uses upper*100000000<=2^96, with sound loose certificates recorded as tolerance failures.

The independent reference solves only admitted ordered scenes, using every oracle-positive edge, fixed192 coefficient/source enclosures and fixed128 endpoint bisections; zero alpha returns exact root1. Reference uncertainty is visible and unqualified. Neither baseline nor hierarchy may serve as the oracle for the other.

Because both methods use the identical prepared-pair kernel, canonical positive summation order and common deterministic solve/certificate implementation, recommend additionally freezing exact equality of their canonical positive edge records, canonical model result/witness, solve bits and load certificate. Mode, tree, partition evidence and work counters differ. This stronger finite equivalence check is independent of the mathematical validation and is not a claim of equivalence to a historical native model. If exact certificate equality is not intended, settle that now; do not introduce a post-result numeric comparison tolerance.

## Coverage and work counters

Recompute rather than trust every reported count. At minimum retain planned pairs, accounted pairs, zero-node-covered pairs, scalar-evaluated pairs, scalar-zero pairs, positive/rejected/unresolved pairs, query count, tree nodes built and visited, rule attempts/successes, fallback use and declared attempted build/proof work. For screened globally valid scenes:

`accountedPairs = zeroNodeCoveredPairs + scalarEvaluatedPairs = 4*N*(N-1)`

`scalarEvaluatedPairs = scalarZeroPairs + positivePairs + rejectedPairs + unresolvedPairs`.

Baseline/fallback zero-node coverage is zero and scalar-evaluated count is the full planned count. Global invalidity is the explicit no-query exception. Self checks and tree visits are separate from nonself pair counts. Fixed rule order permits replay of exact attempt counts, including failed rules. Do not count covered zero sources as scalar calls or confuse a node count with its member count. These are descriptive algorithmic counts; later matched total-cost work must include preparation, guards, build, traversal, scalar pairs, solve, certificate, output and fallback.

## Recommended fixed fault controls

Freeze exact mutation definitions, first-witness selection order and count in the final contract. The following16 probes form a concrete recommendation; they may be consolidated prospectively, but none may be skipped silently after results are known. Every probe uses the same core validator without journal or baseline-document byte comparison. Select from independently derived source/reference facts, and fail control coverage when a required witness does not exist.

1. **Missing source subtree:** remove the first nonempty hierarchy terminal, leaving a witnessed uncovered source. Prefer an internal zero-node covering multiple nonself members.
2. **Duplicate source coverage:** duplicate that terminal, proving an overlap without changing its zero proof.
3. **False zero over active/rejected member:** select the first evaluated leaf containing a proven positive or rejected scalar member; replace its entire leaf terminal by a zero-node terminal with a fixed false rule. Coverage remains complete, so the failure must involve false zero/proof/model evidence rather than a missing source alone.
4. **Omitted positive leaf entry:** delete the first oracle-positive scalar entry and increase zeroCount to preserve its arithmetic identity. The omitted member is now a false zero claim, which the independent oracle must reject.
5. **Wrong tree membership:** replace a nontrivial node's member/range or swap two source IDs in the stored tree permutation while retaining the canonical tree claim. Record the independently reconstructed mismatch.
6. **Wrong tree bound:** narrow the first node bound with a strictly distinct extremal member so the emitted bound excludes that member; use an exact witnessed coordinate.
7. **Stale prepared/tree identity:** copy a prepared operand or tree from a separately declared changed-current-input scene, preserving that scene's current raw input. The mutation must actually differ; bind the witness to the changed raw/prepared value. If paired-current scenes are not declared, flip one prepared offset bit instead and name the narrower control accordingly.
8. **False global guard success:** in a scene with a recomputed failed global inequality, claim guard pass and screened mode with a node-zero terminal. Independently record the failed inequality; fallback cannot be bypassed.
9. **Incomplete fallback:** remove a nonzero singleton outcome from a fallback query and adjust zeroCount, preferably choosing a proven rejection/positive witness; if a complete-zero fallback scene is the only witness, remove a required query instead and freeze that narrower mutation.
10. **Altered positive coefficient:** replace the first coefficient with[0,0] where the independent coefficient lower bound is strictly positive. Admission/coverage and candidate roots do not substitute for coefficient containment.
11. **False affected root1:** return[1,1] for the first admitted row whose independent root upper is strictly below one.
12. **Altered candidate bits:** change one recorded candidate bit while preserving saved exact candidate-load identities. Select a candidate whose changed value remains finite and positive when feasible; the intended failure is identity inconsistency.
13. **False normalized error zero:** set one rotor error bound to zero only when the exact candidate lies strictly outside its independent root enclosure; record the positive rational normalized separating gap. A merely loose positive error bound is not enough.
14. **Missing scene:** remove a required scene.
15. **Duplicate scene:** replace one scene by another required scene's duplicate.
16. **Reordered scenes:** exchange two distinct required scenes.

The final suite should prospectively provide nonempty screening, active interaction, strict nonzero true error, a nontrivial tree extremum, and failed-global-proof/fallback witnesses. Include dense/sparse3D groups, rotated unequal-force groups, permutation and changed-current-state pairs, exact tree/rule boundary cases, and near/cap/order/global-invalid cases. Whether each intended rule fires is an execution result, not a planning claim. Unexercised rules must be listed as unqualified or explicitly required to fail qualification; do not silently weaken the requirement afterward. These controls do not empirically qualify arbitrary tree size or the positive-term resource threshold.

## Frozen-run and reporting requirements

Preserve exclusive output, append/fsync journal, source/runtime pins before and after, guardian ownership and complete process-group closure. Journal durability must be declared at completed method or completed scene granularity; do not imply partially constructed query partitions survive a crash. Source freeze/publication/independent exact-commit manifest verification precedes every scientific import, fixture generation or execution. Preserve drafts and corrections; no repair/retry after a failed allocated run.

The proposed300s kernel,600s checker,1GiB sampled process-group RSS and aggregate64MiB output/current-private-log budget with64KiB final-report reserve are prospective, not authorizations in this note. Compact evidence should avoid repeated per-query node boxes and individual zero records. The checker can emit per-method coverage/rule/refusal summaries, full admitted root/load evidence and explicit fault witnesses rather than repeat the entire scalar oracle. It must retain meaningful failures within the frozen report limit.

Report separately: source/protocol validity, method model status, global-proof result, fallback use, complete source coverage, certificate verification, exact tolerance achievement, method-equivalence result, fault-control coverage and independent reference uncertainty. Finite agreement establishes the recorded static qualification only. It does not establish wall-clock speedup, total-cost benefit, physical accuracy, dynamics, novelty or completion of the original5,000-drone goal.

## Decisions needed before implementation

Freeze the literal fresh scenes and intended witness requirements; final JSON field/type limits and coefficient-only positive payload; tree leaf-order/signed-zero conventions; guard/build/fallback order and named recoverable failures; canonical result/positive/candidate/certificate equality requirement; exact work counter definitions; control count and mutation recipe; and run/output/journal bounds. After those are settled, an independent checker can be authored without consulting candidate implementation source.
