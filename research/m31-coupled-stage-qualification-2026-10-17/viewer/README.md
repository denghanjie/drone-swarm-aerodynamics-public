# Actual-record coupled continuation viewer

Source-only implementation. No browser, import, scientific execution, build, syntax check, test or Git operation was performed by the viewer author. Parent review and bounded browser QA remain necessary before calling this viewer verified.

Open `viewer/index.html` through the existing repository server on port 8876. The server is unchanged. Three.js and OrbitControls use the existing local vendor files; there is no CDN, dependency installation, external telemetry or solver import.

## Data displayed

The pinned saved `fresh-a-t5` input supplies the common initial state, with all 64 stable IDs and all 17 binary64 state words retained. Its file identity is fixed in `app.js` and recorded in `SOURCE-PINS.json`. The viewer decodes those words for display. It reads the qualification's `browser-journal.jsonl`, `browser.json`, `check.json` and `run-attempt.json` at runtime, without writing or changing them.

Completed `step` records supply their actual `final` state words. Each branch therefore has the common initial state and at most eight recorded endpoints over 0.02 s, starting at original time 5 s. Replay holds each endpoint for 0.5 s: 200× slower than a 2.5 ms simulation step. There is no interpolation, extrapolation, invented trajectory, resimulation or magnification of branch displacement. Both branches retain the same coordinate frame and camera. Small differences can remain visually imperceptible.

The stage toggle instead selects the actual projected `nativeInput` for each saved RK stage. k2 and k3 can have the same recorded time and different states. They are intermediate solver inputs, not additional accepted trajectory samples, and stage playback is disabled. Forces toggle into stage view and display only `consumed.worldForceWords`, after validating all 64 ID/state associations against that stage. Forces are not reconstructed from rotor commands and k4 forces are not attached to accepted endpoints. Failed-stage poses may be inspected when a valid projected input was saved; incomplete consumed-load records show no arrows.

The renderer uses the prior native-fresh viewer's camera-envelope/orbit design. Bodies are enlarged 3× only for legibility; positions are unchanged. World-force arrows use a fixed display scale of 2 m/N. The grid is an explicitly labelled visual reference plane, not terrain. GPU buffers use ordinary display precision; the rendering is not an exact-arithmetic certificate.

## Missing, incomplete and failed records

Absent result files are expected before execution. The pinned initial state remains visible and the page says that no motion evidence exists. If an already verified initial state is available but later evidence has an identity, schema or loading error, the viewer falls back to that initial state and withholds motion/loads. It does not substitute another run or fill missing endpoints.

A partial journal without its saved index can be displayed as unbound partial evidence. Only complete newline-terminated JSONL records with contiguous sequence numbers are consumed; an unfinished last line or malformed record is reported and subsequent lines are excluded. Invalid states, duplicate IDs/stage identities, missing endpoint sequence entries and invalid force associations are rejected or visibly withheld. Failed stages and omitted records remain notices, not successful observations.

When the browser index is present, the journal must match its byte length and SHA-256. Where supervisor stage output identities exist, browser and checker files must match them. All available index/attempt/check source identities must agree. A positive status additionally requires the saved supervisor and all three stages to be complete, the saved browser/root closure flags, the saved checker to report complete/passed, eight endpoints and 32 completed stages per branch, and no display-integrity warnings. The viewer reports that saved outcome; it does not rerun or independently establish scientific acceptance or measured aerodynamic validity.

Each fetched file is capped at 32 MiB and a 15-second fetch timeout. Reload is manual. There is no automatic background monitor or retry of the scientific run. Raw journal/index/check/attempt links are always exposed; selected primary stages link to actual input sidecars where the index supplies them.

## Review hooks and provenance

`window.__M31_COUPLED_VIEW__` exposes UI state, available saved counts, selected arm/frame, rendering positions, arrow endpoints, camera matrices and playback state for bounded parent QA. It is an inspection hook, not evidence generated by an experiment. The viewer itself contains no verdict fixture or synthetic result file.

`SOURCE-PINS.json` records the exact local dependencies, prior viewer sources consulted/adapted, pinned initial input and the schema-source snapshots consulted during drafting. Those schema snapshots are reading provenance, not a claim that other agents' source is frozen. `VIEWER-MANIFEST.json` records the viewer-owned files and explicitly marks browser QA as not performed. Parent must refresh any affected manifest after edits.

Suggested parent QA scope: missing-output initial state; actual saved partial/failed state; both branches' available endpoints; stage/force association; 64 displayed IDs; scrub/play/pause; orbit/reset; desktop and narrow layout; no cropping at saved camera bounds; no mutation of experiment files. Do not manufacture a passing scientific result to exercise the success label.
