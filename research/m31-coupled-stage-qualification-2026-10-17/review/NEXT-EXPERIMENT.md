# Next experiment: remove native pair enumeration without changing positive arithmetic

**Recommend one native spatial-tree broad-phase experiment, measured inside a single coupled RK step on fresh large swarms.** Its question is whether skipping whole groups of interactions already excluded by F can materially reduce production cost after paying for rebuilding the index and restoring source order. Do not optimize the Python reference again, repeat the old F-versus-L browser campaign, reopen typed storage, or introduce positive-term approximation.

This is a source/provenance recommendation only. No science, imports, tests, browser, network or Git operation was performed. No values from the newly completed coupled qualification results were read or used. This note changes no frozen source or allocation.

## Why this mechanism, and what already exists

The actual native path is `native-load.cjs:query → kernel.cjs:build(...,'screen',false)`. After preparation, F still executes the entire nested `i,j` loop. Only then does it skip a pair when `max(abs(dx),abs(dy),abs(dz)) >= 4`; survivors receive the original center test and four rotor classifiers. At5,000 drones that is **24,995,000 nonself visits per query**, or99,980,000 visits for four RK stages. These are deductions from the loop bounds, not new measurements. Node/row construction, sorting, graph admission, solve, residual, materialized loads and consumption also remain payable.

The closest prior work is substantial:

The new contrast is therefore **group-level culling in the current native delivered-load pipeline**, with coupled current-stage inputs and unchanged positive arithmetic. It is a bounded implementation hypothesis, not a novelty claim.

## One deliberately narrow candidate

Build a balanced spatial tree of the current prepared center words at every stage. Reuse the existing tree policy—widest center axis, stable-ID tie break, median split, leaf capacity8—but implement numeric center min/max bounds without copying the Python oracle or its arbitrary-precision arithmetic into production. Keep IDs distinct even at coincident coordinates.

For a receiver coordinate `r[k]`, omit an entire node only if, on some axis,

`RN(node.min[k] - r[k]) >= 4`, or `RN(node.max[k] - r[k]) <= -4`.

Here RN is the same binary64 subtraction used by F. The node endpoints are actual finite source-center extrema. Rounded subtraction is monotone, so the endpoint test proves that **every member takes F's existing component-screen exit**. It needs no approximation to Math.hypot, no source aggregation, no estimated positive-mass bound and no altered cutoff. Retain F's whole-scene screen eligibility and unchanged L fallback; never suppress the invalid-before-outside behavior when that eligibility fails. A failure to prove a node irrelevant means descend or evaluate its members, not reject the scene.

Gather the surviving source indices once per receiver, remove self, and restore strictly ascending original source-index order before the unchanged F classifier runs. Preserve rotor order, every positive K/a operation, positive-cap failure order, graph edges, nominal motors, roots, residuals and all delivered-load words. Whole-node omissions contribute the same four default zero symbols as the original F exit. Do not change assembly storage, root arithmetic or the projected integration convention.

**Do not port the exact tree's down/radial rules in this first candidate.** Those rules enclose exact prepared geometry, while native decisions have a specific rounded expression order and guard precedence. Their proof obligations do not transfer by replacing Fractions with Numbers. This restriction gives the first test a short independent equivalence argument and isolates elimination of pair enumeration. Axis/rotor-aware bounds would require a distinct later decision, not an automatic rescue if this candidate loses.

Expected work is a tree rebuild plus node visits, surviving pair evaluations and per-receiver ordering. The existing tree policy sorts within each internal node; those repeated sorts must be charged rather than assuming a free or linear build. No worst-case subquadratic claim is available: a compact dense swarm can retain almost all pairs, and sorting/allocation can erase the gain. The previous grid failure makes that risk central.

## Metrics, gate and falsification

Record, per stage and per case: original logical pair count; tree build time/node count; visited nodes; wholly omitted nonself pairs; gathered/sorted candidates; center and rotor calls; positive terms; ordering time; build/admission/solve/residual/load/consumption time; complete native-query time; common controller/projection/integration cost; byte volume and honestly scoped memory observations. Count actual executed work separately from logical coverage. H0 measures overhead; F/H measures practical benefit.

Propose a simple useful-result gate: all correctness/coverage controls pass; at each fresh5,000 case H's sum of four complete query times is at most0.80 times F's, with fewer explicitly visited nonself pairs. Freeze this engineering threshold before measurement. Show every stage ratio, H0 cost, the1,000-drone result and absolute one-step accounting; four stages of one trajectory are dependent observations, not four independent replications. Total diagnostic wall time includes all three arms and validation; do not advertise it, or a subtraction of it, as production frame time. H's four query times alone are a lower bound on standalone step cost; the separately clocked common work and a future standalone run remain necessary. Production affordability must ultimately meet the2.5ms step budget, not merely a relative improvement.

Fixed failure controls must include all-axis node-face equality/adjacent words around±4, strict center-radius boundaries, duplicated positions with different IDs, permuted IDs, a compact all-near scene, sparse translated scenes, the existing span-eligibility boundary and its fallback, invalid far centers, unsupported near-field/cap/order cases, missing/duplicated candidate IDs and deliberately false whole-node culls. Inspect exact coverage and positive order, not just a checksum. No geometry branch may become “successful zero” merely because it was omitted.

If H reduces visits but misses the cost gate, close this implementation as an overhead-dominated negative result; do not respond with another leaf-size or storage sweep. If it cannot preserve guard/ordering semantics, reject the source design before timing. If dense/admitted stages retain almost all candidates, the zero-only mechanism has little available work to remove; a future decision would need a different formulation with its own approximation/physical-error contract. If H passes, the next gate is a longer coupled5,000 continuation that spans a controller update, with separately budgeted trajectory/admission checks—not an immediate real-time or physical-validity claim.
