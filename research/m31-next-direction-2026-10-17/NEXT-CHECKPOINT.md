# Next checkpoint: admit evidence before comparing physical models

The fresh numerical experiment is complete. No further execution is authorized by this planning note. Its purpose is to make the next restart concrete and prevent another cycle of redundant timing or ever-smaller arithmetic tolerances.

**First priority: determine whether the public flight records can support a fair physical test.** The inspected CF50 CSV is accessible, but not a validated force label. Before scoring any model, freeze a small complete flight group (both vehicles and both runs, rather than selecting individual favorable frames), its immutable source identities, a private storage cap and a data-only audit plan. Read the authors' preprocessing and calibration source as text, establish the correspondence with the paper/version, then check time units and synchronization, quaternion/coordinate conventions, acceleration provenance, mass/actuator calibration and delay. Derive residual labels only after these prerequisites are resolved. Preserve unavailable or ambiguous fields; no tuning against the eventual held-out flight. Public aggregate reporting should retain data provenance without copying unlicensed source/data into this repository.

Admission is allowed to conclude that these records are unsuitable or insufficient. A calibration fit score in a text file is not an independent validation set. Firmware motor-force fields must not be relabeled measured aerodynamic thrust. A five-second synthetic Boids run is not a replacement for physical labels. If a valid evaluation is possible, compare baseline and velocity/multi-neighbor variants on untouched complete flights, with uncertainty and negative cases retained. Do not assume that a published network or our27g wake law transfers to these vehicles.

**Second priority: make strict larger-state numerical checking tractable.** The source-only bridge note identifies reusable exact hierarchy bounds, but the current oracle still evaluates every pair first. A tree-first independent dispatcher must prove complete disjoint coverage, preserve invalid-input precedence and scalar fallback, and pass a fixed small-corpus/corruption test before any reference-cap change. Follow review/EXACT-BRIDGE-FEASIBILITY.md; its tentative24-scene plan is not yet an executable allocation. Dense worst cases remain quadratic. Existing large Chrome screening times already leave a substantial gap to an interactive coupled simulation.
