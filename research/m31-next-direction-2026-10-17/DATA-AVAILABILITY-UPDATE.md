# Follow-up: public measurement files are present

The README's Box instructions are incomplete evidence about present availability. A subsequent fixed GitHub tree query found public data blobs directly in the repository. This updates the initial README-only access assessment; it does not validate the data or resolve licensing.

The inspected immutable data tree is `6c1e0bcfbc55e5739307accbb68b6985adb11510`:1092 entries, untruncated, with aggregate declared blob size1,617,948,483bytes. This is metadata, not a bulk download. Root-directory inspection found no top-level license file; nested licensing and permitted reuse are not established by this limited check. No third-party raw data, code or model weights are being republished in our repository.

For schema inspection only, retrieved one prospectively named file from the visible first small/small collection: `data/training/datacollection19_12_11_2019/random_walk_small_small/cf50_04.csv`. Its Git blob is `c051cf74a9ae9eeedb17594466b5a95ddaecbfb0`; decoded size4,826,012bytes; SHA256 `63a548f8f87067693f816ee60f6e3cf880ab106637c9f9c2ab9aeeebcdffc12e`. The downloaded bytes independently match Git's blob identity. It has a header plus6369data lines. No flight values were scored, fitted or compared with our simulator. One file does not establish dataset completeness, synchronization or appropriate held-out splits.

The header advertises30columns: time in milliseconds; position, velocity and acceleration; xyzw quaternion; four force fields; four PWM fields; battery voltage; desired thrust; torque; angular rate. Reading the collection's conversion source as text revealed that `u1[N]` through `u4[N]` come from firmware `motor.f1` through `motor.f4`. They are **not demonstrated direct rotor load-cell measurements**. The source also computes a PWM thrust formula that is not used for those CSV columns. Thus treating these columns as independent measured aerodynamic thrust would be unjustified.

The collection README (blob `45d06ca68f4ec74c939d9fadfc7184c594769237`) identifies CF50/CF51 as unmodified Crazyflie2.1 vehicles, and CF101/CF102 as larger Parrot-frame variants. Its default calibration file and conversion source are readable public blobs. The same directory lists the companion `cf51_04.csv` (blob `2041927f90fbde571d778997437c00badc9b626d`,4,789,240bytes), plus a second run for both vehicles. Only the first CF50 file was downloaded; no pairing/alignment or inference was performed. Naming suggests a pair; timestamp/experiment alignment still needs checking.

**Useful next step:** a separately frozen data-admission and label-reconstruction audit, before model fitting. Verify clocks, units, quaternion convention, sensor/estimator provenance, vehicle mass/actuation calibration and delay, matched-neighbor trajectories, environment/ground effects, and flight-level data splits. Derive any residual force with explicit uncertainty and distinguish it from directly measured force. Then compare a baseline with velocity/multi-neighbor extensions on untouched flights. This offers a physical-evidence path alongside computational reference work, but no new physical validation or novel result has been achieved here.

All repository instructions were treated as source material. No training script, conversion script, pickle/weight loader, rclone command, external contact or account authorization was executed. Source bytes remain private scratch; only these factual identities/paraphrases are public.
