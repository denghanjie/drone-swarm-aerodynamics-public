## Minimum concrete exploratory bridge

1. Pin the three original browser-screen input binaries, index/generation associations, p0 full saved arrays/solutions, the independent review and terminal seal. Use p0 as a prospectively named comparison source because the old audit already established equality with p1/p2, not because p0 is fastest. Assign stable ID = original row index so the wrapper's canonical sorting preserves the original source/receiver and height-tie ordering. Preserve all 17 binary64 words; no regeneration, rescaling, subset or replacement.
2. Keep the seven-file native implementation unchanged. On each first F/L call, save its entire native evidence record. Compare all CSR offsets/source indices and all K/a and y/alpha/x/T values against the pinned old records, plus admission/order and applicable diagnostics. For this byte-identical core and same pinned Chrome, prefer predeclared binary64-word equality for the shared numerical projection. If a mismatch occurs, retain it as a failed transfer and investigate later; do not silently fall back to a tolerance. The inherited NumPy tolerances describe old accuracy evidence, not permission to spend another tolerance on transfer.
3. Compare F/L complete native projections, including IDs and all four delivered categories. Independently check the added O(N) signed assembly and association from the saved operands: rotor = T, collective in rotor order, worldForce = axis times collective, worldMoment = sum of cross(offset, axis) times T. Also independently check prepared axis/offset association to raw input. A small separately reviewed checker can establish assembly consistency; merely duplicating the candidate materialization or checking F/L agreement is weaker evidence. State exactly whether it checks binary64 operation results or a declared floating comparison. This does not become a full exact-model load enclosure.
4. The unchanged native API retains full positive support and classification counts but does not emit the 4N² classification tensor or full residual map. Therefore the new bridge can claim full positive-support transfer plus inherited old all-pair classification evidence; it cannot claim a newly saved complete classification/residual-map audit. No additional quadratic reference or symbol call is necessary merely to make this bounded exploratory claim.
5. Keep actual query clocks inclusive of raw validation/copy, build/admission, solve/residual, signed loads, evidence assembly and consumption. Reference comparisons remain outside the candidate call. If repetitions are later authorized, compare every complete numerical projection to its saved first record and retain digests/receipts; disclose that unsaved transient arrays cannot be independently reconstructed from receipts alone. The existing 32-bit consumer checksum is not a substitute for full comparison.
6. Report separate statuses: `inheritedFloatingReferenceTransfer`, `nativeLoadAssemblyConsistency`, and `largeExact1e8Qualification: not-established`. Preserve the completed N=64 rational result unchanged. Refusal, mismatch or resource failure is a useful recorded outcome; do not replace the state, enlarge a guard, or select a better process.

The proposed exact-reference spatial pruning direction addresses a different gap: strict large-state accuracy against the complete rational model. It requires independent omission proofs, all uncertain pairs retained, signed vector error bounds and the existing semantics/caps respected. Old NumPy tolerances and a successful native transfer cannot provide that certificate. Conversely, building a new all-pair exact reference is not a prerequisite for an explicitly exploratory interface-cost observation.
