# Bounded spatial wake omission campaign (pre-run plan)

The sparse, read-only `snapshot/` checkout includes the original eight-step framework (`outputs/research-roadmap.md`), current mean-wake coupling, rigid-body model, genuine local 3D Boids, and local Three.js. ## Hypothesis and scientific scope

At identical prescribed states, a conservative, accumulated inflow-error budget can omit geometrically weak source-to-receiver interactions, preserve four-rotor forces and roll/pitch moments within declared numerical tolerances, and reduce CPU aerodynamic evaluation time versus an allocation-matched zero-budget implementation. A negative speed result is useful and retained. This is an approximation to an unvalidated, finite-support mean-field model with constant isolated-hover source strength, not physical validation, turbulence resolution or a safe-flight claim.

The original eight steps remain the framework: (1) freeze experiment, (2) preserve the existing drone mechanics, (3) verify two-drone interaction equivalence, (4) bound overlapping omissions, (5) conditionally test genuine local 3D Boids, (6) measure CPU acceleration, (7) scale only 16→50→100→200 here, (8) report accuracy/cost and failures. No step is declared scientifically complete by this campaign.

## Candidate and controls

The primary law remains `sum-rotor`, all four receiver rotors, fixed nominal receiver response, existing support/fades (2.5 m downstream; 3 half-widths radially), 3 m broad-phase search, and 10 ms aerodynamic refresh. Controller, mechanics and source strength are unchanged. Original module is the independent software reference. A scalar, allocation-reduced equivalent module at budget zero is the matched primary comparator. Candidate uses exactly this module plus omission decisions, so comparison does not credit allocation optimization as pruning.

For each receiver/source pair, geometry at receiver center and the rotor-offset norm R bounds all four rotor points. Downstream lies in [d−R,d+R]; radial distance is at least max(0,r−R). For a valid far-field point, centerline speed is bounded using the smallest possible downstream, and the radial profile denominator using the largest possible half-width. Fades and axis cosine are at most one. The resulting positive upper bound applies to each rotor. An interaction is skipped only if adding this bound to the receiver's running omitted-inflow budget does not exceed epsilon. Source order remains ascending and exact retained contributions use the original equation. This is a conservative per-receiver sum of omitted influences, not independent per-source thresholding.

All inputs are validated. Tilt and near-wake checks run independently of the omission budget; no unsupported pair may disappear. Receiver response and nominal yaw-torque convention remain unchanged. Reduced receiver sampling and adaptive refresh are excluded from this primary experiment and documented as separate future controls. Support expansion/shrink sensitivity and refresh refinements are separate diagnostics, never silently mixed into the baseline.

## Frozen measurements and acceptance gates

1. Unit/equivalence gate: original versus zero-budget fields ≤1e−12 m/s absolute; force ≤1e−12 N and moment ≤1e−13 N m. Exact same domain outcomes on valid, boundary and deliberately invalid cases. Candidate positive-budget field errors must be nonnegative (up to rounding) and ≤its recorded accumulated bound +1e−12, independently for all four rotors. Reordered-state permutation checks and many-weak-source tests are required.
2. Approximation budget sweep epsilon = 0.002, 0.01 and 0.04 m/s. Each run retains per-rotor inflow, force-vector error, roll/pitch moment-vector error and bound, absolute maximum/RMS/p95, worst-case configuration, contribution counts, domain failures and NaN checks. Bound from receiver law: |dT/dU|≤sqrt(2 rho A Tnominal)/3. Force bound is sum of rotor thrust bounds; moment-vector bound ≤sqrt(2) a times that sum. No unstable relative error near zero.
3. Frozen approximation gate: maximum force error ≤0.005 m g and maximum roll/pitch moment-vector error ≤0.0075 m g a, plus accumulated-inflow bound compliance and zero hidden domain exits. These are engineering tolerances against the declared numerical model, not measured accuracy. They conservatively match epsilon 0.04 with nominal thrusts up to the existing 2.25×hover motor cap. All thresholds must pass, rather than trading torque away for force.
4. Timing gate: serial same-host warm runs; exact same frozen states and four-rotor receiver loads; report setup/field/receiver/end-to-end scope separately, individual paired repetitions and bootstrap interval. A useful provisional speed win requires ≥10% median field-time saving and a paired 95% bootstrap interval entirely below a candidate/reference time ratio of 1.0 on at least two held-out N≥100 scenario families, with correctness gate passed. Small-N regressions and dense-case failures remain visible. This threshold avoids claiming negligible noisy changes as a contribution; no hardware-generalization claim.
5. Closed-loop gate, only after correctness and a timing slot: a small, separately labeled Boids comparison may run even when pruning is too slow, as a bounded numerical-sensitivity diagnostic. Use the existing local separation/alignment/cohesion plus shared route and wall-priority controller, no individual scripted tracks or controller tuning. Seeds and starting states identical; dt 2.5 ms, controller 10 ms, field 10 ms. Begin 16 agents for 1 s; only if valid extend to ≤50 agents for ≤5 s. Save recorded full states and held fields. Any domain exit/contact/NaN stops that member and remains a failure. Compare 1.25 ms physics and 5 ms refresh separately on one small case; no trajectory-accuracy claim if either differs by >1 cm or reference itself fails.

## Scenarios and untouched evaluation

Development seeds 3301/3302; held-out seeds 3391/3392 are not used to tune algorithm or thresholds. Prescribed-motion force benchmarks (explicitly not called a flock) cover centered/offset two-drone wake, staggered 3D clouds, sparse expanding clouds at 0.75 m nominal spacing, dense clouds at 0.40 m, and allowed tilted axes up to 15 degrees. Geometry varies smoothly over a 1 s window sampled at 10 ms; all variants see identical states. Deliberate near-field, >20-degree tilt and support-boundary cases are unit/stress diagnostics. Independent adversarial tests are reported separately. Source support truncation is a model assumption; exact finite-support baseline is not infinite-domain truth.

## Resource caps, stages and stop conditions

- Before independent plan review: source inspection and tiny deterministic unit checks only, no timing experiment or broad simulation.
- After review gate approval: smoke ≤16 agents, ≤10 snapshots; then correctness matrix up to N=200. Timing runs require exclusive, serialized measurement windows.
- One process/CPU task at a time for measurements; no parallel benchmarks. Timing wall budget ≤30 minutes campaign-wide; initial requested slot ≤5 minutes. No job >60 seconds without an explicit per-job timeout, no runaway retries. N≤200; generated artifacts ≤2 GB; source checkout currently about 74 MB and evidence archive untouched.
- Stop on bound violation, nonfinite result, reference mismatch, hidden domain discrepancy or insufficient evidence for a claimed gate. Preserve failure inputs and logs; diagnose before any retry. Stop scaling if predicted remaining cost violates caps or no speed benefit appears at N=100/200. Do not tune toward an attractive movie or loosen criteria after seeing outcomes.
- Local artifact only: self-contained Three.js replay with controls, model limitations and links to saved raw records/configurations/seeds/hashes; no published hosting. Demo trajectories must be actual retained Boids records, never prescribed benchmark motion mislabeled as flocking. Tiny records are sufficient for a truthful useful demo.

## Deliverables

Source inventory and hashes, immutable plan plus append-only amendments, inspected reference provenance, candidate and tests, scenario configs, raw results (including failures), checkpoint reports, comparison summary, reproducible local commands, and self-contained 3D evidence viewer. CPU numerical throughput and replay rendering are reported separately. Physical receiver calibration, independent wake validation, browser/WebGPU coupled performance and 5,000-drone feasibility remain open.
