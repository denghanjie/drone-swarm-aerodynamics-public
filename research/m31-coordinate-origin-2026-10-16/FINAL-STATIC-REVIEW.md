## Findings resolved before exposure

1. **Control output reuse could hide unwritten records.** The browser initially reused the same control-output storage for A/B/C without clearing it. Since identities and most expectations match, an unwritten later record could retain a valid earlier one. Verified fix: the output has `COPY_DST`, a command-encoder clear precedes each control dispatch, and three clears totaling 6,240 bytes are counted and reconciled.

2. **Aggregate reference reservations occurred after evaluation.** The driver initially charged `hostReferencePasses` after `evaluateSelected`. Verified fix: every pass reservation precedes the call. The host also now reserves translated/Q1 prepared copies before the `.slice()` operations.

3. **Recorded browser faults did not stop later cells promptly.** The driver initially checked page/console faults only after initialization and at the end. Verified fix: `guard` checks recorded faults; charged operations, assessments, dispatches and cell-preparation/continuation boundaries invoke that guard. A shared browser fault cannot be treated as an ordinary numerical negative.

4. **The output cap did not encompass all terminal files.** The raw writer cap initially omitted duplicated result output, stdout/stderr, lock and budget files outside `raw/`. Verified fix: a separately stated 32 MiB result cap covers those files, with periodic external polling and final budget-record byte reconciliation. The 256 MiB raw cap includes an 8 MiB failure reserve. The protocol explicitly calls polling an overshoot detector, not a filesystem quota. Private process/exception provenance is separately retained and disclosed.

5. **Missing signed-integer encoder API.** The driver calls `h.encodeI32` after fresh generation, but the initial host export lacked that function. Verified fix: the explicit little-endian signed-integer encoder is defined and exported. The driver also saves the generated receiver-ID array, reflected in the final 116-file typed inventory.

6. **Public failure strings could disclose private process details.** Playwright launch errors and Python launch exceptions can contain absolute paths, profile arguments and process identifiers. Verified fix: caught driver errors have bounded first-line public redactions; complete exception strings and private ownership details are retained privately with a receipt. The supervisor publishes launch-error type only. The preparation disclosure explicitly requires privacy inspection of stdout/stderr before publication because top-level import/launcher failures can precede the sanitizer. Successful runtime pin records use public-safe labels.

7. **The kernel's upload example did not match the driver.** The driver uploads offsets and IDs for every cell, while an early kernel-contract example counted them once. Verified fix: the contract and both resource ledgers use the actual six-cell upload plan, including per-cell offsets/IDs and separately counted control clears.

8. **The seed rule needed explicit historical-seed handling.** The accepted challenge forbids historical seed 608897; the initial generator accepted every uint32 seed. Verified fix: that seed is rejected before random draws, without replacement. Source, host contract and protocol agree. The preparation disclosure clarifies that documented escaped newlines denote actual LF bytes in the seed input.

9. **Reference-row structural qualification was too permissive.** The initial R/Q assessment checked the term/status/term-validity/code range but did not independently check identity, metadata code agreement, exact masks, complete scalar finite/placeholder rules, or term-array agreement with the scalar payload. Verified fix: a shared row validator checks those properties and typed array shapes. Completed sum metadata/nonfinite corruption is an integrity failure. The final config reserves 480,000 reference rows and 8,640,000 reference numeric-field checks across two R and four Q passes. These are saved-array checks, not added geometry.

10. **Diagnostic integrity results and observed GPU costs needed enforcement.** Verified fixes: diagnostic contrasts now require `integrityPass`, while their numerical values remain diagnostic. The driver computes exact expected buffer creations, allocated/uploaded/cleared/readback bytes, live/peak payload, output slots, launched lanes and padding from executed cells and reducers, compares every reported cost, and checks the adopted maxima.

## Static findings supporting the intended design
