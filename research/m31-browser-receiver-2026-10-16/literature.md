## Consequences for this model

The existing source uses a rational radial profile, polynomial fades, norms/divisions, quaternion rotation, nonnegative source sums and the receiver equation

`g(x; alpha) = x³ + alpha*x − 1`, `alpha = U/vi0`, `f = f0*x`.

The unchanged CPU receiver starts `x=min(1,1/alpha)`, takes at most 12 Newton iterations and returns nominal thrust directly at zero inflow. It does not use a general cubic-root library. Porting its actual multiplication/division expressions is a smaller question than changing to a closed-form cubic or `pow` implementation. The existing near-wake, tilt, center-distance and support predicates must remain visible outcomes, including expected rejection.

Three distinctions are essential:

1. **Original values versus stored f32 values.** A comparison only against a reference whose inputs were already rounded can hide most of the input error. Preserve both. Quantize constants as well as coordinates; record their exact bits. Quaternion component rounding generally does not preserve the current 1e-10 unit-norm gate. Reject/retain that defect explicitly; silently renormalizing would introduce another intervention.
2. **Term error versus sum error.** This model's inflow terms are nonnegative, so the exact sum has no cancellation when positive. That helps summation conditioning, but branch changes and errors in each term remain. Roll/pitch moments are differences of rotor thrusts and can have large relative error near zero; use absolute component errors there. A fixed source-ID loop is the simplest first implementation. Any tree or subgroup reduction is a later, separately compared arithmetic change. H/O are rationale, not certificates for an unexamined shader.
3. **Residual versus root accuracy.** Preserve the shader's x, alpha, f, iteration count and stagnation/status flags. Evaluate its residual again in host binary64 at the saved shader alpha, and compare x with an independent binary64 bisection root for that same alpha. Separately evaluate the root for the original U/constants. A tiny or zero shader residual can result from its own rounding. It does not establish a tight root bracket or repair input error.

For the real equation, alpha≥0 gives one root in (0,1]; implicit differentiation gives `dx/dalpha = −x/(3*x²+alpha)`. This desk derivation helps attribute input sensitivity; it is not a WGSL error bound. Likewise, f32 spacing in [2^-4,2^-3), containing nominal f0=0.0662175 N, is 2^-27 N. Hence a general f32 output cannot inherit the existing 1e-12 N rotor-thrust guarantee. This is a representation argument, not a measured failure count. Existing binary64 qualification stays intact; any new engineering tolerance must be separately justified and frozen before shader outputs are exposed.

## Narrow experiment proposed for later selection

Use a single diagnostic suite, one authorized invocation and **no timing comparison**. A compact prospective ceiling is 32 scalar receiver probes, 32 single-pair/rotor probes, and eight receivers (all four rotors) from one already saved N=5,000 snapshot. Freeze snapshot/time/receiver IDs and probe values before running; disclosed historical inputs are development evidence, not fresh holdouts. The scalar set should include zero inflow and fixed representatives from the saved inflow range. The pair set should cover both sides and equality at center-neighbor, upstream, near-domain, downstream-cutoff, radial-support, projection and tilt decisions. Do not select easier replacements after observing failures.

For the eight receivers, enumerate all source IDs directly and apply the same strict center-radius and self-exclusion predicates; this avoids introducing a new grid. At most `8*4*4999 + 32 = 160,000` pair/rotor reservations per arithmetic path result. Three paths therefore reserve at most 480,000 such visits, before separately budgeted source-geometry preparation, controls and root iterations. This is a static work-count proposal, not runtime prediction. Exact wall/storage/root caps and failure retention must be reviewed with the final layout before any launch.

Freeze these three paths:

| Path | Purpose |
|---|---|
| R64 | Independent binary64 equations on the original input and constants; retains original domain/API verdicts. |
| Q64 | The same independent mathematical formulas applied in binary64 to exactly the f32-encoded inputs/constants; a representation diagnostic with separately recorded quaternion defect/domain status, not a requalified production API. |
| G32 | Actual WGSL f32 geometry, ordered source sum, receiver solve and load assembly on those exact encoded bytes. |

R64↔Q64 measures the effect of input representation; Q64↔G32 measures shader arithmetic/implementation effects on matched bytes; R64↔G32 is the delivered total discrepancy. Comparing these is not permission to substitute Q64 for R64. If the input representation violates the chosen API contract, stop before dependent work and report that outcome. Precomputed axes/rotor points could instead define a smaller kernel-only probe, but would leave quaternion rotation and end-to-end geometry explicitly untested.

Record every probed classification, contribution, per-rotor inflow/thrust, body/world load, and original/encoded input bytes. Same-pass per-source output for these eight receivers makes lost/gained support observable without a hidden second GPU field evaluation. Use explicit integer status records for rejected input/domain conditions. Bound finite operands and denominators before arithmetic; a final nonfinite check alone cannot diagnose every indeterminate intermediate permitted by W.

Keep the receiver's 12-iteration ceiling and initial guess, freeze any stopping-rule translation, and report stagnation instead of silently substituting a solver or clamping outputs. Host bisection remains the independent root diagnostic. Root residuals and power identities evaluated from saved scalars remain numerical diagnostics, not formally directed-rounding interval certificates. A bitwise-equal result is not required across backends; finite/range checks, exact expected domain verdicts and predeclared absolute/relative numerical budgets are. Boundary mismatches must be retained and fail the relevant classification claim, even when resulting force error is small.

The next protocol still needs an explicit output-error allocation and decision rule. If unchanged binary64 gates are mandatory, perform a saved-data/output-representability screen first and stop on incompatibility; do not weaken them after failure. If a separate f32 engineering allowance is selected, preserve both old-gate and new-gate outcomes. The old positive-omission allowance does not automatically become the f32 allowance. A diagnostic pass would justify only these static probes on the observed browser/backend. It would not establish full-flock correctness, speed, cross-adapter reproducibility, physical validity or trajectories.

No installations, shader compilation, GPU tests, field evaluations, benchmarks, new agents or scientific module imports were performed for this desk review. Existing budgets remain closed; the proposal is not selected.
