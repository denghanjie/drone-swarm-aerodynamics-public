# Prospective total-cost test of the verified zero filter

The previous finite scalar-filter correctness checkpoint is closed and published at c1afe65dc2a458086b8993e50a940c479fb08f9b. This package asks a different question on fresh, frozen scenes. No numerical import, probe, warmup, fixture execution, reference execution or candidate run is permitted before independent source review, freeze, public push and exact public verification. Source inspection, literal serialization, hashing, AST and syntax checks are permitted. Historical allocations remain closed.

## Question

Does adding the unchanged conservative binary64 zero filter reduce total calculation time compared with the same exact spatial hierarchy without that filter, while retaining the identical scientific result and all normalized load tolerances?

The filter can cheaply prove selected zero branches; uncertain cases use the unchanged exact scalar calculation. Published interval filtering is prior work, not our algorithmic novelty claim. Previous finite verification found five direct zeros among 19 selected zero cases; that is not a typical hit rate or cost prediction. The exact hierarchy already removes many pairs, so filter setup and tests may cost more than they save.

## Methods and unchanged model

`hierarchy` is the unfiltered baseline. `filtered` uses the same admission, prepared binary64 words, exact rational geometry, global guard, tree construction/traversal, positive scalar coefficients, ordered admissibility, candidate load solver, certificate and error tolerances. Both pay those operations on every call. Only filtered constructs additional singleton interval geometry and constant words, inside its timed preparation, then applies the published classifier to scalar pairs left by the hierarchy. Uncertain results call the identical exact query. No cache crosses method calls; no approximate positive coefficient is introduced.

Both scan/leaf records include `filterZeros`, empty in the baseline and sorted by input source index in the candidate. The extra list records each zero's exact branch. Additional counters distinguish prepared fast objects, filter attempts, proven zeros and exact scalar calls. Saving these lists is charged inside the timed method call. The independent checker validates each fast zero against exact branch-priority semantics, all implicit zeros, all positive coefficients, original complete pair coverage and load certificates. It does not re-execute the candidate classifier. Metadata projection into the unchanged inherited semantic validator must first validate the new metadata and cannot discard an unchecked mathematical claim.

Both methods retain all four normalized load-error thresholds of 1e-8. Method agreement alone never replaces independent validation. Every scene must be admitted and certified, with zero baseline errors and no unresolved/reference-undecidable outcome; otherwise scientific qualification fails. Numerical correctness under this model is separate from the physical model's unresolved validation.

## Prospective decision rule

Scientific qualification and practical benefit are reported separately. For each scene report every paired filtered/hierarchy ratio, its exact median, ratio of method medians and number of strict filtered wins. The primary practical gate requires **all three dense scenes** to have median paired filtered/hierarchy <= 0.9 and at least three wins out of four measured pairs. Sparse results are contextual and never pooled with dense scenes to rescue this gate. No confidence interval or statistical population inference is allocated.

If scientific qualification succeeds and this practical gate passes, advance toward browser and moving-flock integration using a fresh protocol. If the gate fails, retain the negative/inconclusive cost result and consider exact shared-work reuse or batching; do not tune against these six cases. The quantitative gate is a research resource decision, not a proof of general speedup. Even success does not demonstrate real-time 5,000-drone operation.
