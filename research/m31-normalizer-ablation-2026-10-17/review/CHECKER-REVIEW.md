# Saved-evidence checker source review

Status: source preparation and AST validation only. No scientific module import, candidate call, reference evaluation, mutation evaluation, generation or timing run occurred during this work. Numerical execution remains gated by complete independent source review, public source verification and the separately supervised sole allocation before the fixed cutoff.

The checker CLI is `PYTHON -I -B PACKAGE/source/check.py PACKAGE`. It writes `results/check.json` and twelve files under `results/reference/`: the four fixed controls, six scheduled states, `lifetime-a` and `lifetime-b`. Each input has one independently reconstructed reference and both arm validation evidence. Output files are exclusive; the report has a 2 MiB cap and references share the remaining 64 MiB checker allocation, with a 32 MiB per-file cap.

## Trust boundary

Before importing any numerical reference, the checker verifies the complete new source manifest, fixed checker/helper hashes, all twelve unchanged baseline module hashes, runtime executable pin, public-source receipt, source identity, exclusive kernel/checker attempts and publication/attempt/cutoff chronology. It requires successful closed kernel supervision, including process-group absence and final source/runtime checks. The new manifest must contain the old moving checker, pair reference, semantic reference and qualification driver paths.

Only four historical Python modules are loaded, after exact buffer checks. The frozen moving checker supplies preparation, complete-pair/reference reconstruction, assembly/zero/certificate validation, generation provenance, nontriviality and metadata mutation functions. The frozen qualification driver supplies its corrected 21-control table and method mutations. Its intended `frozen` dependency handle is assigned to the exactly pinned moving checker; no historical function is replaced and no historical main function is called. Neither JavaScript candidate nor generator is imported by the checker. Old files remain unchanged.

The bootstrap's strict JSON, canonical encoding, path, hashing and exclusive-writing helpers are copied as source from the moving checker. Scientific equality is recursive and type-sensitive. JSON duplicate keys, nonfinite tokens, unsafe integers, scientific decimal tokens, noncanonical artifacts and path/symlink escapes are rejected.

## Targeted controls and decisions

Each arm receives all 21 qualified corruption recipes, including the repaired semantic false-zero target and separate counter-interception regression. Metadata, fixed-input and capture mutations retain their intended failure families; the full semantic wrapper validates method mutations. Independent pristine copies prevent cumulative corruption.

Six additional mutations target wrong source beta, wrong receiver nu, wrong rotor nu, actual lifetime input binding, swallowed qualified exceptions and swallowed unexpected errors. The state-binding mutation flips one rotor-force word in a cloned lifetime-B call and invokes the same pure `lifetime_state_binding` predicate used for the original records. It must reach `lifetime-state-binding`, rather than merely an unrelated file digest or trace-label failure. The five direct mutations target their precise normalization/status/error checks. There are 48 targeted mutations in total; an arbitrary rejection does not count as success.

`equivalencePassed`, `recordIntegrityPassed`, `admissionPassed` and `benefitPassed` are separate report flags. Benefit uses exact rational ratios of saved complete worker wall times: median of four candidate/baseline ratios at most 9/10 and at least three strict wins in every state. All paired times and ratios are retained. Method-return time is secondary; the checker asserts it fits inside the recorded spawn-to-exit wall duration. No per-arm CPU/RSS, persistent-process, browser or general speed claim is made. `passed` requires all four gates; a failed performance gate preserves an equality result without relabeling the experiment successful.

Final checks rehash every consumed evidence file, source closure, manifest and Python executable. Any missing record, mismatch, unavailable intended witness, scheduled refusal or reference-undecidability, resource violation or programming error fails closed and preserves the saved kernel evidence. Partial checker output is retained; no retry is authorized.
