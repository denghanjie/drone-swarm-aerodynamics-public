# Browser confirmation checkpoint

This prospective checkpoint asks whether the previously measured interaction-query speedup repeats in actual Chrome on three new swarm states and three fresh browser processes. Its protocol and code must be published and independently verified before its single scientific allocation.

Read [PROTOCOL.md](PROTOCOL.md), [CLAIM-EVIDENCE-LEDGER.md](CLAIM-EVIDENCE-LEDGER.md), [LITERATURE-EXPERIMENT-LEDGER.md](LITERATURE-EXPERIMENT-LEDGER.md) and [PHYSICS-BOUNDARIES.md](PHYSICS-BOUNDARIES.md). All historical experiments remain closed.

The source uses existing Node/Python/NumPy/Chrome/Playwright installations; no installation or paid resource is authorized. runtime.json records the admitted identities without private filesystem paths. Set NODE_PATH to the installed package directory, set PYTHONDONTWRITEBYTECODE=1 to avoid local bytecode cache files, and use the matching Node/Python binaries. Keep localhost8876 available for the existing research viewer; the benchmark page itself serves exact frozen bytes through the automation route.

After exact source publication/independent verification, commands are:

```text
PYTHON source/run.py generation NODE SOURCE_MANIFEST_SHA SOURCE_COMMIT
PYTHON source/run.py candidate NODE SOURCE_MANIFEST_SHA SOURCE_COMMIT
PYTHON source/run.py review PYTHON SOURCE_MANIFEST_SHA SOURCE_COMMIT
PYTHON source/seal.py SOURCE_MANIFEST_SHA SOURCE_COMMIT
```

Run each once, serially, from this package or with absolute script paths. The package root is inferred by the supervisor. Generation failure prevents candidate launch. A closed failed candidate may be inspected by the sole saved reviewer; missing evidence cannot qualify. Do not remove locks, overwrite outputs, retry a consumed invocation or interpret example command syntax as permission to rerun a historical record. Reproduction must use a separate declared copy/allocation and preserve the original evidence.

Source publication receipt source-publication.json is created only after independent remote-byte verification. Browser result folders are runs/p0/results through runs/p2/results with actual perprocess closure.json records. The final decision is results/qualification.json, never a browser banner or in-child audit alone.

A result summary and actual-record Three.js replay will accompany the sealed result. The new trajectories are5s airflow-off local3D Boids; final-state aerodynamic queries are not coupled into those poses. The original5000-drone live simulation/physical/publication objective remains open.
