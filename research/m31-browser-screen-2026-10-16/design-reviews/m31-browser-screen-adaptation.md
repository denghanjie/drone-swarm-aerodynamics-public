## Small transparent wrapper

Generate one deterministic browser bundle whose four static factories have this structural form: `function(module,exports,require,Buffer){` followed by the exact original source bytes, followed by a separately added closing delimiter. Wrapper separators belong to the wrapper and must not replace original bytes. Preserve directive placement. Use a fixed allowlist for the four exact relative CJS IDs and a normal per-page CommonJS cache: create and cache `{exports:{}}` before calling its factory, pass `module.exports` as `exports`, then return the resulting `module.exports`. Reject every unknown ID. Do not add network resolution or a general polyfill loader.

For the four inspected numerical modules, a local compatibility allocation equivalent to `alloc(size,fill) { return new Uint8Array(size).fill(fill); }` covers their fresh byte storage filled with 1, with integer sizes derived from array length. The complete harness must extend that narrow interface for the parent's reported control uses: `Buffer.alloc(8)` must produce fresh zero-filled bytes, and the returned buffer must expose the four specified little-endian read/write operations. Native DataView `getFloat64`/`setFloat64` and `getBigUint64`/`setBigUint64`, with the little-endian argument explicitly true and the correct view offset/length, can supply the bit reinterpretation needed by unchanged nextUp code. Preserve exact unsigned 64-bit BigInt handling, signed zero, offsets, supported range checks and method return values as required by the actual control call sites; review those sites before freezing the shim. Buffer writes return the offset after the write, unlike DataView setters. Do not replace the control algorithm with an approximate epsilon perturbation or evaluate controls during adaptation design.

Use one frozen local Buffer compatibility binding for the admitted modules/control loader, with buffer-local methods or a private compatibility prototype. Do not attach it to the global object or modify native typed-array prototypes. This is not a general Node Buffer API or extreme-allocation/error-equivalence claim. Keep supported input/size bounds in the frozen outer protocol and leave the numerical guards unchanged. Qualification byte equality and artifact encoding belong in the harness. Full symbols are disabled by the inspected timed query paths, so symbol-buffer allocation is absent from their timed numerical work; nextUp/control construction belongs outside those timers too. Freeze and verify the additional exact control bytes separately from the inspected four-file numerical closure.

The page must verify the bytes that it actually executes. A suitable construction is:

1. Freeze the bundle, wrapper generator/loader, four input byte lengths, source byte offsets/lengths within the bundle, and all hashes. The generator only reads and concatenates bytes; it does not import the scientific modules.
2. A small frozen bootstrap fetches the bundle as bytes and verifies its complete hash plus the four exact source-slice hashes before factory execution. Compare the slices with frozen source hashes, not with a fresh untrusted manifest supplied by the same response.
3. Execute that verified byte buffer through a script Blob or an equivalently explicit mechanism whose exact payload is bound to the verified bytes. Keep all factory execution behind the completed verification gate. A separately fetched source file hash alone does not establish the provenance of an independently loaded bundle.
4. Record the actual loaded bundle/source digests and loader receipt. Preserve the native page `Math` and `performance` objects. Factory compilation/loading and provenance checks occur outside query timers and are separately accounted.

Static factories avoid runtime rewriting and do not require a broad `unsafe-eval` exception. If Blob script loading is selected, freeze the corresponding CSP and loader behavior. This is a design suggestion, not an executed wrapper or a verified launch path. A syntax-only build of the future wrapper is permissible only within the final design authorization; it is not scientific qualification.

## Input, output and timing transport

Freeze the generation rule before any generation and do not regenerate after failure. A single immutable set of generated cases can be reused by all three processes so process effects are not confounded with a different input for every launch; the final protocol must state the case-by-process assignment explicitly. Preserve each case's initial/final states and pose evidence. Domain failures consume the declared allocation under the final stop policy.

Use a fixed binary contract for finite state and numeric-output arrays: dtype, little-endian encoding, dimensions, byte length, logical field order, case/method/process identity and SHA-256. Reconstruct the same nested 17-state arrays expected by the numerical source. Do not roundtrip scientific numbers through decimal JSON. For exceptional control values, freeze explicit tokens for NaN, infinities and signed zero or a separately specified raw-bit contract; JSON null is not an acceptable silent substitute. An abstract NaN token does not prove preservation of NaN payload bits.

Prefer a small allowlisted loopback server and same-origin bounded binary transfers to giant CDP JSON/base64 messages. The server may serve only frozen assets and declared case files; output endpoints accept only manifest-declared artifact IDs, expected lengths, sequence numbers and bounded chunks. Enforce one acknowledged chunk in flight, total/chunk/file-count caps and exclusive partial files. Validate host-observed lengths and hashes before completing an artifact. Preserve partial artifacts and terminal failure metadata; never overwrite an earlier launch or accept a final summary without its promised arrays. The server and all writers are owned processes included in elapsed, storage and RSS accounting.

For outgoing outputs, serialize bounded slices with explicit backpressure and count encoding/copy memory. Browser WebCrypto digest ordinarily needs the full ArrayBuffer: use it only on explicitly bounded objects, or freeze a bounded streaming hash implementation if streaming is required. Do not promise constant memory while silently keeping a whole extra digest buffer, a CDP base64 copy, a Node array and a browser array. Full qualification symbols cost `4*n*n` bytes per retained tensor, before any comparison/transport copies. Resource design must count simultaneous L/F qualification products and all other live fields; it cannot rely on nominal file size alone.

Keep the source's `query(...).totalMs` and component timers exactly as defined. Preserve the driver-supplied guard invocation contract and freeze the guard implementation; it was not reviewed here. Generation, page loading, module hashing/compilation, input fetch/decode, output comparison, encoding, hashing, transfer and persistence are outside those timers and individually described/accounted. Also record outer page-call and whole-lifecycle elapsed times. Do not move checksum, allocation or existing guarded numerical work out of the timed query to obtain a different result. No renderer, Three.js replay, animation loop or concurrent scientific worker runs during matched timings.

Persist small raw timing/attempt metadata immediately after each return, before large output processing or validation. A thrown or interrupted call still receives a bounded failure record; a valid query measurement does not imply completed artifact persistence. Release prior outputs according to a frozen schedule without explicit GC or adaptive repetition. Freeze warmup/measured counts and ordering, qualification frequency, comparison rules and stopping rules before launch. Repeated queries within one process are dependent observations, and three process repetitions are not three independent swarm populations. Timing aggregation must respect that distinction.

The independent checker must reconstruct comparisons from saved full numerical evidence and source/input hashes, not only from checksums or driver booleans. It must retain admission reasons, symbols where required, source IDs/order, coefficient and solve/residual outputs, signed-zero/nonfinite handling, screen eligibility/fallback and omission evidence. Exact field list and tolerance/bit rules need review against the current driver/checker, which lies outside this ten-file inspection.

## What the retained lifecycle source establishes—and does not

Useful mechanisms in `run-once.py` and `process-registry.cjs` are pre-spawn intent records, a private nonce-bound append-only registry, exact executable/profile identity, finite record/byte/spawn limits, bounded pipe drains, and refusal to signal a stale numeric PID merely because a post-spawn append failed. Node stays in the directly owned relay group. The observer confirms actual relay exit/reap and pipe closure rather than trusting a worker's terminal flag.

`observe-science.py` samples owned group members and transitively observed descendants with a bounded, deadline-limited process-table helper. It counts observer/capture/probe processes too. It rejects observed unregistered detached descendants and accounts private diagnostics. Its final exact-size accounting is conditional on complete writer/process closure, and the caller must still retain the observer's real exit and full elapsed time.

The old implementation is explicitly one detached browser launch: observer registry admission enforces that limit. Its historical 300-second envelope and fixed byte/RSS/spawn/registry caps are evidence about that prior allocation, not authorized budgets for this experiment. Do not silently multiply or reuse them.

Two limitations matter directly to the adaptation:

* Safe detached-browser signaling requires a current exact executable/profile leader with PID equal to PGID. If that leader exits while group members remain, the code refuses to signal the unverifiable group and correctly marks incomplete closure. A browser-close promise cannot repair that evidence gap.
* The hard-deadline handler kills the directly owned unreaped relay group and direct probe children, but does not itself kill registered detached Chrome groups. Abrupt observer exit can therefore leave Chrome running. The source does not establish guaranteed browser teardown at the hard wall cap. Its RSS observations also are samples, not an OS-enforced peak-memory limit; shared pages may be counted more than once, and transient or GPU-driver peaks are not proven bounded.

## Proposed three-process containment contract

Use one outer lifecycle supervisor with a total deadline and resource budget beginning before setup/metadata I/O. Reserve each of exactly three launch ordinals once, use distinct fresh profile directories and immutable run IDs, and admit only one active browser at a time. Each ordinal has its own deadline, artifact namespace and receipt inside the overall cap. A launch failure is terminal according to the frozen stop-on-first-failure rule; later ordinals must be recorded as not attempted, not substituted for a failed one. The three declared process repetitions are planned experiments, not retries.

The safest source-level extension is direct ownership of each Chrome session leader by the lifecycle supervisor or a dedicated guardian whose authority survives controller failure. Launch Chrome as a directly owned new-session child, and connect the Node controller through its declared local debugging endpoint instead of allowing the controller to create an unowned detached root. Before spawn, record intent with ordinal, exact executable, unique profile, expected command/flags and authority nonce. Retain the direct leader unreaped until the designated teardown state has safely signaled its group and verified descendants. No incidental library `poll`/`wait` path may invalidate that ownership. Ensure the hard-timeout owner includes every still-owned direct browser group as well as controller/server/probe children; disarm numeric-group signaling before any reaping operation.

This is an architectural option requiring implementation and platform-specific review, not a claim that an existing Puppeteer path does it. A direct unreaped child avoids the old dependency on a live command-line leader for that child's reserved identity. It does not automatically contain descendants that deliberately create another session, children missed between samples, or every OS-managed Chrome service. Declare any permitted extra group with an ownership mechanism before its creation; reject unregistered detachment. Never signal unrelated user Chrome processes, kill by executable name alone, or infer identity from a reused numeric PID. If ownership cannot be proved, record incomplete cleanup, stop the allocation and prohibit the next launch. If strict OS-enforced memory/process death guarantees are required, the current inspected macOS polling design does not supply them; an enforceable containment mechanism must be selected before such a claim is made.

The per-launch closure barrier should require all of the following before the next launch reservation can become active:

* Scientific work and new-spawn authority are stopped, all expected artifact writers/uploads are finished or terminally failed, and the controller's actual exit is recorded.
* Bounded graceful Chrome closure is attempted, followed when necessary by a safe owned-group termination within the cleanup reserve. No indefinitely pending CDP close call is awaited.
* Owned direct children are reaped in the documented safe order; a fresh bounded process table verifies the browser group and all accounted groups/descendants absent. Unknown or unverifiable survivors prevent qualification and progression.
* Pipes and helpers are closed/reaped, registry phases reconcile, output accounting is final, and the per-launch receipt records actual exits, closure observations, errors and the retained artifact hashes.

The aggregate observer must then complete its own cleanup and final records under a reserved deadline margin. The outer caller independently records its real exit and complete elapsed interval. A hard exit or missing receipt remains a failed/incomplete allocation, never a successful terminal result. Profile deletion is not proof of process exit; retain required evidence before removing only owned temporary data.

Freeze exact caps for overall and per-launch wall time, cleanup/finalization reserve, concurrent process/group count, sampled aggregate RSS, probe interval and maximum probe gap, source/input/artifact bytes, profile/cache/temp/diagnostic bytes, files, pipe/registry entries and bytes, chunk size/in-flight count, CDP message sizes and failure records. Account profile/cache growth as well as published outputs. The previously inspected observer accounts its raw/results/private directories, but that alone is not proof that all Chrome profile and temporary storage is covered. Count the union of owned processes once per sample; state shared-page RSS duplication and unobserved transient peaks explicitly. Chrome can start GPU/utility processes even when all scientific arithmetic is JavaScript; monitor owned processes without presenting their existence as a GPU numerical experiment.

## Runtime identity and final gates

The old runtime inventory is a bounded read-only selected-file inventory with exactly six Chrome pins, explicitly labelled partial. Retain that honesty. The new freeze must identify the intended executable, framework, selected helper/resource files, launcher/automation package and Node/Python runtimes, flags, OS version/architecture and test conditions. At the admitted launch record actual Chrome/CDP product, browser and V8 versions, user agent, executable/command identity, headless or visible mode, page visibility, timer resolution/isolation state and the selected environment/power/load metadata. A reported version string or six hashes is not a complete-installation/OS proof. Before/after metadata checks should fail on drift without selecting a replacement version.

Public provenance should use repository-relative source paths, labels, digests and sanitized lifecycle facts. Keep personal absolute executable/profile paths, process command lines and ownership nonces in bounded private diagnostics when needed for safe cleanup; bind those private receipts to the public summary without claiming that unavailable private contents were independently audited.

Before any scientific action, the parent still needs a concrete frozen and published implementation of: the exact-byte wrapper and loader; case generation/admission and binary schemas; per-browser controls and comparison evidence; paired schedule and process-aware analysis; the independent saved-artifact checker; an explicit three-launch supervisor/registry/cleanup design; transport and complete storage/RSS/wall caps; runtime identity pins and allowed flags; failure/partial-evidence rules; and independent verification of the published source bytes. Source hashing or syntax checks alone cannot clear these gates. The current assessment supports feasibility of the minimal source adaptation, while leaving browser qualification and guaranteed lifecycle completion unresolved until those items are reviewed.
