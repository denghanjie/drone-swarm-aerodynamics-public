## Fresh-state meaning and shared generation evidence

“Fresh” means the declared inputs have not been evaluated for this proposed comparison before the new freeze, then are generated once using the frozen rules. New seeds and a longer horizon do not make the cases independent physical samples, out-of-family validation, mature flocks, or coupled-flight trajectories. The 5 s horizon is a fixed horizon, not an observed convergence criterion. Retain all three cases even when one is unfavorable; do not choose another time from the replay.

Save complete initial/final17-state arrays and all21 pose frames at t=0,.25,...,5, with generation config, initial/final identity, frame times, frame pins, full-state input pins, completion/stop/failure diagnostics and resource closure. Save progress and already produced frames immediately. Check finite states, exact endpoint correspondence and final input bytes. A generation/domain failure admits no replacement seed, altered duration or regenerated file. A successful generation that is followed by browser failure remains immutable evidence, not permission to rerun generation.

The browser experiments evaluate frozen final-state interaction loads. The saved poses support provenance and replay only. The interaction query is not evaluated at all21 poses, and it is not coupled back into Boids/dynamics under this proposal. State that boundary explicitly. Use a single shared input manifest; every browser verifies received byte length/hash and reports its own decoded-state before/after hashes. Loading and decoding the same bytes is not a generator rerun.

The planned total is126 returned calls if the campaign completes, including18 warmups and108 measured calls. These administrative counts do not create extra calls. Use an in-page monotonic timer around the original query boundary. Keep CDP/automation round trips, artifact transfer, compression, validation, file writes and rendering outside that timer, but save their costs and include them within wall/storage budgets. Fix the event-loop/task boundary between queries and artifact acknowledgements: changing whether calls run in one task or separate commands changes scheduling opportunities. Do not overlap heavy host compression/review/rendering with matched queries. Do not batch more computations to fix an unexpectedly coarse timer; freeze a timer-resolution/zero-duration validity rule instead.

Raw timing must survive a validation exception and, as far as the protocol can ensure, a browser crash. Send each returned raw record to a host collector, save it exclusively, and receive an acknowledgement before subsequent validation and the next query. Keep incomplete launch/page/query/export records distinguishable from returned validated queries. A console line or an unexported in-page array is not durable raw evidence. A lost acknowledgement is a terminal uncertain outcome, not a reason to repeat the query.

Retain full per-process/per-case paired L/F totals, ratios, differences, six-pair median and strict-win count, method total/phase raw arrays and median/min/max. Also retain process order and start/end load/power/visibility metadata. Report the three process-specific paired medians and their min/max/spread per case; a median across processes is descriptive only. Summary-only absent-phase zeros must be explicitly labeled as accounting, never measured L screen-preflight time.

Three serial processes on one host give a small process-repetition check. They do not estimate general runtime-to-runtime variability, and the six paired blocks within one process are dependent repeat measurements. These numbers are prospective ceilings, not forecasts of successful completion and not permission to spend the allocation. They do not derive from historical timing arrays. A smaller chosen envelope is defensible if failure is accepted as terminal. Reject changing the envelope after seeing whether it fits. Freeze chunk size and in-flight transfer bounds (for example, <=4 MiB binary chunks and one acknowledged chunk at a time), rather than building multiple huge base64/JSON copies of symbol tensors. No guarantee of compression ratio should enter the fit argument. Release full tensors only after full comparison, omitted-pair verification and durable export, without forced garbage collection.

The external supervisor must continue monitoring while the page is busy, aggregate the owned process tree, track process identity/reparenting and reject monitor uncertainty. Sampling may miss spikes and sum-of-RSS can count shared pages repeatedly; state both limitations. A lone parent PID's RSS is not a Chrome memory bound. On timeout/crash/cap/export failure, preserve the consumed slot, progress, completed artifacts and partial/raw records; close only owned processes, wait/reap and verify no owned descendants remain. A generic page-disconnected or browser.close promise does not prove tree closure.

Recommended stopping policy: any generation, correctness, artifact-integrity, runtime-identity, resource or cleanup failure halts further scientific work; remaining planned slots are explicitly marked not attempted because of that dependency failure. They are not silently omitted. Performance thresholds are interpreted only by saved review after the fixed attempted correctness schedule, so poor timing cannot trigger an extra process, deletion of a process or adaptive early success. Once all three valid processes complete, failure of any primary timing cell is an ordinary negative practical result. A missing/failed process makes evidence incomplete/unqualified, not a three-process timing result.

## Closure, independent review and final seal

Use immutable exclusive stage locks and distinct generation/process1/process2/process3/review terminal records. Source publication receipt, complete source/runtime/input pins and local/committed/remote verification must precede the relevant scientific launch. Browser process slots are declared repetitions, never retries under a success quota.

Each numerical child may report its internal completeness and correctness, but practicalRulePass stays null. The saved reviewer verifies all actual generation/browser closures and numerical artifacts, reconstructs per-process/case gates and writes immutable analysis with performanceRulePass (or null on incomplete audit), practicalRulePass=null, requiresReviewSupervisorClosure=true. It cannot assert its own terminal success.

After the reviewer actually closes, a separately frozen stdlib-only seal verifies all required terminal records, source/publication identity, input preservation, inventories and pins, reviewer pass and the immutable analysis. It combines saved Boolean gates only and writes final qualification exclusively once. Distinguish: (1) qualified evidence and practical gate pass, (2) qualified evidence and practical gate rejection, and (3) unqualified/incomplete evidence. No final success is inferred from an in-page banner, browser exit code, successful replay, or the reviewer's self-report alone. The final seal also needs its own bounded append-only failure record; it cannot repair a source/artifact or recompute timing/numerical targets.

If every fixed gate passes, the supported wording is: **on these three newly generated frozen states, in three sequential fresh processes of the pinned Chrome build under the declared warming and timing regime, L/F finite-output checks passed and each primary case met the preregistered practical gate in every process.** All broader aerodynamic, coupled-flight, live-pipeline, cross-device/browser and novelty questions remain open.
