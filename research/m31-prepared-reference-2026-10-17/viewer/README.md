# Prepared-reference saved evidence viewer

This milestone shows the actual qualified prepared-reference result and its two
saved 64-drone final states. Scene preparation, validation, suffix calls, bound
operand lookups, and pair preparation are read from the new result index. No
counter is replaced by an expected value. The prior oracle's two preparations per
residual pair support the explicitly labelled derived avoided-work count; this
is not a measured timing comparison or speed claim.

The Three.js renderer and responsive stylesheet are copied unchanged from the
qualified tree-coverage viewer. Geometry and overlay membership come from the new
saved case records, whose entire scientific content matched the prior tree
records. The display still shows actual prepared positions, source-centre proof
boxes and positive scalar support. It performs no simulation, oracle, aerodynamic
query or numerical verification. Drone glyphs are enlarged three times; boxes
are not wake volumes and support lines are not force magnitudes.

The runs that produced these states used local 3D Boids with airflow off. This
viewer adds no new trajectory and links both the earlier coverage milestone and
the original flight replay. All 24 exposed regression scenes remain in the table,
including deliberate refusal cases. The six new binding controls are distinct
from the retained, previously executed six coverage controls.

The binding pins the complete new index, both new case records, renderer and
vendored Three.js dependencies. Hash, source identity, completion, qualification,
preservation, counter consistency and binding-control checks precede rendering.
Absent, changed or failed evidence produces a disabled error state with no 3D
geometry. A stale or invalid selection also clears the overlay. Browser testing
does not establish scientific accuracy, physical validity or 5,000-drone scale.

Browser plugin is not available in this session. The explicit bounded UI-only
allocation uses installed pinned Playwright/Chrome, with an owned root/profile
and preserved numerical/source files. See `qa/attempt01/PROTOCOL.md` for the fixed
flow, failure fixtures, limits and cleanup. No existing server is restarted.
