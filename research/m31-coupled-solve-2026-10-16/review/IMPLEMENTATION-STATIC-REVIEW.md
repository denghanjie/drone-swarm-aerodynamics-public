## Initial findings and observed pre-freeze fixes

1. **Bind the execution to the published source.** The initial runner checked working files against a working manifest without binding that manifest to its recorded commit. The revised runner requires an independently supplied manifest hash and published commit, checks current HEAD against that commit, compares the manifest and every listed file with that commit's Git blobs, and checks the manifest's byte/hash entries before creating the invocation lock. Its repository lookup is anchored to the runner location. This addresses the identified provenance gap, provided the frozen manifest includes the runner, experiment, and historical excerpt and the external remote-verification record is retained.

2. **Retain ordinary launch failure outcomes.** The initial runner caught only timeout errors, allowing ordinary launch or stream exceptions after lock creation to bypass the outcome record. The revised runner validates arguments and provenance before the lock, initializes a null return code, catches timeout and other launch exceptions, and writes the outcome plus partial artifact inventory in `finally`. Those identified ordinary failure paths are now retained and exit unsuccessfully. External termination or failure of the filesystem writes themselves cannot be guaranteed to produce a record. The consumed lock must not be removed, and no automatic retry is authorized.

3. **Name the bisection work accurately.** The initial counter was called `bisectionSubdivisions`, although midpoint rounding can cause stagnation before all 56 loop bodies finish. It is now named `bisectionIterations`, and the protocol explicitly defines it as polynomial loop evaluations rather than guaranteed interval halvings. This fixes the work-label issue; it establishes no root-accuracy result.

The protocol also prospectively raised the independent review's outer limit from 100 to 160 updates. Its bound `g(alpha)>=1/(alpha+1)` follows by substituting that lower candidate into the monotone cubic. Combined with the declared coefficient/domain bounds and the global one-half log contraction, this is a valid exact-arithmetic basis for the larger finite budget. No target values were used by this audit to assess that revision.

## Static checks consistent with the intended contract

- **Frames:** the default basis is perpendicular to the axis. For the near control, writing the requested unit corner direction as `e` and `f=a cross e`, the code gives `u=(-e+f)/sqrt(2)` and `v=(-e-f)/sqrt(2)`, so its first corner `-arm(u+v)` is exactly `R e` in real arithmetic. This matches the symbolic construction. The hexagon axis uses the preceding vertex and the correct source-to-receiver edge orientation. Floating normalization and frame agreement still need the independent check.
- **Admission:** every non-self rotor pair is evaluated. Symbols 4 or 11 append an admission error, and any error returns before either solve. The retained zero-valued coefficient for a rejected pair cannot be used by a solver in this code path. The whole-cube scaled cap uses `K sqrt(S0_j/mg)`, correctly bounding source amplitude because `0<=y_j<=1` under the intended map.
- **Four receiver roots:** `nodeMap` computes one dimensionless inflow and cubic root for each of four receiver rotors, then computes `sqrt(sum_r f0_ir*x_ir/S0_i)`. It does not average inflow or substitute a total-disk root. Its coefficient denominator is the individual receiver rotor's hover inflow; the source numerator uses the source's total nominal force. The frozen nominal-force formula is strictly positive.
- **Direct order:** graph edges are stored as `[source, receiver]`; descending center height with ID ties is used only when every positive edge respects that order. Since positive `S0` preserves the zero pattern between `K` and `a`, this checks the actual nonzero dependencies of the frozen map. Initialization of unprocessed amplitudes to one is harmless in an eligible pass because those unprocessed sources have no positive coefficient into the current node. Direct residual work is separate.
- **Simultaneous iteration:** every update uses the same previous vector. It starts at one, retains the initial state and every update, performs at most 64 updates, saves the last updated vector, then evaluates that vector's map once more for its residual. The saved final rotor forces belong to this final residual evaluation. The first update is reused as the uncoupled-source ablation and is not an extra map call.
- **Work accounting:** geometry calls equal `4*N*(N-1)`. A direct pass has `4*N` closures plus `4*N` separately recorded residual closures. With `k` simultaneous updates, iteration work has `4*N*k` closures, followed by `4*N` residual closures. The ablation's work is already included in update one and must not be added again. The positive-term counter counts positive dimensionless coefficient-times-amplitude contributions, not all floating-point multiplications in the program. Alpha-zero closures are counted but return without bisection iterations. These are operation counts, not elapsed speedups.
- **Historical field:** the inspected copied excerpt retains the original receiver-rotor point evaluation, source-axis projection, near rejection, downstream/radial fades, receiver projection, and speed admission logic. No target calls were used to reach this assessment.
