**Interface.** Invoke the supervisor with pinned Python `-I -B`, `source/supervise.py`, and exactly `kernel` or `checker`. External environment provides `RESEARCH_NODE` as the intended pinned executable and `RESEARCH_PRIVATE_RUN_DIR` as an outside-repository directory, empty for the kernel and retained for the checker. Machine paths stay outside public source/runtime pin documents. The supervisor uses its own resolved Python executable and resolves the specified Node executable, checks both binary byte counts and SHA256s, clears Node/Python preload/search overrides, and refuses loader injection.

The kernel child command is `[NODE, PACKAGE/source/run.cjs, PACKAGE]`. The checker child command is `[PYTHON, -I, -B, PACKAGE/source/check.py, PACKAGE]`. The supervisor injects `RESEARCH_SUPERVISION_STAGE`, `RESEARCH_SOURCE_COMMIT`, `RESEARCH_SOURCE_MANIFEST_PATH` and `RESEARCH_EXPECTED_MANIFEST_SHA256`. Child scientific output must retain top-level `sourceCommit`, `sourceManifestSha256` and `configSha256` in index/check reports. Attempts are `results/{stage}-attempt.json`; closure reports are `results/{stage}-supervision.json`. Attempt fields are exactly stage, sourceCommit, sourceManifestSha256, configSha256, launchCutoffUtc, allocation and startedUtc. Allocation text is `sole attempt; existence prevents retry`.

**Publication and exclusive allocation.** Before any scientific child, the supervisor requires the fixed package/config, exact resource limits, fixed case IDs/seeds, arm and schedule IDs, a nonempty duplicate-free manifest with canonical path/byte/SHA pins, the complete present local source file set, runtime pins, and an exact-public-verification receipt. The receipt must bind the manifest bytes/path/count and a 40-digit commit, claim remote and committed byte equality, and carry a valid timestamp before the fixed cutoff. It is a saved receipt supplied by the parent; this code does not invent an HTTPS retrieval.

The supervisor checks current local files against every source pin and compares every pin plus the manifest with Git blobs at the receipt commit, with replacement objects disabled. HEAD must equal that commit. It rechecks source, source file membership, runtimes, receipt and exclusive attempt bytes after scientific process closure. The source gate hashes whatever complete reviewed closure the parent publishes, including explicitly listed historical reference source dependencies; it does not evaluate historical result corpora or invoke previous experiment entry points. External dependency completeness remains a source-review obligation, not something inferred from arbitrary dynamic imports.

Kernel requires empty results and private-log directories. Any preexisting stage output, attempt, lifecycle report or private stage log refuses that stage. Attempt creation is exclusive and fsynced before launch; there is no retry path. Checker requires closed-success kernel supervision, matching source/config/runtime context, all kernel lifecycle files and the exact saved scientific pin set. All preexisting kernel scientific/lifecycle files and private raw logs are pinned before checker launch and rechecked afterwards. The checker shares the same private log directory, so accounting cannot silently omit kernel logs.

**Fixed outputs and limits.** Kernel output membership is the parent-agreed closed set: index and journal; twelve inputs (four inherited controls, six fresh scheduled states and lifetime A/B); two generation records; eight control-call files; forty-eight scheduled-call files; two direct-control transcripts; and two lifetime files containing three method bodies each. The latter were added after independent source review identified those two unique control inputs; the checker author confirmed independent both-arm lifetime validation. No arm-suffixed reference filenames are allowed.

Kernel scientific bytes are capped at192MiB; checker scientific bytes at64MiB; metadata plus both raw/private and redacted/public logs at16MiB; aggregate at272MiB. Index/check reports are2MiB, journal4MiB, each generation8MiB, each remaining scientific record file32MiB, and each supervision report64KiB. This supervisor permits partial scientific files to be preserved on failure: presence of index/journal and clean process exit is a containment condition, while complete scheduled coverage, record semantics and benefit are the independent checker's responsibility. Missing/refused slots cannot thereby become scientific success.

**Process ownership.** Each stage has600s supervised duration,610s independent guardian deadline and1GiB sampled process-group RSS. The guardian starts a new session and stays alive after the scientific child exits. Kernel may have at most one additional sequential worker, with the exact observed parent chain guardian -> runner -> worker and one inherited process group. Checker may have no subprocesses. The inspected runner worker interface uses synchronous Node spawn with60s timeout, SIGKILL and bounded stdout/stderr; it starts no separate process group. The source monitor refuses observed unexpected descendants, escaped descendants, residual members and premature guardian exit.

After the child exits, supervisor requires the guardian to be the only remaining group member before sending release. Failure cleanup signals only while the owned leader remains alive. Guardian failure/disconnection/timeout ignores its own TERM, sends TERM to its still-owned group, waits briefly for its direct child and then KILLs the entire group including itself. This includes a worker even if its runner has already exited, and avoids relying on a successful failure-journal write. Supervisor records group absence before declaring closed. No signal targets a historical exited group ID.

This is containment of reviewed processes. RSS and output sampling are not continuous instantaneous hard limits; short-lived processes may fall between samples. Escaping hostile code, uncatchable guardian death, process-ID reuse and operating-system failures are not proven isolated. The monitor reports actual sample gaps and sampled peak group RSS; it does not produce per-arm peak-RSS or CPU evidence. Source/runtime rechecking and final accounting are included in supervised wall duration; primary worker timing is separately defined and implemented by the parent kernel. Source-only review does not measure its cost.

**Report meaning.** Stage `success` requires child/guardian zero exit, no recorded containment/provenance/resource failure, normal group closure, and postrun source/runtime recheck. Checker also records the scientific `passed` value separately. The current checker interface returns nonzero when its scientific passed gate fails, so failed benefit or correctness consumes the sole attempt and does not become a successful advancement. Finalization errors attempt an exclusive terminal-error record with `closureUnproven:true`; consumers must reject any such marker. No historical failure is relabelled and no new experiment is allocated by this source preparation.
