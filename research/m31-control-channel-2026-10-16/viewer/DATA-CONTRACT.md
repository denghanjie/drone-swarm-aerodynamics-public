# Visible control-channel milestone

This is a recorded engineering evidence diagram, not drone flight or a live transport simulation. Five stages will map only to final actual records: page construction, API return, representation validation, exclusive file persistence, and independent reread. Until binding.json exists, the page fails closed and displays no result.

The renderer is reused unchanged from the published transport checkpoint; the introductory text and binder are specific to this new test. It hashes the evidence JSON and every declared backing file before rendering. The binding is integrity checking, not authenticity independent of the repository. Earlier 3D Boids with airflow off remain linked. No synthesized flight or airflow is added.

The flow under test is: load this viewer -> verify evidence bytes -> choose stages and saved events -> see the corresponding recorded details. Browser plugin not available; regular installed Playwright will perform presentation-only checks after the diagnostic is terminal, on the existing server. Desktop/mobile screenshots, controls, errors, and corrupt-binding rejection will be recorded. This QA does not consume or repeat the diagnostic's payload extraction.
