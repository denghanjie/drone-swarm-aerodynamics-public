## Returned representation

Envelope keys are exactly `version,format,payloadId,byteLength,values,origin,isSecureContext,constructionPhase,browserConstructionMilliseconds`. Identity is version1, `uint8-values-v1`, `synthetic-control-channel-3840-v1`, length3840 and phase `array-ready`. The decoded ordinary object's properties must be own enumerable data properties. Its values must be an ordinary array with length3840, exactly3841 own keys including length, and an own data property at every numeric index. Every element is a finite integer from0 through255; coercible strings/null/undefined, floats, negative zero, overflows, holes, accessors and extra keys are rejected before Buffer.from.

Origin is admitted only as the exact fixed page origin or the literal `null`; opaque-null is retained safely but creates a protocol deviation. Secure-context is Boolean. Browser construction duration is finite, nonnegative and below10000ms. All admitted strings are fixed ASCII; canonical compact JSON plus newline must be at most32768 bytes. The validator never compares content against expected bytes: valid-shape wrong bytes must still be persisted as actually received.

Only after strict validation is `raw/returned.json` written. It is the canonical JSON encoding of the actual decoded Playwright return value, not a wire-protocol capture. The values then become the received Buffer; the frozen fixture is only compared, never substituted as output. An invalid envelope causes an incomplete diagnostic, preserves a bounded safe `raw/rejected-return.json` projection with error code and primitive root type, and publishes no unvalidated arbitrary strings/nested values. The rejected original is not retained; this explicitly limits subsequent independent reconstruction of the rejection.

`raw/received.bin` is created exclusively once from the actual received Buffer. Partial writes advance only by successful returned byte counts; zero/failed writes reject and preserve the actual prefix. File close is recorded separately. A declared-length complete write can contain incorrect bytes. Received digest, actual persisted digest, equality to received bytes and equality to the expected fixture are distinct fields. Final worker reread follows browser cleanup; independent saved review must reread again after actual external closure.

Local completion requires recorder health, no operational/cleanup/deviation error, browserClosed and evaluation.settled. A fully observed non-timeout evaluate rejection can be complete with `status:"control-return-failed"`, no returned JSON or binary, and worker exit0. It is failed transfer with complete local observation. A malformed return is incomplete/exit1 with a safe rejection projection when writable. Timeout or a late return beyond10s never proceeds to persistence and is incomplete/exit1. Successful valid actual-byte persistence has `synthetic-control-transfer-complete` if exact, or `received-content-mismatch` if the actual retained bytes differ from the fixture. Correctly observed wrong content can exit0; success and integrity remain separate. Other persistence failures are incomplete when their operational error is caught. The fallback status `persistence-failed` exists for any complete record lacking a completed equal-to-returned file.

Worker stdout contains exactly one `synthetic-control-channel-worker-summary`, binding result.json's bytes/SHA, status, terminal and qualified:false. Stderr contains only a fixed-shape finalization-failure record if normal finalization fails. Lifecycle output names remain root-owned `results/diagnostic-stdout.txt`, `diagnostic-stderr.txt`, wrapper.json/budget.json/capture.json and the agreed final tool receipt. Root's observer must expect the new worker kind; other source/terminal/qualified/status projections remain compatible.

## Trace, privacy and resources

Public `raw/trace.public.ndjson` and private `trace.private.ndjson` beside the registry share envelope `{version:1,id:eN,sequence:N,clock:worker-monotonic-receipt,milliseconds,kind,data}`. At most2048 write attempts, private trace3MiB, public trace2MiB, per-event8192 bytes. Failed/partial writes, dropped events and truncation make instrumentation incomplete. Listeners are detached after cleanup and before closing traces/snapshot; counters cannot drift afterward.

The new phase kinds are `control-evaluate-started/returned/error`, `control-envelope-validated`, `persistence-started/write/completed`, and `cleanup-finished`; PW/page/CDP kinds retain the predecessor semantics. Channel phases use `transferID:channel-1`. PW and CDP request IDs remain different namespaces. Audits may replay; absent optional fields remain unknown. There is no sink event namespace or sink authority in this design.

The public projection retains controlled numeric/Boolean fields, logical IDs, lexical-filtered categories and known header values; arbitrary console/error text, exact request URLs, profiles/process identities/private paths and unsupported detail objects stay private or are omitted. Headers exclude authorization and cookies; Content-Type is admitted only for exact known complete values, so arbitrary parameters cannot leak. Error text is limited to net::ERR categories. Validated returned.json contains only the fixed-safe envelope and ordinary byte values. Rejected values are represented only by a fixed safe projection.

Worker hard limit40s includes cleanup; substantive work stops34s. A stop flag and monotonic guards apply after evaluate, before validation, before retained JSON and before binary exclusive open/write. The one evaluate is bounded by10s; Promise.race timeout is not claimed as cancellation. Browser close is bounded3s; the root's independent owned-process supervisor remains authoritative for actual closure and its60/58 limits. No second evaluation is issued to recover a timed-out result.

Root enforces8MiB combined retained diagnostic output and2GiB sampled owned RSS, including private traces, both return artifacts if present, partial binary, pipes, registry, locks and final receipts. Local hard subcaps leave headroom for lifecycle records. Wire size/serializer expansion is not measured by returned.json size. This one3,840-byte transfer supplies no scaling, reliability, GPU-mapped-lifetime, old-cause, aerodynamic or performance conclusion.
