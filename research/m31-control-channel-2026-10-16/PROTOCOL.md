# Prospective engineering diagnostic: one control-channel return

Adopted October 15, 2026 UTC under the standing research mandate. This is a new isolated engineering question following published result `98880952397aedbc99bdd11794ad6085d883328a` and static follow-up `57d275a1eed21475c76880cbab0ad1cf5edae8b1`. Earlier terminal attempts remain immutable. No scientific experiment or automatic successor is allocated.

## Question and hypothesis

Can one ordinary-heap payload constructed in a controlled browser page return through the existing Playwright automation channel and be persisted without changing its bytes? The API documentation motivates this possibility; it does not establish success here. This test does not change any browser permission or security setting and does not exercise the earlier HTTP sink.

The fixed fixture has 3,840 bytes, byte i = `(73*i+19) mod 256`, SHA-256 `b92773fc3edb949a8a0d6e4a2f60ef2020ee2bd5bf6f8299c1448142a6cd3404`. This non-scientific fixture was already public; it is not a fresh confirmatory scientific sample. No scientific input, GPU API, wake model, flight integration or historical output may be imported.

## Fixed design

One explicitly pinned Chrome 155.0.8059.80 lifecycle, Playwright 1.62.1 and Node 24.19.0. Runtime executable/package checks derive from the previous diagnostic and are repeated before admission and after launch where specified by source. The same loopback page origin is retained. Frozen HTML/script are route-fulfilled; no application HTTP payload transfer or evidence sink is created.

The browser creates its ordinary Uint8Array and a dense plain number array. Exactly one payload-bearing `page.evaluate` is reserved, with no retry, secondary extraction, fallback encoding or transport. Before Buffer conversion, the receiver validates exact envelope keys, fixed labels, exact length, array density and finite integer values in 0–255. The actual returned representation is retained within 32 KiB. Only its validated values may supply the output file; expected fixture bytes must never replace a failed or mismatching return.

The one output file is created exclusively. Partial writes are handled explicitly; any partial file is retained. A valid-shape but incorrect-content return is still persisted as its actual bounded bytes and classified as mismatch. Declared-length completion, actual digest and equality to the fixture are distinct outcomes. File-close completion is required. An independent checker rereads the output after external process closure and compares exact bytes to the separately frozen fixture.

Host observation is prearmed before evaluation. Public event records use stable local IDs and allowlisted values; original private exceptions/ownership data remain private. A missing evaluate return leaves browser completion unknown. A promise timeout does not cancel page JavaScript; further work stops and owned context/browser closure plus the external ownership supervisor establish whether cleanup completed.

## Allocation and stopping rules

- One new diagnostic invocation; at most one browser lifecycle and one payload extraction. A reserved invocation is consumed even if interrupted. No relaunch or completion of skipped stages in this record.
- Whole observed command allowance60s; worker40s, substantive stop34s, evaluate deadline10s, cleanup through58s, caller hard limit60s. Existing ownership supervision is copied with its derivation disclosed.
- Combined retained execution output cap8MiB; sampled owned RSS cap2GiB; trace2048 events. These are operational bounds, not measurements of transient or driver memory. Public/private execution artifacts are accounted together.
- Source-only syntax checks, pure inert validator tests and independent static review precede freeze. Freeze includes the independent checker source and its pure tests. Publish and independently verify the exact commit/freeze before the diagnostic invocation.
- One separately invoked saved-evidence review after external diagnostic closure, at most30s, no browser/producer imports, fresh outputs and permanent lock. Complete actual tool exit observation is required. Public input manifest excludes reviewer outputs and binds all selected final evidence.
- No new overnight diagnostic or saved-review launch at or after **2026-10-15T23:00:00Z** (October16 07:00 Shanghai). Preparation that misses that window is checkpointed unexecuted. The window is not extended.

## Primary outcome and interpretation

The narrow positive observation requires admitted source/runtime, exactly one returned valid envelope, an exclusive closed file, exact post-closure file equality, complete instrumentation, complete owned-process closure and complete actual external observation/accounting. It supports only this single fixture, representation and environment. There is no failure-rate estimate from one trial.

Classify API/rejection/timeout, invalid shape, wrong content, persistence failure, and incomplete evidence separately. Preserve observed boundaries without inferring unobserved browser execution. A record-consistency pass can accompany a failed transfer. Conversely, matching bytes cannot excuse missing lifecycle evidence. Protocol deviation, source mismatch, cap breach, dropped evidence, extra extraction or uncertain ownership rejects the complete positive claim.

Host evaluate elapsed time combines browser execution, scheduling, serialization, transfer and deserialization. It is not isolated wire time or a benchmark. No zero-copy, GPU-buffer-lifetime, scaling, historical-cause, numerical-accuracy, physical-validity or 5,000-drone feasibility conclusion is permitted from this diagnostic.
