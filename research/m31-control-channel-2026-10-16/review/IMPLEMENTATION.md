# Independent saved control-channel evidence checker

Prepared for the prospective `research/m31-control-channel-2026-10-16` campaign. This checker has not been invoked on campaign evidence. Preparation used syntax parsing and synthetic tests of `byte_evidence.py` only; neither the diagnostic nor the checker was imported or executed by those tests. Historical sources and evidence are unchanged.

Install `check-records.py` and `byte_evidence.py` together under the campaign's `review/` directory. Include both files, `test_inert_bytes.py`, `INERT-BYTE-RESULTS.json` and this note in the source freeze before the diagnostic invocation. The checker also verifies every pin in that freeze, including the worker validator. It reads frozen files as bytes; it never imports operational sources, launches subprocesses or opens a browser. Python bytecode-cache writes are disabled before importing the pure helper.

After the diagnostic's actual external completion, root prepares `publication/capture-execution.json`, exact retained `publication/capture-output.json` and `publication/observer-output.json`, and `review/evidence-manifest.json`. The execution receipt kind is `actual-control-channel-capture-tool-completion`, with `sourceCommit`, `sourceFreezeSHA256`, `toolSessionCompleted`, `actualCaptureExitCode` and `actualFullElapsedSeconds`. The manifest kind is `new-control-channel-public-evidence-manifest`, version 1, with the same source identity and `files` entries containing campaign-relative `path`, `bytes` and `sha256`. It covers the complete flat `raw/` and `results/` directories, the permanent capture lock and the three publication receipts/copies. Publication paths must be public evidence. The manifest excludes itself and later reviewer outputs.

Invoke exactly once as `python3 review/check-records.py ABSOLUTE_CAMPAIGN_DIRECTORY`. The source derives the repository from the established `research/campaign` layout. It reserves campaign-root `review.lock` exclusively and creates fresh `review/results/`. It refuses a reused reservation or existing output directory. The original `2026-10-15T23:00:00Z` launch cutoff is unchanged. Work stops at 25 seconds, finalization must begin before 29 seconds, and an independently armed 30-second alarm remains active through output and exit. Root must record actual checker exit and external elapsed time; the checker cannot certify its own later exit.

Five assertion groups cover frozen source and expected fixture; the final public manifest; the worker, trace and exact bytes; explicit lifecycle projections; and resource/output accounting. Reports list these groups and bounded meaningful errors, without a synthetic assertion-count total. Source/evidence paths must be contained regular files with no symlink traversal. JSON rejects duplicate keys, non-finite constants and negative-zero integer tokens. The public manifest has an aggregate 8 MiB read cap before payload loading. Source verification is separately bounded.

For a validated return, the checker reconstructs bytes independently from `raw/returned.json`: exactly 3,840 integer values from 0 through 255, excluding booleans, floats, strings and nested values. It requires byte-for-byte equality between those actual returned bytes and `raw/received.bin`, then separately compares each with frozen `payload.bin` and an independently reconstructed `(73*i+19)%256` fixture. Reported hashes, equality flags, write totals and transfer status must agree. It never substitutes expected bytes for received bytes. The returned JSON is a saved encoding of the decoded automation return, not a capture of wire serialization.

A complete non-timeout evaluation rejection can pass record-integrity review with `transferSuccess:false`, no invented array or file, and matching settled-rejection trace. Valid but incorrect returned bytes can likewise pass integrity review only when the actual persisted bytes match them and the worker honestly reports the fixture mismatch. Malformed returned arrays, timeout/deadline overrun, partial persistence, contradictory bytes, recorder loss, unclosed lifecycle or missing external completion cannot qualify. This complete-observation scope deliberately does not certify every possible partial failure record.

The trace must be contiguous, monotonic within the worker clock, bounded, closed after cleanup and consistent with the observed phase and write counts. Browser timing is a separate clock; no cross-clock ordering or throughput claim is made. The lifecycle checks use named shared fields and raw-file hashes rather than whole-object wrapper equality. A worker's local success cannot replace actual observer/capture exits. Process closure and sampled RSS remain claims of the saved observer; the review does not independently reobserve old processes or inspect private logs. Sampled RSS is not proof of transient or GPU-driver peak bounds.

The diagnostic's recorded combined byte total is reconciled with exact public file lengths and reported private bytes. Later public summary copies, external capture receipt and manifest are added; review lock/report/summary and one additional stdout-summary copy are also counted. Any later external review completion receipt must be added by its recorder. This does not reopen the diagnostic allowance. Review report and summary are bounded to 64 KiB and 4 KiB. Regular validation failures are retained as terminal reports; admission refusal before exclusive output ownership or a hard kill cannot promise a complete report. No finalization path changes failed checks to success.

`recordIntegrityCandidate:true` plus checker exit 0 is only a candidate pending root's actual completion receipt and complete final summary hash. `recordIntegrityVerified` and `qualified` remain false inside the self-report. `transferSuccess` is separate and can be false for an integrity candidate. Neither result explains historical transport failures or validates any aerodynamic model.

The inert tests cover malformed containers, wrong lengths, boolean/float/negative-zero/non-finite/string/nested/range-invalid values, exact synthetic bytes, honestly retained wrong bytes, a changed persisted file, and a full-length synthetic array. They import only the pure byte module. Their outcome is source-preparation evidence, not an operational saved review or a diagnostic result.
