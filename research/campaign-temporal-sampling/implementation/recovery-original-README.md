# Bounded airflow-cadence numerical campaign

This independent harness imports the unchanged local 3D Boids controller and RK4 receiver dynamics. The field evaluator is byte-for-byte frozen from the preceding exact campaign (SHA-256 `6111d7a70a7ca60ed7404889042e4f0ad61c852794289fc6f5e95d67070c9189`). No physical-model validation is claimed.

The campaign cannot run until the parent approves the final plan and creates the freeze record. `src/campaign.cjs` verifies all source/config and plan hashes, performs a historical full-state/held-inflow compatibility check, and serializes the prospective reference-gated matrix. It refuses an unregistered rerun into existing results. Node.js and Python standard libraries suffice; no package installation, remote computation or network access is needed.

After freeze, run `node src/supervise.cjs` serially. Direct campaign invocation is rejected. Do not run it alongside another numerical experiment. The entire compatibility/matrix/replay pass has a 300-second wall/CPU cap and each job a 45-second wall cap, enforced by an independent monotonic watchdog. Synchronous integration, checksums, gzip and serialization remain inside the job deadlines. Instrumented single-run stage timings are resource records, not optimized steady-state throughput measurements.

The campaign automatically runs `src/evaluate.cjs` through its module entry inside the original supervised window, reconstructing coupled reference gates from hash-verified raw full17 arrays and rejecting any discrepancy. Standalone numerical recomputation is disabled; no CLI starts a new audit allowance or silently resets the original 300-second budget. The saved replay source and raw field/state arrays make force/torque diagnostics reproducible, but additional numerical replay is outside this frozen execution allowance. The independent read/recompute path does not trust saved error summaries. It shares the frozen field/receiver equations, so this is reproducibility evidence rather than an independently derived aerodynamic oracle.

Raw data use gzip-compressed little-endian Float64 arrays; each adjacent `.json` specifies shape, field order, cadence and compressed/uncompressed SHA-256. Driver states retain every 0.15625 ms endpoint. Other coupled records retain every common 0.625 ms full17 state. Each field value is a nonnegative projected rotor scalar. Its source/receiver cosine is fixed at refresh; RK4 recalculates effective thrust from current motor state and rotates by current attitude. Yaw torque remains nominal. The coupled terminal state does not refresh field or controller; diagnostic instantaneous terminal fields are separate.

Fixed-path error integration uses the old held field at both ends of each interval. Thus a refresh's old-hold left limit and new-hold right limit remain distinct; terminal left-limit errors are retained. Force impulse is world-frame; torque error is rotated into the world frame before angular-impulse integration. Saved maxima describe sampled endpoints and one-sided limits, not continuous-time suprema.

`node src/build-viewer.cjs` builds the record-linked viewer dataset after the experiment. Serve this directory with `python -m http.server 8000 --bind 127.0.0.1`, then open `/demo/`. The Three.js modules and complete MIT license are local. The viewer downsamples actual retained states to 10 ms and interpolates visually; diagnostic metrics use the raw dense paths. Rendering is not timed as simulation. Native artifacts and publication are managed separately by the parent.
