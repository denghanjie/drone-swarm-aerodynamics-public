# Next decision: one audited browser scaling probe after compact-evidence source work

**Prepare one bounded source package, then consider one four-case browser attempt. Do not launch the present Node harness at 5000.** The qualified candidate has not yet demonstrated useful work reduction on a representative saved swarm, and its current requested evidence cannot satisfy the existing large-run file cap. The next question is narrow: on fresh initial scenes of increasing spatial extent, can H reduce the complete audited native-query cost after paying for the tree, traversal, source sorting, and required witness capture?

This note is a source-only decision. It writes no other source, changes no frozen result, and authorizes no launch. No new experiment, candidate import, test, browser, network or Git operation was performed. The author wrote the native candidate and is not an independent reviewer of that code. Existing source, the saved qualification report, and previously verified literature were read.

## What the completed qualification does and does not support

The saved checker passed 42 cases / 126 native queries, 15 deliberately corrupted saved-record controls, 16 subtraction fixtures and six threshold comparisons. This supports the registered finite Node equivalence and certificate checks. It is not a browser or performance result.

The exposed `fresh-a-t5` 64-drone record is counterevidence to calling this a successful optimization: H omitted **zero** pairs and retained all **4032** nonself candidates, just like F and H0. H additionally built 15 nodes and recorded 960 node visits and 5760 endpoint comparisons. The 64 omitted pairs across the entire fixed suite came from artificial boundary/sparse controls. Those observations establish that the code can omit certified groups, not that it has removed useful work in the exposed compact swarm. No timing conclusion is drawn from these work counters.

The earlier grid loss also remains counterevidence to assuming that fewer visits means lower cost. A tree win must be measured including its repeated construction sorts, receiver gathering/order restoration, allocations, and complete numerical pipeline.

## Why the present evidence path blocks launch

With requested evidence, `tree.gather` stores each receiver's actual `gathered` array, including self, plus its visited-leaf and cull arrays. H0 retains every source. For N5000, the compact JSON text of `[0,...,4999]` is 23,891 bytes. Repeating it for all 5000 receivers requires **119,455,000 bytes per query** before any field names, leaf visits, bounds or native payload. That alone exceeds the 32 MiB file cap. Four stages do not fit by merely moving the same arrays into a different JSON envelope. Keeping all those ordinary arrays also adds substantial live allocation; byte arithmetic is not a measured JS heap or RSS result.

The current harness then duplicates complete payloads into sidecars, `work.jsonl`, and `work.json`. That duplication must not be carried into the large browser package. The full positive CSR can independently exceed a single file cap near the unchanged 2,000,000-term guard: K and a alone require 32,000,000 binary bytes, before source indices and other evidence; their existing hex JSON needs still more. Disabling all coverage, saving only a checksum, truncating candidates, lowering the positive cap, or increasing file/disk caps after exposure is not an acceptable fix.

The current Python checker also explicitly visits every omitted member and reconstructs full per-receiver arrays. H0 evaluates every tree node for every receiver, including the endpoint predicates. Repeating expensive Fraction operations over the resulting large cross-product risks exhausting the fixed checker allocation. Disk compression alone does not resolve that checker cost.

## Minimal compact evidence work and proof obligations

Prefer one optional compact collector and one lossless transport extension, not a new scientific harness family. Leave the present qualified package immutable and fork narrowly. Keep leaf capacity 8, all source order and numerical expressions, whole-scene eligibility/fallback, original guard sites, positive-term limits, and every full native evidence field.

1. **Pack actual receiver coverage as it is produced.** After gathering and sorting, encode the actual sequence as increasing `(start,length)` runs or a fixed-width literal-index block, choosing the shorter exact representation. Do not retain all ordinary candidate arrays until query completion. H0's actual `[0,N)` sequence becomes one run only after the encoder checks the real array; never synthesize that run solely from the H0 label. The classifier must consume the same sorted array that the witness describes. Preserve incomplete/failed-receiver state honestly.
2. **Store nodes once and deduplicate repeated trace data exactly.** Keep actual finite endpoint words, children and leaf members. Pack visited-leaf IDs and culls with explicit integer ranges/lengths; retain every cull's node, first qualifying axis/side, and rounded difference word. Identical leaf sequences can share a dictionary entry after byte equality, which removes H0's repeated full-leaf lists. 3. **Shard full numerical evidence without dropping it.** Preserve the complete logical `encodeEvidence` payload for every arm and stage. Use fixed-size shards below 32 MiB, with a bounded manifest of ordered lengths/types, complete path coverage and hashes. Content-identical raw/prepared/CSR/solution/load chunks may share storage only after each arm's actual returned values have been encoded and byte-compared. A reference to F's payload based merely on “equal=true” is insufficient. The independent checker must resolve and inspect the full data represented by every reference. Binary packing preserves exact 64-bit words and integer identities; it does not authorize numeric rounding or omitted fields.
4. **Keep the journal small.** Durably record ordered input/result/trace shard descriptors and status once; avoid embedding the same full body again in the journal and final index. Bind all shards, lengths, method/stage IDs, input hashes, source pins and completion flags. Missing, repeated, reordered, unknown or trailing encoded elements must fail. Set decompressed element/byte bounds from the frozen schemas and native limits, rather than trusting compressed file size.

The collector's work is inside the measured query. Final serialization, optional compression, host transfer and persistence are separately clocked and excluded from the native-query metric for all arms, while remaining inside the browser and total resource allocation. No failed equality may be replaced by a shared chunk; preserve its divergent bytes or a clearly incomplete resource-failure record. Full reconstruction and comparison remain mandatory for success.

Compact transport is not a guarantee that arbitrary admitted N5000 payloads fit the aggregate cap. The native positive-term cap stays unchanged. ## Exact large-case certificate verification without an all-pairs replay

The large checker may use the node proof instead of rechecking every omitted member separately, but that change must be explicit and separately reviewed. Reconstruct the entire deterministic tree from saved center words, prove its bounds are the actual extrema and its leaves partition the canonical IDs, verify each recorded rounded endpoint comparison and first-satisfied axis/side, and prove that visited leaves plus culled subtrees partition every receiver's full source set. Monotonic RN subtraction then applies to every descendant. This proves the same omission property; it is not a sampled audit.

Exact integer bitsets can represent each node's descendant IDs and each receiver's retained/omitted partition. Compare decoded sorted candidate runs to those sets, require disjoint runs and exact cardinality/order, include self exactly once, and verify no omitted subtree contains self. H0 must have no culls and its actual decoded candidate sequence must be exactly `[0,N)`. Counts of visited nodes/leaves, omitted members, gathered indices, nonself candidates and completed receivers can be derived without materializing a 4N² symbol tensor or N² Python lists.

If independent validation of H0's endpoint-comparison counter would otherwise dominate the checker, a narrow exact acceleration is available. For finite eligible inputs, ties-to-even gives:

```text
RN(x) >= 4   iff exact x >= 4 - 2^-52
RN(x) <= -4  iff exact x <= -4 + 2^-52
```

Both midpoint ties round to the even word ±4. Predecode dyadic coordinates to exact integers on a shared scale that includes 2^-52. Sorted receiver coordinates and exact prefix bitsets can then form each node's six ordered predicate-success sets. Intersect with that node's actually visited-receiver set; remove receivers after their first success; sum the remaining-set sizes before each test to obtain the comparison count. This handles H0's ignored first success without an N-by-node Fraction loop. Actual saved cull-difference words still need the existing exact RN conversion. The midpoint formula, inclusivity, signed zero, first-test order and mask accounting are proof obligations; a source author must not replace RN comparisons with ordinary exact `difference >= 4`.

Use the existing 42 saved cases to check compact-to-original logical reconstruction and the optimized partition/predicate results against the already saved exhaustive certificates. Retain the 15 corruption laws and fixed RN fixtures; add only focused saved-data corruptions for bad run length/dictionary/shard references if needed.
