Only source/text reads, structural JSON inspection, index/ID lookups and byte hashes were used; no scientific module, fixture, generator or reference was imported or evaluated.

The current dispatcher has the intended structure: complete scene preparation; exact global guard; exact node proofs before residual scalar calls; full scalar fallback when the global proof fails; and canonical pair ordering before decision and root/load arithmetic. Its explicit leaf `sourceIndices` allows a completeness test that preserves counts and all positive contributions. The fixed corpus supplies witnesses for all six controls below. None requires a new scene or a witness search during validation.

## Independent acceptance requirements

The small-corpus checker may expand membership, using the unchanged full oracle as comparison evidence. The new producer must keep proved-zero terminals compact and must not materialize their pair records just to fit an old schema.

1. Reconstruct raw/prepared words and exact geometry independently of candidate metadata. Require byte/value equality with the frozen full reference, including raw/preparation refusals. Reconstruct each node's exact center/axis bounds, membership, split, ID and range from those operands. Do not trust a candidate box merely because its endpoints are ordered.
2. Require one unique stable-ID permutation with an inverse; the tree uses stable IDs, leaf `sourceIndices` use input indices, and terminal bounds use permutation positions. Enforce every pair's `i == inputIds[ii]`, `j == inputIds[jj]`, rotor and nonself condition. The tree recipe is exact largest span with xyz ties, coordinate then ID sorting, floor midpoint, capacity 8 and preorder left-first IDs.
3. For each receiver/rotor, terminals partition `[0,N)` in order without gaps or overlaps. Each terminal count is `end-start-1` exactly when the receiver's unique self position is inside the range, otherwise `end-start`. The effective pair membership is the full range minus that self position. A singleton still has four queries and zero nonself members. Require exact leaf member lists, unique scalar pair keys and canonical `(ii,r,jj)` order. `zeroPairs + scalarPairs == 4N(N-1)` alone is insufficient.
4. Reconstruct the global guard and evidence. A failed proof requires the unchanged complete scalar scan. In particular, the scalar center guard precedes the neighbor-zero branch. A failed global proof alone is neither a scene rejection nor permission to classify a pair zero. For every candidate group-zero terminal, require a genuine guard pass, a valid rule on the independently reconstructed box, and full-oracle zero status for every expanded nonself member.
5. Preserve the five rule boundaries: neighbor squared-distance lower bound `>= neighbor^2`; height upper `<= 0`; height lower `>= downCut`; height upper `< minDown*D` with residual squared lower `>= nearRad^2`; or height lower `>= minDown*D`, width lower `> 0`, and residual squared lower `>= radCut^2 * width.upper^2`. Use the actual rounded receiver rotor point and residual `displacement - height*sourceAxis`. Do not substitute exact-unit-axis geometry. The group `proofRule` need not equal each member's first scalar zero branch; actually evaluated scalar status and branch must match exactly.
6. Require the exact same positive support by receiver/rotor/source identity and identical rational coefficient endpoints at the unchanged outward 192-bit recipe. A subset, containment-only check, approximate tolerance or aggregate count is insufficient. Require exact equality of all root endpoints and every signed rotor, collective, world-force and world-moment endpoint. Keep source boxes at 192 bits and each root endpoint at 128 bisections. Root/load comparison cannot replace pair coverage: exchanging two zero sources changes neither.
7. Require the same descending exact center-height/stable-ID solve order and canonical scene result: first raw/preparation refusal in input order; otherwise first rejected pair in `(ii,r,jj)` order before any uncertainty; then first uncertainty; then first positive backward edge; then positive-term cap; otherwise admission. Tree traversal order must not choose the witness. Exact status, branch, witness and reference class must match even when no load boxes exist.
8. Reconcile the observed scalar/zero memberships with work counters and declared completion. Every residual member has an explicit scalar record, including zeros and refusals. Absence is never an implicit zero. Only after these checks can `coverage.complete` be accepted. Preserve both fresh records' saved strict `1e-8` native-load checker verdicts, without new native or browser calls.

The unchanged full helper may be shared for arithmetic/geometry reconstruction; the validator must not import the new dispatcher, ask it to validate itself, or build its expected membership from mutated candidate data.

## Six controls, bound before execution

Each control mutates a separate copy of the same accepted baseline candidate. Assert the listed scene, query, node/member, status and ID preconditions at the literal fixed keys. A missing precondition fails the planned control and the validation; it must not trigger a scan for another witness, a new seed, a substitute corruption or a skipped test. Preserve ordinary schema/type validity and reconcile bookkeeping where necessary so the intended scientific check is reached. Record whether the mutation changed the intended object, its pinned witness, the observed failure code and whether that code belongs to the required family. An exception, timeout or unrelated schema/counter failure does not qualify.

## Dispatcher and checker source observations

At reviewed dispatcher snapshot `d08efc5e80910066d061a664aa7902c7ae7bab27dc710f5c00c9b2bf1671df65`, no orchestration or canonical-precedence defect was found by inspection. `add_terminal` requires contiguous full permutation ranges and subtracts the unique self position; `scan` translates permutation IDs through an explicit input-index map; all residual pair rows are finally sorted by `(ii,r,jj)`; the unchanged scalar oracle, coefficient quantization and root/load helper remain in use. The dispatcher deletes the tree builder's membership tuples and emits no per-member records for proved-zero groups. The tree builder itself still constructs those tuples during tree construction, and residual scalar calls still redo preparation; this review makes no performance claim.

The initial `validate.py` read checked canonical terminal kind before evaluating a candidate zero proof. The author moved candidate zero legality/member checks before that comparison; the updated source now routes C1 to `node-proof-rule`. This resolves the source-review finding. No failing or passing scientific run was executed during this review.

`source/corruptions.py` implements exactly these controls through `run_bound(case_id, full, tree, validator, semantic, constants)`. The driver must validate the clean baseline first. Four controls bind to `dense-cube-27`, one to `permuted-cube-27` and one to `center-guard-fallback`; all other fixed cases return no control. Missing fixed-key preconditions and repeat invocation fail. Each result records exact changed fields, before/after values, witness, observed exception and one specific required failure: C1 `node-proof-rule`; C2 `scalar-pair-canonical-membership`; C3 `scalar-member-list`; C4 `tree-identity`; C5 `scalar-oracle`; C6 `scalar-j`. Only the validator's designated validation exception is caught. Unexpected exceptions propagate and cannot count as successful rejection.

The bounded proposal remains one full-oracle and one tree-first evaluation of each of the fixed 24 scenes, at most 160,000 scalar calls combined, with no browser, simulations, repeats, added scenes or 5,000-state run. Exact pair/root/load equality on this small corpus would qualify this orchestration change only; it would not establish large-state feasibility, physical validity or model novelty.
