## Allocation and independence

One audit allocation has a 1,800-second successful wall limit, a 1,820-second external termination boundary and a 128 MiB output cap. The supervisor's measured success wall includes cleanup. An exclusive `audit-supervisor-launch.lock` and newly created `audit/` directory prevent another attempt. Unexpected failure, timeout, malformed evidence or persistence failure closes the allocation. There is no numerical retry, tolerance change, repaired rerun or new storage qualification within this contract.

The auditor uses only Python's standard library. It does not import or execute the producer, JavaScript scientific modules, initializer, controller, contact geometry, native airflow code, browser or an earlier audit. Binary64, rotation, projection, native-evidence, derivative and RK helpers are copied or adapted from the independently written continuation Python auditor. This preserves independence from the JavaScript producer; it does not make those helpers a third independent Python implementation. The segmented reader, publication gates and baseline join are adapted from the independent nominal auditor. The new memory recurrence is independently implemented here. The journal reader does not import the producer's Journal.

The baseline coupled trajectory is reused evidence. Its published audit and export are trusted after exact provenance and closure checks. The auditor does not rescan or recompute that trajectory or extract new baseline tracking errors. The sole baseline journal-prefix exception reads the two corresponding original initial records to establish exact shared starting states. The already exposed nominal result is pinned as motivation, not a new arm or held-out evidence.

## Byte handling and record order

The unchanged continuation Journal uses 16 MiB raw blocks and compressed parts at most 32 MiB. Descriptors have canonical contiguous part names/offsets, bounded lengths, aggregate compressed/raw hashes and exact record counts. Nonfinal parts are exactly 32 MiB. The audit exposes no part bytes to gzip or JSON parsing until the entire part's length/hash matches. It streams concatenated gzip members forward and checks complete compressed and raw JSONL totals.

Every JSONL record is at most 4 MiB and ends in a newline. Duplicate keys, nonfinite/overflowing numeric literals, missing records, unexpected order, extra records and noncontiguous sequences fail. New completed frames retain endpoint- and safety-record sequence/offset/length/SHA-256 provenance. Controller observations and a refused-stage frame retain their corresponding source-line provenance. Hashes include the newline.

Each verified-read operation permits at most three byte-read attempts after an OS error or identity mismatch, before bytes from that operation are consumed. Anomalies record the path, operation number, attempt and error or observed identity. Gate-before, evidence consumption and gate-after are separate verified-read operations. Parsing, arithmetic and whole phases are never retried. A newly captured small result without an established expected hash has one initial read; its captured identity is rechecked before success.

Each segment follows exactly: initial; controller when due; k1, k2, k3, k4; completed step; safety; next step or case-end. A structured refusal truncates the stage sequence as described below. Adapter stage IDs remain local to their journal. All controller, stage and endpoint arms are `coupled`. Controllers are due at local step zero of each segment, then every two or four integration steps. Commands remain held across all four stages and until the next due controller.

## Independent controller memory

Physical state remains 17 words. Separate memory records have exactly `id`, `integralWord`, `previousErrorWord` and integer `updates`, in ID order. Every path starts with positive-zero integral/error words and zero updates. Integral values are finite and within [-5,+5]; previous errors are finite; counts range from 0 to 500.

Controller records use schema `m31-vertical-memory-controller-v1`. Each row binds its physical state to the current endpoint and includes `verticalMemory.before`, `incrementWord`, `unclampedWord` and `after`. Before/after objects contain integral/error words and update count. The independent recurrence, preserving operation order, is:

```text
increment = updates == 0 ? +0 : (2.5 * .01) * previousError
unclamped = integral + increment
integral = max(-5, min(5, unclamped))
currentError = desiredVz - currentVz
previousError = currentError
updates = updates + 1
targetZ = z + ((2.5 * desiredVz + 1.5 * currentVz) + integral) / 6
```

Each computed intermediate is finite and each saved recurrence/target word must match. No algebraic simplification is accepted. Global controller index is `timeOrigin/.01 + stepIndex/stepsPerControl`, an integer on this fixed schedule. Before each controller, every memory update count equals that global index; afterward it equals global index plus one. Local controller index resets at the second segment, while global index continues at 100. Thus the error sampled at t=.99 is integrated exactly once at t=1. No memory update is invented at a terminal endpoint without a due controller record.

The ±5 bound applies only to memory. The inherited F.control net-acceleration clamp remains [-4,+5], and the actuator law/mixer/saturation decisions are not recomputed by this auditor. This is bounded integral memory, not conditional or back-calculation anti-windup. Controller checks also cover finite saved desired velocity, target, quaternion and commands, canonical sorted neighbor-ID shape, x/y target bindings, step/control indices and segmented clocks. Neighbor membership, Boids steering, yaw trigonometry and actuator decisions remain omitted computations.

Every reached controller exports mean absolute vertical error across all 64 saved rows and the minimum/maximum integral, with its actual time, local/global indices and line provenance. These are descriptive candidate own-reference measurements: changing the trajectory changes its neighbors and desired Boids velocities. They do not establish improvement over an unmeasured baseline fleet tracking error.

If both paths finish, the conditional totals are 500 controller records per path, 1,000 overall; 64,000 memory rows; 499 prior-error integrations per vehicle/path, 63,872 overall; and 128 first-update rows with zero increment. Actual counts follow reached records, including a due controller before a refused step. These full-horizon counts are not assumed outcomes.

## Coupled arithmetic and structured refusals

State and scalar words use 16 lowercase hexadecimal digits. Required numerical quantities are finite IEEE binary64, with signed zero retained. Basic operations follow the frozen JavaScript grouping and compare exact words. This establishes consistency on the audit runtime, not an exact-rational or cross-runtime accuracy proof.

A saved positive square root must be within one ULP of Python `math.sqrt` of its independently recomputed operand. The saved value is used downstream. Root comparisons and one-ULP differences are counted. A refused stage lacks per-row norm evidence in the unchanged adapter: for each quaternion the auditor tries Python's root and its immediate lower/upper neighbors, requiring an exact projected-word match from a finite positive candidate. This reconstruction is explicitly counted; it is not a recovered saved norm. Native root-two constants use the same three-candidate policy.

Checks cover all 64 vehicles at each reached stage and every completed endpoint:

- Raw k1 is the current base; k2 and k3 use base+h/2 times their preceding checked derivative; k4 uses base+h times k3. Relative/original clocks, dt, projected inputs, per-row raw/projected words and held commands bind exactly. Quaternion norm-square/projection and preservation of non-quaternion words are checked.
- Native method F, model/schema, stage identity and canonical input hashes bind to the current projected input. Saved constants, prepared centers, axes, rotor offsets/points, projected motor forces and totals are checked. Saved induced, beta and rotor-nu roots follow the declared root policy.
- Saved coefficient dimensions, offsets, ordered source IDs and success ranges are checked. The scaling `a = K * sourceBeta / receiverNu` must match exactly. Geometry-derived K values are not regenerated.
- Successful native records require admitted diagnostics, empty admission reasons, descending eligibility, recorded schedule order and finite residual diagnostics within the inherited limits. The native root algorithm and residual model are not rerun. Saved alpha sums over saved coefficients/solutions, rotor force products, collective force, world force/moment and the exact consumption checksum are checked. The saved solution y is checked against its saved collective-load ratio under the root policy.
- Each derivative consumes the same-ID native loads. Body-frame arm moment, unchanged nominal reaction yaw from projected motor states, total body moment and gyroscopic term are checked. All 17 derivative components are checked: position, coupled acceleration/gravity, quaternion rate, angular acceleration and motor lag. This verifies the implemented convention, without physical-validity attribution.
- RK accumulation is exactly `base + h * (((k1 + 2*k2) + 2*k3) + k4) / 6`, followed by endpoint projection. The complete resulting state becomes the next controller/step input or terminal state. No new aerodynamic force is assigned to an unqueried final endpoint.

Exactly one native call is recorded per attempted stage. A saved `domain-refused`, `input-refused` or `numerical-failure` native status is an allowed scientific stop when its reason/stage are structured and its adapter record is failed with `native-non-success`. It has no consumable solution/load/checksum or derivative rows; available native preparation/coefficient evidence is still checked under the refusal branch. Thrown/malformed native output, unexpected status and any unexpected producer failure fail the allocation.

At refusal, the attempted step has no endpoint or safety record. Physical state remains the last completed endpoint, including the original initial state if zero steps completed. Controller memory remains the most recently emitted memory, including a due update immediately before that refused stage; it is not rolled back. A separate `refusedFrame` contains the projected trial positions, actual original time, local step/stage, attempted global step, status/reason and line provenance. It never enters the contiguous completed-frame list or matched endpoint comparisons. The path stops, with no later segment. For each path, attempted stages equal four times completed steps plus the refused stage index when present. Successful plus refused stages equal all attempted stages.

After each completed endpoint exactly one safety record is required. The auditor checks issue kinds, ID shape/order, finite saved distance/clearance fields and equivalence of `pass` with an empty issues list. It does not regenerate obstacle/swept-contact geometry, vehicle-limit decisions or a safety certificate. The first nonempty issues list stops the segment and path, retaining that completed endpoint. Segment and whole-case termination issues reproduce the saved list exactly. Status/reason, refusal, counts, full final physical state, latest memory and nominal last time bind to case-end and index. Horizon completion requires every prescribed step and empty termination issues. The remaining prescribed resolution path may still proceed after a structured path stop; unexpected/resource/persistence failure fails the whole allocation.
