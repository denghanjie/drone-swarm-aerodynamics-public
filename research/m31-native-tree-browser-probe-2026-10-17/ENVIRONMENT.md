# Measurement environment

Read-only host queries during source preparation reported **Apple M4**, **25,769,803,776 bytes RAM (24 GiB)** and **macOS 26.5.2**. Only CPU model, total memory and OS version were requested; no serial number, hostname, user account or network identifiers are recorded here. The initial sandboxed CPU/RAM query was denied; the same narrow read succeeded through the authorized tool escalation. No benchmark or initializer was invoked by these queries.

Selected Chrome, Node, Python and automation runtime bytes will be pinned in `runtime.json` and checked before execution. This is one available development machine, not evidence for a low-end-device claim. The browser uses CPU JavaScript for this native comparison; Three.js rendering is outside the scientific query timing.

The study does not reserve cores, control ambient thermal state or eliminate background OS activity. No concurrent heavy benchmark is deliberately scheduled. Method-order balancing and reporting every stage help expose order effects but cannot establish timing uncertainty from two fixed seeds and four dependent stages each. The 20% gate is an engineering decision threshold for a subsequent experiment, not a confidence bound.

RAM capacity is not a process limit or a memory-use measurement. The inherited supervisor reports its named process readings and owned-root exit observations with their limited scopes. It does not enforce an OS memory ceiling or certify every browser helper under arbitrary OS failure.
