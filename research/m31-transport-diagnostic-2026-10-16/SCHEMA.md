# New transport record contract, version 1

Source preparation only. No diagnostic, supervisor, browser, network probe, sealer or saved checker has been invoked. Files are held in an isolated implementation staging area for independent review. Copy the seven executable/fixture source files into the new campaign's `source/`; place `config.json` at its campaign root. No file from a previous result is read by the new implementation.

## Producer records

`results/result.json` is produced once by `diagnostic.cjs`, after browser.close and sink.close attempts, optional payload reread, removal of all tracked listeners, and trace file closure. It has `version:1`, `kind:"synthetic-transport-diagnostic"`, the supplied 40-hex `sourceCommit`, verified `sourceFreezeSHA256`, and `terminal:true`. `qualified`, `scientificSuccess`, `explainsHistoricalFailure`, and `retryPermitted` are always false. A missing result means incomplete evidence, never a negative transport observation.

|Field|Meaning and producer|
|---|---|
|`browserLaunches`|0 or 1; increments immediately before the sole Playwright launch call. A failed launch still consumes it.|
|`fetchCalls`|0 or 1; host count of the browser's awaited `fetch-start` binding immediately before its sole fetch call. This is a reserved attempt boundary; interruption between binding and fetch can leave the actual network call unknown. `browserResult.attempted` is set synchronously just before fetch in the browser and survives only if the browser returns its result.|
|`observerReadyEvent`|Event ID of `observers-ready`, emitted before page navigation after all recorder enabling succeeds. Null on earlier failure.|
|`browserContext`|Actual pre-fetch `location.origin`, reduced to `page-origin`, `opaque-null`, or `other-origin`, plus actual `isSecureContext`. Exact origin is private. Unexpected effective origin stops the attempt and marks protocol deviation.|
|`origins`|Prospective structural scheme/loopback/port-role metadata. `actualOriginsEqual` begins null and becomes the measured location.origin comparison with the actual constructed sink URL.origin only when the browser-context binding arrives. It does not substitute for observed effective page origin. Actual ephemeral sink port never appears publicly.|
|`browserResult`|Null before a return. Otherwise `attempted`, `fetchCompleted`, `acknowledged` booleans; nullable `httpStatus`, `receipt`, `errorName`, `redirected`; `lastPhase`. `fetchCompleted` means fetch resolved on response headers, before JSON read/validation. `receipt` may exist after validation fails. `acknowledged` means HTTP success and parsed `complete:true`, bytes3840 and exact predetermined SHA.|
|`sink`|`requestCount`, `postCount`, `optionsCount` count actual Node request-entry callbacks, independent of duplicate PW/CDP observations. `started` changes before Content-Length/open checks exactly as in the preserved transport. `receivedBytes` counts emitted data chunks, `writtenBytes` counts successful writes, `writeCalls` counts successful calls. `complete` requires exact3840 bytes and successful close. Nullable `status`, `receipt`; `closed` and `activeWrites` describe local cleanup.|
|`persistence`|`exists`, nullable `bytes` and `sha256`, `exact`. Worker rereads the retained file after local cleanup; the saved reviewer must independently reread after external closure. Partial bytes are preserved. No file is normal when acceptance/open never occurred.|
|`instrumentation`|Readiness flags `server/playwright/cdpNetwork/cdpAudits/browserBinding/routes`; event counts/caps; `droppedEvents`, `truncatedEvents`, `observerExceptions`, `callbackErrors`; `unexpectedRedirectObservations`; `collectionBeforeFetch`, `captureClosedAfterCleanup`, clock declarations. `complete` means local recorder health and no detected redirect, not a guarantee every browser event/field exists.|
|`trace`|Separate `public` and `private` byte-length/SHA256 receipts, after both trace files are closed. Private path is intentionally absent.|
|`errors`, `cleanupErrors`, `protocolDeviations`|Bounded stage/type or fixed-code diagnostics. Complete operationally observed fetch failure need not be a worker error. Any nonempty operational/cleanup/deviation list makes the overall local record incomplete.|
|`status`|`incomplete` takes precedence; otherwise `synthetic-transfer-complete`, `exact-persistence-acknowledgement-failed`, `sink-accepted-incomplete`, or `transfer-failed-before-sink-acceptance`. None alone is a policy-cause claim.|

`raw/received.bin` is optional and contains only bytes actually successfully written (maximum3840). `raw/trace.public.ndjson` is the sanitized derivative. `trace.private.ndjson` is beside the private process registry, outside the public campaign; retain privately and never publish. `results/diagnostic-stdout.txt` contains one bounded worker summary binding `result.json`; stderr contains only fixed-shape finalization errors. `results/wrapper.json` is the relay record.

## Event schema and public transformation

Each line has `{version:1,id:"eN",sequence:N,clock:"worker-monotonic-receipt",milliseconds,kind,data}`. Sequence numbers are contiguous for successfully retained complete pairs of private/public records. At most2048 write-attempt events (`attemptedEvents`); `eventCount` counts successfully retained private/public pairs. Capping attempts prevents failed writes from bypassing the event ceiling. Private record maximum8192 bytes, private trace maximum3MiB, public trace maximum2MiB. Oversized field/record, partial write, full trace or callback error increments an explicit unhealthy counter; incomplete instrumentation dominates classification. Partial write may break NDJSON or IDs and must fail saved review. There is no log eviction.

Both traces preserve the same envelope and event identity. Public data is an explicit projection. Arbitrary console/error text, exact URL, nonce, ports, process/profile/path identities, remote addresses and unknown detail objects are excluded. Only selected header names are retained. Public header values are known protocol values, integer Content-Length, semantic origin labels (including opaque-null), or `other-header-value`. Raw selected headers also exclude cookies and authorization. Public `errorText` is only a `net::ERR_*` category or `other-error-text`; `failedParameterObserved` records presence while its value stays private. Optional CDP fields absent from an event remain absent, not false. Enum-like fields are lexical-filtered; unavailable/rejected values are null. Full private raw means all selected values before the public projection, not an exhaustive browser log.

PW request IDs (`pw-N`), CDP IDs (`cdp-N`) and sink request IDs (`sink-N`) are deliberately distinct namespaces. IDs correlate events within the corresponding API. Sink `connectionID:conn-N` links requests and socket events. A normalized `transferID:"transfer-1"` tags the sole exact reserved sink URL and browser phases. The same public URL label and method link APIs without exposing authority. ExtraInfo events can arrive before ordinary CDP request events; their CDP ID provides correlation later. `relatedCDPID` retains emitted initiator request linkage, including preflight relationships. Never count the duplicate API events as extra POSTs.

Kinds are: `sink-listening`, `sink-connection`, `sink-socket-error`, `sink-socket-close`, `sink-client-error`, `sink-server-error`, `sink-request`, `sink-post-started`, `sink-file-open`, `sink-data`, `sink-write-error`, `sink-persisted`, `sink-request-close`, `sink-response-finish`, `sink-response-close`; `pw-request`, `pw-response`, `pw-request-failed`, `page-console`, `page-error`, `page-crash`, `page-close`; `cdp-request`, `cdp-request-extra`, `cdp-response`, `cdp-response-extra`, `cdp-loading-finished`, `cdp-loading-failed`, `cdp-audit-issue`; `observers-ready`; `browser-browser-context`, `browser-payload-ready`, `browser-fetch-start`, `browser-fetch-response`, `browser-receipt-matched`, `browser-fetch-error`; `worker-error`, `observer-callback-error`, `cleanup-finished`.

Node receipt time defines the sole stream order. Browser `browserMilliseconds` is its independent performance clock; raw CDP timestamps are another independent clock. Neither is silently ordered against host timestamps. Audits.enable can replay issues; every audit record declares replay possible. An issue needs correlated request data to attribute to this fetch. Network absence or absent private/local-network fields proves no causal negative. Public origin metadata is not a browser-reported IP address-space classification; those are separately preserved when emitted. Unexpected redirects observed through PW, CDP or fetch response mark incomplete; the count is observations, not unique redirects.

## External lifecycle and bytes

The sole entry is `capture-transport.py <absolute pinned Node>`. It owns the permanent root `capture-launch.lock` and launches the fixed observer once. Observer creates `results/sole-launch.lock`, one fresh private directory/registry, and one relay group. Relay creates one Node invocation in its group. Registry records exact Chrome executable plus fresh Playwright profile before detached spawn and PID afterward. At most one detached Chrome intent is admitted. No registry/reap identity is published.

`results/budget.json` has `kind:"whole-transport-lifecycle-observation"`. Shared lifecycle fields are `sourceCommit/sourceFreezeSHA256`, `wrapperInvocations/wrapperExitCode/wrapperReaped/wrapperGroupAbsent`, pipe observed/retained counters, `registryComplete`, registered/absent detached groups, sampled RSS count/peak/errors, `processClosureComplete`, `outputAccountingComplete`, and `candidateLifecycleVerified`. `rawBytes`, `resultDirectoryBytes`, `privateDiagnosticBytes` are final only when accounting complete; otherwise final fields stay null and last-observed fields are explicitly samples. `accountedTotalResultBytes` includes **raw + result directory + private diagnostics + exact final budget + observer stdout summary**, once each. Although the historical field contains “Result”, it is the combined diagnostic total. The summary is persisted by the outer capture, so it is counted once.

`results/capture.json` has `kind:"external-transport-lifecycle-observation"`; it binds the observer budget and summary hashes/lengths, actual observer reap and exit, full before-Popen-through-reap elapsed, captured stdout/stderr observed/retained bytes, and `accountedCombinedResultBytes`. It adds outer stderr, permanent root capture lock, capture receipt and final capture stdout summary to the inner total; inner stdout is already counted. It exposes `candidateWholeLifecycleVerified`, never final authority. The final caller stdout is one `external-transport-capture-summary` binding capture.json. The saved checker requires that complete hash/length-matching summary, actual completed capture exit0 from external tool receipt, full external elapsed below60, and the candidate conjunction. No yield/session identifier proves completion.

Worker substantial operations stop locally at34s to reserve its inclusive40s deadline. Observer work ends40s, owned cleanup/final accounting ends58s, hard timer60s. Capture conservatively stops59.5s, reaps through59.75s, hard timer60s; failure to finish in that reserve cannot pass. Timers are independent with capture as outer authority; actual caller completion must meet the original60s allowance. External group signal never certifies detached-browser closure. Current full executable/profile/group proof is required for each browser group signal. Identities observed absent are never signaled again; group leader must remain unreaped until relay group signaling is disabled.

Combined retained cap8MiB includes raw/private payload/traces, all pipe persistence, registry/cleanup metadata, locks, results, receipts and summaries. RSS cap2GiB is sampled across capture/observer/probes and owned relay/Node/browser groups and descendants. Neither sampled RSS nor polling proves absence of every transient peak. Worker hard caps constrain retained writes; output overflow/truncation is incomplete. Source inputs, frozen payload fixture and source freeze are immutable inputs, not generated output. External tool receipt is a later publication artifact whose exact bytes the coordinator/saved checker must account separately if retained as diagnostic evidence.

## Intentional differences and static corrections

Heap bytes replace GPU-mapped bytes; no preceding GPU work or scientific imports. HTML/JS pathname is new; only its two exact frozen resources are fulfilled. As before, no real port8876 server is started. Payload is3840 bytes and request defaults, MIME, ordinary AbortSignal, page origin, sink CORS headers, ephemeral binding, nonce/reservation acceptance and original receipt shape are retained. Awaited trace bindings introduce observation scheduling points. Browser additionally validates known synthetic receipt SHA, beyond the old complete/bytes assertion. Fetch deadline is10s; the new diagnostic has its own one-shot40/58/60 lifecycle. `clientError` is explicitly observed and its malformed socket is destroyed; this is an instrumentation handling difference for malformed HTTP, not the expected valid POST path.

The initial mechanical lifecycle draft had an RSS literal corrupted by replacement, stale config keys, and raw bytes omitted from combined accounting. Independent static review caught these before any execution; all are corrected. CDP field extraction was corrected to `localNetworkAccessRequestPolicy`, explicit secure-context/address-space fields, response ExtraInfo address space, related preflight ID, and explicit selected Audits fields. No old failure or failed reviewer is modified or retried.

Adoption freeze must include all seven source files, config, PROTOCOL.md, payload.bin/json, runtime-provenance.json and this contract. Only Python AST, Node --check and inert source/JSON assertions have run. No operational source has been executed.
