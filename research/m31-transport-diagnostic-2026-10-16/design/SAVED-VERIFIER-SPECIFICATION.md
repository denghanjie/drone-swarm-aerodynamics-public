# Static specification: saved evidence for the new transport diagnostic

Status: **specification only**. Preparation currently proposes one 3,840-byte synthetic `Uint8Array` POST, one 60-second diagnostic lifecycle, fixed transport semantics, no GPU/scientific imports, and no retry or automatic scientific successor. This document allocates no invocation and supplies no executable checker. Implementation waits for the draft producer source, final record schema, and coordinator approval.

The verifier should be a small standard-library reader of **new diagnostic records only**. It must not import a producer, run a browser/subprocess, invoke any old checker, read old numerical buffers, or evaluate numerical model code. Prefer an independently readable frozen payload fixture so checking exact byte identity requires no input generation.

## Required evidence checks

1. **Identity and containment:** validate the new schema version, source commit/freeze identity, expected artifact list, exact byte lengths and hashes, and the frozen 3,840-byte synthetic fixture. Reject duplicate artifact entries, escaping paths, symlink redirection, missing required records, and inconsistent identities. Select shared fields explicitly when comparing differently wrapped records; never equate whole objects merely because they describe the same event.

2. **Attempt cardinality:** confirm one reserved diagnostic invocation, at most one browser/worker lifecycle, and at most one application POST. Treat any automatic preflight separately from the application request. Permit an accurately recorded failure before browser startup or fetch; a failed attempt must not be rejected merely because it never reached its planned POST. Record all extra attempted requests or relaunches as protocol deviations/failures.

3. **Trace coverage and correlation:** require listener-readiness evidence before fetch begins, unique sequential event identities, declared clock domains, one normalized request identity, and explicit dropped/truncated-event counts. Absence of a request cannot support a negative observation unless the relevant recorder was ready and its capture completed without loss. Compare event order within one defined stream/clock; do not silently compare unsynchronized browser and host timestamps.

4. **Byte and receipt consistency:** independently inspect any new persisted or partial file. A successful persistence claim requires exactly 3,840 bytes, the predetermined digest, and equality to the frozen payload fixture. Cross-check server received/written counts, reservation state, response status/receipt, browser acknowledgement, and final file identity using explicit field projections. Browser acknowledgement alone cannot establish persistence. Preserve partial bytes and hashes when a failed request writes less than the payload. Do not require a binary file when a valid pre-transfer failure record says none was created.

5. **Outcome-specific logic:** distinguish (a) exact persistence plus matching browser acknowledgement, (b) exact persistence with failed/missing acknowledgement, (c) observed request followed by rejection or incomplete persistence, (d) no observed application request with complete applicable traces, and (e) incomplete/inconclusive instrumentation or closure. A browser-reported reason remains an observation about this new diagnostic. None of these outcomes establishes the original GPU-upload cause.

6. **Lifecycle and budgets:** bind actual externally observed completion, exit codes, complete summaries, direct-child/owned-resource reaping, and the full before-spawn-through-reap interval to the exact saved files. Verify the adopted 60-second cap and prospective work/cleanup limits, plus output/trace/memory limits once specified. Account for raw/partial records, logs, locks, summaries, and observer/caller receipts in their actual phases without double-counting retained pipes. Incomplete accounting must remain incomplete; an internal flag cannot replace actual outer completion.

7. **Scope of the review result:** keep the observed transport outcome separate from whether the new saved records are internally consistent and complete. Complete evidence of a failed transfer is different from a successful transfer. Scientific qualification, explanation of the old failure, and permission for further science must remain false. Report the number of checks with an explicit definition that includes any rejected check. Preserve every review error; do not fabricate an aggregate pass after early failure.

8. **Privacy and publication binding:** validate the declared transformation manifest and hashes of actual public artifacts. Public event identifiers must retain useful correlation without exposing transport nonce/authority, browser profiles, process identities, private paths, credentials, or unrelated request data. Keep original private traces immutable. Redaction may not erase the distinction between missing evidence and an observed negative result.

## Static source challenge before implementation is accepted

- Trace the producer of every required reviewer field, its type, envelope, optionality, clock, and terminal-write ordering. Construct a producer-to-reviewer schema table before writing comparisons.
- Inspect success, early admission failure, browser failure before POST, persistence failure, exact persistence with acknowledgement failure, timeout, trace truncation, and incomplete cleanup branches. Missing optional output must be handled according to its recorded branch, rather than assumed to exist.
- Verify the allowlisted imports and all write targets; exclude old campaign data, scientific modules, GPU calls, dynamic scientific imports, retry loops, fallback transfers, and post-failure repair. Static source review supports these exclusions; zero self-reported counters alone do not prove them.
- Check that added listeners and logging do not change the frozen origin relationship, page-delivery mechanism, request method/MIME/mode, sink acceptance, or response semantics. Record intentional differences, especially the synthetic payload's non-GPU backing storage.
- Prepare inert schema examples for correct and mismatched envelopes, missing/truncated traces, extra POSTs, corrupted payload bytes, inconsistent receipt lengths, and outer nonzero exit. These are prospective contract cases, not authorization to execute a checker now.

The final schema must specify the verifier's own permitted output, wall/output allowance, terminal lock, exact invocation policy, and external completion binding before any review is run. No verifier allocation is inferred from the diagnostic's 60-second allowance. Keep this small: the purpose is transparent reconciliation of a finite new transfer record, not restoration of any unexecuted predicate in the failed scientific review.
