## Decision before execution

The reviewed candidate and measurement protocol are suitable for the stated single prospective computational screen after the complete source manifest is frozen, publicly pushed and independently verified. This is approval of the bounded experimental design, not a result or a speed claim. The run, saved-evidence audit and display still have to complete within their separately frozen allocations. Any failure closes its allocation; neither changing the source nor retrying is authorized by this review.

The proposal is ordinary conservative neighbor-list reuse. It cannot resolve the earlier physical-model mismatch, establish safe flight, demonstrate integrated flock trajectories, qualify 5,000 drones, or prove equivalence over all inputs. F remains the frozen reference and current baseline. A successful finite test would justify only considering this exact candidate for a separately designed broader computational test.

## Independent implementation assessment

Compared the complete candidate wrapper and kernel against the exact fresh-transfer baseline sources. The wrapper changes its kernel import, passes canonical IDs into the builder and exports cache inspection/reset APIs. The kernel changes dependency paths to the unchanged fresh-transfer files, routes the freshly computed global-screen failure through cache invalidation, obtains candidate rows and traverses their ascending indices. Its preparation, current component and norm screens, rotor classifier, coefficient assembly, admission, solve, residual, loads and consumption logic are otherwise unchanged. The final prefreeze representation uses canonical indices internally with the exact canonical ID vector retained; the public witness resolves them back to source IDs. This change introduces neither a second candidate nor a post-result selection.

For actual stored intervals, real subtraction is monotone in the source and antitone in the receiver. Binary64 rounded subtraction is monotone too. Therefore `RN(source.lo - receiver.hi) >= 4` or `RN(source.hi - receiver.lo) <= -4` implies that F's current rounded component difference meets its existing rejection threshold for every pair of contained current centers. The endpoint padding is outward and box containment is inclusive. This argument is about completeness relative to F's component screen; it is not a physical-model or cross-runtime library proof. The coordinate bound keeps endpoint arithmetic finite. Equality at the screen threshold is correctly rejected by F.

Every other nonself source is retained in canonical order. Count or canonical-ID changes rebuild before indices can be reused. Input-row permutation is normalized by the inherited wrapper. Each query recomputes the global eligibility predicate and all scientific values. Global ineligibility invalidates the cache and delegates the original lean fallback. Cache-coordinate/cap failure invalidates and returns to all-current-source F enumeration without truncation. A partially built cache is never published. The cache stores no attitude, force, coefficient, admission, root, solve or delivered load. Duplicate-ID refusal occurs before the cache is reached.

Static inspection finds no remaining source-completeness blocker for the supported synchronous experiment. Ordinal resource-guard call equivalence is expressly excluded: extra guard polling can change the point of an interruption. Entry-cap and interrupted-build behavior are statically assessed, not additional empirically qualified controls. The current workload is finite and does not test every cache invalidation or refusal path.

## Challenges resolved before freeze

1. The initial outer timer included word conversion and input-mutation comparison. The reviewed producer stops the timer immediately after the owned input copy and complete native query return. Preservation checks, semantic encoding, cache witnesses and persistence follow it. Reset duration is included in each stream's sequential timing sum. `encodePersistMs` excludes journal append; pair-comparison durations are saved separately. These totals are query/reset costs, not elapsed stream or end-to-end simulation times.
2. Cache events were initially observations only. The producer now requires the frozen control actions/reasons before any stream, checks no cache access on duplicate refusal, and requires build at stages 0 and 6 with reuse elsewhere in every stream. The controls contain a close source, a far source crossing the positive/negative component boundary, an inclusive outward box face and its next-word exit, force plus input permutation, attitude, ID/count changes, global fallback/recovery and coordinate fallback.
3. Raw-output changes alone would not establish refresh of delivered values. The force and attitude controls now require distinct derived-load digests as well as full F/C semantic equality. Input preservation has an explicit passed flag and matching before/after hashes per query.
4. Cache counters alone would not establish omission completeness. Owned full boxes and source-ID rows are saved for twelve controls and the first eight-stage measured candidate stream, outside query timing. The auditor independently reconstructs the expected boxes/rows and counters, requires exact preservation on reuse, and checks every omitted current ordered pair against both the interval-separation condition and current F component screen.
5. The original payload counter omitted journal appends. The reviewed producer accounts for launch, journal and all native result files, limits ordinary writes to 510 MiB, and reserves 2 MiB for failure/exit closure under the 512 MiB cap. The auditor checks the actual persisted inventory and the exact summary/exit byte counts. A final guard follows saved view data.
6. Audit work now has its own permanent locks, 120-second internal limit, 130-second external supervisor and combined 2 MiB output cap, separate from the 168 native queries. It imports no scientific module. Five negative checks alter saved small witnesses: missing candidate, duplicate, noncanonical order, stale ID and missed box-exit rebuild. Their rejections and mutation hashes must be preserved in the audit report.

## Evidence and decision requirements

The native allocation is exactly 24 control, 16 warmup and 128 measured calls if successful, comprising 84 F/C pairs. Warmup uses C then F; measured even batches use F then C and odd batches C then F. Cache resets occur once before controls and before every candidate stream. All eight measured paired batches are retained. Source-public verification must precede launch by less than 24 hours; the permanent exclusive result directory and supervisor lock prohibit restart.

The complete semantic record is compared as canonical binary64 words. The only exclusions are top-level method/timing and the four specified nested timing/enumeration paths in the protocol. Raw inputs, constants, prepared geometry, coefficients, ordered solve, residual, loads, consumption, refusal stage and remaining diagnostics are retained. The auditor checks content-addressed bytes, structural completeness, exact raw-input association, full pair identity, native timing nesting, sequential reset-inclusive totals, batch arithmetic and saved-view identity. Its snapshot construction independently repeats the specified binary64 additions/multiplications; the two control trig values are checked against the small prescribed tilt within 1e-15 to avoid assuming identical cross-runtime libm words. That recipe check does not relax any F/C equality: every compared semantic word remains exact.

Keeping the candidate for broader testing requires every correctness gate, median of the eight C/F ratios at most 0.90, and at least seven strict wins. This small, same-device sequence supports no population, significance or confidence claim. A cost-gate failure is a negative engineering result even if correctness passes. A correctness/audit failure prevents timing interpretation. Saved visualization is prescribed synthetic motion only; display QA and publication privacy checks remain the parent's separate responsibilities.
