Understand the controller comparison

What changes: the position controller asks for a horizontal velocity toward the original point. The previous controller only asks for zero horizontal velocity. Altitude control, attitude control, motor limits and both aerodynamic models remain the same.

Fixed settings: requested horizontal velocity = −1 s⁻¹ × horizontal position error, limited to 0.5 m/s in magnitude. These gains were chosen for this experiment, not fitted to measured flight or tuned to make one model look better. Position holding is a command objective, not a guarantee that the drone will stay still.

Read the overlays: solid = selected model/controller; purple = other aerodynamic model with that controller; orange = other controller with the selected aerodynamic model; pale = no interaction. All are alternative predictions for one receiver. The upper blue drone is fixed.

Fair comparison: all four model/controller combinations start identically. Playback, plots and differences use their shared time interval, ending at the first model limit or 16 seconds. Select Pitch or Horizontal X position to inspect differences. Changing settings restarts every run.

Still exploratory: this retains the unvalidated constant ideal-power rotor assumption, one-way hover wake and nominal 27 g geometry. The 20° cutoff is a software limit, not a physical safety boundary. The grid has no ground contact; bodies are drawn 2× larger. Rotor bars are diagnostic lift estimates; the force-only model discards their aerodynamic moment changes. Read the methods and results.
